# Task 7 Brief：补齐深链定位与原业务动作调度

## 目标

让“我的待办”每一条记录都能进入已有业务页面的正确上下文，并把可直接执行的动作委托给原业务 API；路由型动作只负责导航，不在待办模块复制业务校验。

## 范围

- 前端待办深链构造与动作调度。
- 检验、稳定性、留样页面读取对应 query 参数并定位记录。
- 留样观察复核使用已有 `observation_name` 接口参数。
- 不新增待办持久化模型，不改变原业务动作的权限与状态校验。

## 验收

- 六类深链均有契约测试：检验任务、稳定性取样、稳定性结果、留样观察、留样使用、留样处理。
- 目标记录不存在时页面保留上下文并给出来源编号提示，不出现空对象异常。
- 直接动作成功后刷新待办列表和摘要；失败后强制刷新且不乐观删除。
- `npm run test:unit`、`npm run build`、前端契约测试通过。

## 开始前检查

- 已确认原业务 API 映射及 `review_observation(observation_name=...)` 签名。
- 先写失败测试，再实现生产代码。
