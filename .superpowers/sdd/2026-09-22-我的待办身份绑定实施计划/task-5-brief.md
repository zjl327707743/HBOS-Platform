## Task 5：建立前端 API、模型与 Pinia store

### 范围

- 新增待办 API 类型与 Frappe 查询封装。
- 新增纯 TypeScript 模型工具：归一化展示字段、白名单查询参数、标量路由参数、逾期排序、失败保留旧摘要。
- 新增 Pinia store，管理摘要、列表、筛选、加载错误和注销清理。
- 不在本任务实现页面、侧栏和业务动作调度。

### 安全与状态边界

- API 查询不得发送 `user`、`roles` 或旧的 `overdue_only` 参数。
- 身份由后端会话决定，前端 auth 只用于展示。
- 列表/摘要刷新失败不得清空上一次成功数据。
- `removeResolved` 只提供给后续动作成功后的页面流程调用。
