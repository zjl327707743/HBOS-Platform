# 前端实施流程规范

本文件定义新乡海滨智能运营管理平台中独立前端的实施流程、分层边界、组件库选型和 Agent Skill 使用规则。

适用对象：Claude、Codex、Cursor、GPT 及所有参与本项目前端开发、设计和审查的 AI Agent。

## 1. 前端分层

HBOS 采用双层前端架构（参见 `docs/adr/0003-use-dual-layer-frontend.md`），两层职责严格区分：

### 1.1 Frappe Desk / Workspace / Report（后台层）

用于：
- 后台管理、表单、台账、流程、配置、权限
- 基础报表、数据导入导出
- 组织架构、角色管理、审批流

约束：
- 优先使用 Frappe 原生能力（DocType、Workspace、Report、Custom Page）
- 不得为了"好看"强行重做成独立前端
- 不得绕过 Frappe 权限、API 和数据边界

### 1.2 Vue / React 独立前端（展示与交互层）

用于：
- 平台门户、首页
- 领导驾驶舱、运营大屏
- AI 工作台、智能看板
- 视频审核中心
- 复杂排班日历
- 其他高视觉 / 高交互页面

约束：
- 不得自行维护用户体系
- 不得绕过 Frappe 权限
- 不得直接访问数据库
- 必须通过受控 API 获取数据
- 不得将 Frappe Desk 后台页面强行重做成独立前端，除非该页面明确属于高视觉 / 高交互场景

## 2. 独立前端启动 Gate（强制）

任何独立前端页面或模块在进入代码开发前，必须经过以下 Gate：

### 2.1 原型 / 视觉方案阶段

1. 必须先输出页面原型图、视觉方案和页面结构说明。
2. 原型应覆盖：布局结构、信息层级、组件选型、交互流程、响应式断点策略。
3. 视觉方案应覆盖：色彩体系、字体策略、间距系统、暗色/亮色模式（如适用）。
4. 原型产出工具：`frontend-design` skill 或其他前端设计 skill 产出的设计初稿。
5. 产出必须交 Owner 人工审查。

### 2.2 Owner 审查阶段

1. Owner 审查原型和视觉方案。
2. 审查要点：
   - 信息层级是否合理
   - 视觉风格是否符合业务定位
   - 组件选型是否与技术栈一致
   - 交互流程是否覆盖关键路径
3. **未经 Owner 审查通过，不得进入前端复刻阶段。**

### 2.3 前端复刻阶段

1. Owner 审查通过后，才能进入前端代码实现。
2. 复刻阶段关注：组件结构、响应式、可维护性、视觉一致性。
3. 复刻应严格遵循已审查通过的原型和视觉方案，不得擅自偏离。
4. 如复刻过程中发现原型有不可行或需调整之处，必须回退到原型阶段重新审查。

### 2.4 功能接入阶段

1. 前端复刻完成后，才能接入真实 API、权限、数据和业务操作。
2. 功能阶段关注：API 契约、权限校验、状态管理、错误处理、空状态和加载状态。
3. 禁止在原型未审查通过的情况下预埋 API 调用或业务逻辑。

### Gate 流程图

```
原型/视觉方案 → Owner 审查 →（通过）→ 前端复刻 →（完成）→ 功能接入
                    ↓（未通过）
              回到原型阶段修改
```

## 3. 组件库选择原则

组件库必须根据已确定的前端技术栈选择，不允许同时混用多套风格冲突的组件库。

### 3.1 React 技术栈

- **首选**：Ant Design（企业级后台与 SaaS 场景）
- **可选**：Tailwind CSS + shadcn/ui（现代 SaaS / AI 工作台）
- 如项目后续确定具体 React 组件库，以项目工程配置为准

### 3.2 Vue 3 技术栈

- **首选**：Element Plus / Naive UI / Ant Design Vue
- 如项目后续确定具体 Vue 组件库，以项目工程配置为准

### 3.3 图表

- ECharts（统一图表库）

### 3.4 约束

- 不得同时混用多套风格冲突的组件库
- 不得为了好看绕过 Frappe 权限、API 和数据边界
- Frappe Desk 页面不要强行重做成独立前端，除非明确属于高视觉 / 高交互页面
- 组件库选型应在原型阶段明确并记录，作为视觉方案的一部分提交审查

## 4. Agent Skill 使用要求

### 4.1 设计阶段

凡涉及独立前端、漂亮页面、驾驶舱、AI 工作台、复杂交互页面：
- 必须优先调用 `frontend-design` 或相关前端编程 skill 辅助产出原型和视觉方案。
- Claude 在未使用 `frontend-design` skill 的情况下，不得直接开始漂亮前端代码开发。
- Codex 负责独立审查时，必须检查是否使用了前端设计 skill 产出或审查页面方案。
- Agent Skill 产物只能作为设计和代码初稿，必须经过 Owner 审查和 Codex 审查。

### 4.2 审查聚焦

| 阶段 | 审查聚焦 |
|------|---------|
| 原型阶段 | 布局、信息层级、视觉风格、组件选型、交互流程 |
| 复刻阶段 | 组件结构、响应式、可维护性、视觉一致性 |
| 功能阶段 | API 契约、权限、状态管理、错误处理、空状态和加载状态 |

### 4.3 禁止

- 不得因 skill 输出扩大任务范围
- 不得未经审查直接采纳 skill 生成的代码或设计
- 不得自行编造未确认的 skill 名称
- 不得假装已安装候选 skill
