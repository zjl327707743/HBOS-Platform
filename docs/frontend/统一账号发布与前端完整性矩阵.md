# 统一账号发布与前端完整性矩阵

参考：EA-5.3 上传 HTML 的全局顶栏、Portal 导航、首页、应用中心、我的工作、业务脉搏、数字孪生区；已批准 R1 的知识/设备独立应用布局及证据交互。保留已批准样式和字体体系，不按原型示例卡片或数字补造业务数据。

当前代码对应真实五应用：考勤、仓储库存、LIMS、知识助理、设备与工艺。设备与数字孪生属于同一 `hb_twin_app`，不虚构成两个已实现业务应用。

| 区域 | 实现/Provider 与路由 | 真实数据/权限 | 本轮核对与缺项 |
| --- | --- | --- | --- |
| 顶栏与 Portal 导航 | GlobalHeader/PortalLayout，全局搜索、切换器、帮助、个人菜单 | 来自 bootstrap 与当前 Frappe Session；应用按 Provider 过滤 | 帮助按钮补功能；退出清本人会话；消息样例和未读红点移除，通知服务未接入 |
| 首页与应用中心 | `/hbos`、`/hbos/apps`，真实 registry | Administrator 授权范围可显示五应用；业务用户按原角色 | Hero 样例设计说明移除；应用数来自实际 registry；知识图标补齐；卡片会话失效时引导登录，失败可见提示 |
| 我的工作 | `/hbos/work`，当前 LIMS tasks | 本人待办与原业务权限；真实空状态 | 去掉固定“4 个应用”及错误“扫码入库”捷径；考勤/仓储未提供 tasks 时不假装有聚合待办 |
| 业务脉搏 | attendance.summary、inventory.summary、lims.summary | 汇总值由真实后台读取，0 不补样例 | 无业务数据/无权限/服务失败须区分；趋势图仅后台真实提供时显示，不填原型 12/12、7 或模拟折线 |
| 考勤 | `hb_attendance_app` Provider → `/hbos/attendance` → 原 Desk 页面 | HR 角色与 Employee/User Permissions 继续由原 App 约束 | 已实现入口/summary；完整独立前端重写、tasks/search 不在本轮实现 |
| 仓储库存 | `hb_inventory_app` Provider → `/hbos/inventory` → 原 Desk 页面 | 原库存角色与单据权限 | 已实现入口/summary；tasks/search 未接入，权限不能通过授予普通用户管理角色来绕过 |
| LIMS | `hb_lims_app` Provider → `/hbos/lims` → `/hbos-lims/dashboard` | 原角色、批次/样品/任务授权；entry/summary/tasks/search | 需同时部署既有 LIMS 编译制品与 assets；不能只部署 Portal JS 后宣布 LIMS 可用 |
| 知识助理（R1） | `hb_knowledge_app` → `/hbos/knowledge` | 服务端审批 scope → Gateway → 私有索引；证据短时并检查文档范围 | 检索/证据已实现；生成式回答、持久收藏/历史、直接个人助手/MCP 集成未实现 |

| 我的与账号安全 | `/hbos/profile`、`/hbos/account-connect`、`/hbos/reset-password` | 唯一 User、双方身份验证、原生密码/MFA与 Session | 绑定/设密/改密/解绑/冲突/恢复/停用有代码与受控实测；真实企业 OAuth 和原账号仍待现场 Gate |

## 验收记录规则

在正式目标逐行记录 source SHA、编译 build ID、Site apps、Provider/capability、原角色/User Permissions、真实数据结果、页面渲染及跳转。已有测试站的 registry/Administrator 会话展示只能证明该测试环境当前状态，不能证明原账号站点升级或 Owner 通过登录表单验收。

若数据库缺业务数据，显示真实空状态；若 App 未安装/Provider 失败/权限不够/制品没部署，准确标明对应原因。不能复制原型通知、扩大管理员权限或补测试数据来填充首页。源码版本、运行构建、Site app 和 Provider 任一不一致都不放行生产。
