## 1. 本页要解决的问题

现状：Inventory 在 Portal 里只有一张 4 指标的 summary 卡片，点「Inventory」会整页跳出 Portal SPA 落到 Frappe Desk 的 `/app/hbos-photo-intake`。用户从「应用中心」进来，没有任何中间层告诉他「这个应用现在是什么状况、要办的事在哪」。

本页是那一层。它**不承载业务事实**，只做三件事：

1. 把库存异常摆到最显眼处，让仓管一眼知道今天要不要处理什么；
2. 如实反映账面规模，但不伪造没有的能力；
3. 给出到各个办事入口的路径。

## 2. 边界与口径

**Owner 已明确口径（2026-09-25）**：

> 仓管的所有操作都是在前端页面完成的，不存在跳转到 Frappe 后台页面的情况。
> 仓管操作在前端，前端在后台连接仓库工作台。

这句话改变了本方案的定位。此前的理解是「Portal 是壳，业务操作回 Desk」，据此我一度在入口区给每项标注 `Desk` 来源。**那个做法是错的**，已在原型中移除（见 §4.4）。

修正后的分工：

| 层 | 角色 |
|---|---|
| 前端（Portal） | 仓管看到的**唯一**操作界面。所有业务操作都在这里发生 |
| Frappe / ERPNext 后台 | **被前端调用的引擎**。DocType、权限、校验、库存事实都在这层，但仓管不直接面对它 |

**后台能力依然完整保留，只是不再暴露给仓管**：

```text
Stock Entry            Purchase Receipt       Delivery Note
Warehouse              Batch                  Item
库存原生报表（Stock Ledger / Stock Balance / Stock Ageing /
Batch-Wise Balance History / Batch Item Expiry /
Warehouse Wise Stock Balance / Stock Projected Qty）
```

本页**不重建**这些能力，而是作为调用它们的**前端入口**。ERPNext 的校验、放行门禁、权限边界一律原样复用——前端只换皮，不动规则。

**Desk 侧的 `/app/hbos-photo-intake` 与「仓库工作台」保留可用**，作为管理员/技术排查的直连入口，但**不是仓管的主路径**。

| 销售出库 | ❌ 无 |
| 拣货单 | ❌ 无 |
| 库存对账 | ❌ 无 |

## 3. 视觉强度：V2

按 EA-4 §4 与 EA-5.4 §2.2，本页是 **V2 — Application Dashboard**：

| 允许 | 本页用法 |
|---|---|
| Medium Glass（G2，blur 18–22px） | 头部栏、异常面板、入口区，用 `--hbos-glass-g2-*` |
| 域色强调（Inventory = Amber/Orange） | 仅用于：异常面板左侧 3px 身份色条、侧边栏当前项 |
| KPI / 图表 | 4 个真实指标，无图表（无真实时序数据，不画假图） |
| 轻量动画 | 仅 hover 描边/背景过渡，260ms |
| 局部 Aurora | 画布两处固定光斑，透明度 .10–.13 |

**明确不做**（V3 专属，EA-5.4 §6）：鼠标跟随光场、粒子拖尾、强玻璃 G3、Hero 级排版、全页饱和渐变。

域色**不进入数字**——数值用状态语义色（warning/critical），否则会与 EA-5.4 §24 的状态语义打架。

**域色与品牌色不混用**：Global Header 左上角那个 40×40 是 **HBOS 品牌标记**（内容 `H`，走品牌渐变 `#6C63FF→#49A9FF→#4BD8BF`，圆角 14px），与 Portal `GlobalHeader.vue` 完全一致；域色只出现在「应用身份」处。此前的原型把品牌标记染成了 Inventory 琥珀色，属于概念混淆，已修正。

### 4.1 为什么异常在左、规模在右

左宽右窄（约 1.35 : 0.95）。**宽度即优先级**：要处理的东西占更宽、视觉更重（域色细边 + 面板底色）；纯参考数字占更窄、更安静（字重降为 medium，颜色走 secondary）。

### 4.2 为什么用「对账行」而不是 KPI 卡

这是本页的核心设计判断。EA-4 §39 把「每个指标都超大字号」列为反模式，EA-5.4 §12 也说 Metric 只是 Provider Summary 的投影、不是业务事实副本。

库存这张表天生是**对账关系**：左边写科目（负库存项 / 预计短缺项），右边写数字，中间由一条细线牵连——像账页，不像仪表盘。所以：

- 标签 + 一行解释在左，数字在右，**基线对齐**；
- 数字用 `font-variant-numeric: tabular-nums`，等宽对齐，扫读时竖列可对；
- 值为 0 时数字**降为常规字重 + muted 色**——「没有异常」在视觉上就该是安静的，不该和「有 3 项异常」一样响。

### 4.3 为什么「账面规模」要写一句说明

面板底部那行「不显示库存合计：不同物料的计量单位不同，相加没有意义」直接来自 `portal/summary.py` 里的既有约束（`Quantities are never added across items because their stock UOMs may differ`）。用户看不到合计会以为页面缺东西，与其让人猜，不如把原因写在页面上。

### 4.4 为什么入口区是行列表而不是图标宫格

EA-5.4 §13 明确禁止「手机桌面式铺满 20 个 Icon」。行列表也让每个入口能带一行说明（「拍标签 → 识别 → 人工校对 → 生成草稿」），宫格塞不下。

**这里删掉了早期设计中的来源标签。** 我最初给每个入口右侧标了 `Desk`，用来提示「点这个会离开 Portal」。按 Owner 口径这整个前提是错的：**仓管不跳后台**。继续标注只会把实现细节暴露给用户，并且暗示前端是不完整的。

现在每个入口右侧只留一个中性的进入指示符。等到这些页都做成前端页，界面不需要任何改动。

## 7. 状态设计

四种状态在原型里可切换（脚手架按钮），**全部反「整页 spinner」**（EA-5.4 §27）：

| 状态 | 呈现 |
|---|---|
| 正常 | 对账行 + 处置建议（critical / warning / success 三档语气） |
| 空态 | **不是错误，是好消息**：「没有需要核对的异常」，附「查看库存余额报表」 |
| 加载 | 骨架屏（`.hb-skel`），骨架与最终布局同尺寸，不跳变 |
| 错误 | 解释成因 + 重试 / 备用入口 |

### 7.1 空态文案的一处修正

初稿写的是「当前没有负库存项，也没有预计短缺项。**账面与实物应是一致的。**」——**最后一句是我编出来的**，已删。

数据只有 `negative_bins` 和 `projected_shortage_bins` 两个计数。两者同时为 0，只能说明**没有负数、没有预计短缺**，推不出账实一致。反例：某货位账面 100、实物 80，两个计数都不触发，却是一笔真实的账实差异。那句话会把这种情况说成「一致」，直接误导仓管跳过核对。

现文案：

```text
没有需要核对的异常

当前没有负库存项，也没有预计短缺项。这不代表账实已经核对一致——只是没有这两类异常。
```

这条与 Desk 拍照页「识别服务不可用绝不伪造结果」是同一条纪律：**没有依据的话不能说。**

### 7.2 错误态文案的一处修正

初稿写「这不影响你在『库存单据』里继续办业务」——**这是无条件的承诺，而事实是有条件的**：

| 成因 | 该承诺成立吗 |
|---|---|
| 只有概览这一个接口失败 | ✅ 成立 |
| Frappe 整体故障 / DB 不可用 | ❌ 不成立，那时业务接口也不可用 |
| 权限不足 | ⚠️ 不成立，该走 403 视图 |

现文案改为不加保证、只陈述事实与风险：

```text
暂时取不到概览数据

这一页的异常数字依赖库存数据服务，它暂时没有响应。请勿把这里当作「库存没有问题」——只是现在算不出来。
```

**「请勿把这里当作『库存没有问题』」是必要的一句**：异常面板取不到数据时，视觉上会呈现为「没有异常」。必须明确否定这个误读。

错误态一律不写「系统异常」（EA-5.4 §28/§29 禁止），也不暴露 traceback。

## 8. 响应式

按 EA-5.4 §33 与 EA-4 §34：

| 断点 | 行为 |
|---|---|
| ≥1600 | 内容居中，max-width 1600 |
| 1200–1599 | 标准桌面，全宽 |
| 768–1199 | 侧边栏折叠 76px；异常/规模改为上下堆叠；入口区单列 |
| <768 | 侧边栏隐藏（走 MobileAppNav）；头部 64px；数字降为 Section 级 20px；入口区单列 |

**已在 1440 / 1100 / 768 下实测**，无溢出、无竖排文字。

## 9. 可访问性

- 所有可点区域 ≥44px（头部图标 44、侧边项 42、入口项 56、按钮 40）；
- `:focus-visible` 2px 描边；
- 语义标签：`region` + `aria-labelledby`、`dl/dt/dd`、`aria-current="page"`、图标一律 `aria-hidden` + 文字标签；
- **色彩不作为唯一含义**：状态行有文字说明 + 处置建议文案；
- `@media (prefers-reduced-motion: reduce)` 全部动画降至 1ms。

## 11. 侧边栏导航来源

Owner 口径（2026-09-25）：**前端自己维护**。

既然仓管的入口就是前端页面，导航本来就是前端资产——不再是「Desk 仓库工作台侧边栏的副本」，也就不存在我此前担心的「两份清单漂移」问题。Desk 侧那份（由 `workspace_setup.py` 用代码同步）服务于管理员直连，与前端导航职责不同，允许分叉。

分五组：工作台 / 入库作业 / 出库作业 / 盘点与对账 / 主数据 / 报表。EA-4 §18 约束的是导航**深度**不超过两层，平行分组数不受此限。「工作台」单独一条，对应 EA-5.4 §10 要求的「← 返回 HBOS 工作台」不得比业务导航更显眼。
