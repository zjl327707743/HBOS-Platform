## 1. 为什么做这一块

侧边栏「报表」组下面挂着四项，四项都还是「尚未实现」提示页：

```text
货位明细表          库级盘点三对账        效期预警        按批号查货位
```

它们**全是只读查询** —— 没有写操作、没有提交、不碰业务数据。所以：

- 风险最低：做错了最坏就是查不出数据，不会动账；
- 收益成片：一次消掉四个「尚未实现」；
- 后端已经现成：四张报表的 `.py` + `.js` 早就在本 App 里，Desk 侧在用。

## 4. 架构：一个视图组件 + 四条路由

```text
/hbos/inventory/report/location-detail     货位明细表
/hbos/inventory/report/expiry-warning      效期预警
/hbos/inventory/report/batch-location      按批号查货位
/hbos/inventory/report/stocktake           库级盘点三对账
```

**为什么不是一个页面加个下拉切换**：EA-5.4 §37 要求「是否支持 Deep Link」。
四张报表是四件不同的事，各自需要可分享、可收藏、可回退的地址。侧边栏那四项也各自
需要一个真实落点。所以给四条路由，但**共用同一个视图组件**——筛选栏、表格、四种状态、
导出逻辑只写一遍。

上报路由到后端仍是 identity（留在 SPA），与既有四条路由一致。

### 5.1 列由**服务端返回的 `columns` 驱动**，不硬编码

`query_report.run` 的响应里带着每张报表自己的列定义（字段名、标签、类型、精度、宽度）。
前端按它渲染表头与单元格，**不写死任何一张报表的列清单**。

理由：报表的 `.py` 是 Authority。将来有人加一列（比如货位明细表加「库龄」），
前端不必改一行代码就跟着出现。反过来硬编码就会漂——而漂的时候没人会记得改前端。

只有**值→语义的映射**需要前端提供（因为 `urgency` 与 `release_status` 在报表里
都是 `fieldtype: Data`，颜色得前端决定）：

| 字段 | 值 | 渲染 |
|---|---|---|
| `release_status` | 待检 / 已放行 / 不放行 | 蓝 / 绿 / 红 状态标签（EA-5.4 §24，色 + 文字并存） |
| `urgency` | 已过期 / 紧急（≤30 天） / 关注（≤90 天） / 正常 | 红 / 红 / 橙 / 中性 标签 |
| 日期类 | — | 等宽字体，空值显示 `—` 而非空白 |
| 数值类 | — | **右对齐 + tabular-nums**，扫读时竖列能对 |

映射表是一份**小名单**（两个字段），不是整张列清单——这是区别所在。

### 5.2 筛选栏照 EA-5.4 §22 分两层

```text
高频 2–4 个直接铺开  →  其余进「更多筛选」气泡
```

每张报表的高频项就是它 `.js` 里靠前的两三个：效期预警是「预警天数 + 含已过期 + 货位」，
按批号查货位是「批号 + 货位」。低频的（物料、放行状态）进气泡。

**不把所有过滤器永久展开**是 §22 的明文要求。

### 5.3 筛选条件进 URL

改筛选并把 URL 同步进 `?warehouse=...&within_days=90`。这样：

- 刷新不丢条件；
- 能把「我查到的这批临期物料」直接把链接发给同事；
- 浏览器后退回到上一次筛选。

## 6. 四张报表各自的取舍

### 6.1 库级盘点三对账：**刻意只显示一列数量**

这是本轮最需要你确认的一处判断。

报表的 `_columns()` 声明了 11 列，其中三列由现场填写：

```python
"card_qty": None,            # 货位卡数量
"physical_qty": None,        # 实物数量
"variance_corrected": None,  # 差异（实物-ERP）
```

实测返回的正是 `null` —— **报表本身给不出这三列**，注释里也写明「由现场填写 / 在导出的
Excel 中计算」。

所以界面**不显示这三列**，只显示报表真正算得出的 `erp_qty`，并给一条说明：

> 本页只显示 **ERP 账面数量**。「货位卡数量」「实物数量」需要现场清点，报表给不出——
> **请导出后在 Excel 里填写，差异列随之算出**。因此这里不显示那三列，
> 免得空格被读成「数量为零」。

**为什么不是显示空列**：一列全空的数字列，仓管会读成「这里数量是 0」——
那正好和盘点的目的相反（盘点就是要去发现差异）。宁可少一列，并说清为什么。

**为什么不是做成可填的输入框**：那等于把「导出到 Excel 填」的既有作业方式
改成在线填报，会牵出保存、并发、审计一整套东西。**本轮不碰**，等你要的时候单独议。

### 6.2 效期预警：`urgency` 是报表算好的，前端不重算

「剩余天数」与「紧急度」都由报表的 `.py` 用 `date_diff` 算定（已过期 / ≤30 / ≤90 / 正常）。
前端**只做呈现**，不自己拿今天的日期再算一遍——否则两处口径会分叉
（比如报表算的是服务端日期、前端算的是客户端日期，跨时区或跨零点就会不一致）。

### 6.3 按批号查货位：模糊匹配要写在界面上

报表对 `batch_no` 用的是 `LIKE %值%`。界面上必须写清「支持模糊匹配」——
不写的话，用户输 `BMT` 只查到一部分，会以为数据不全。

### 6.4 货位明细表：`include_children` 是唯一「结构性」筛选

「含下级货位」勾上时，选一个库位会展开到它下面所有货位；不勾则只查那一个。
选项旁要带说明（照 `.js` 里的 `description`：**可填具体货位，也可填库位或层**），
否则用户不知道能填层级。

## 7. 状态设计

| 状态 | 呈现 |
|---|---|
| 查询中 | 表格骨架，与最终行高同尺寸 |
| 有数据 | 表格 + 右上角「N 行 · 查询于 时间」 |
| **无结果** | 「没有符合条件的记录」+ **清空筛选条件**按钮 |
| 出错 | 「报表没跑起来」+ **明确否定误读**：这不是「没有数据」 |
| 无权限 | 独立状态（复用 `ForbiddenView` 的语义），指向返回概览 |

**空态与错误态必须分开**——这是本页最容易被做错的地方。

「这个货位没有库存」和「报表服务挂了」在屏幕上都是一片空。若不区分，
仓管会把故障读成「没库存」，然后据此下结论。所以：

- 空态标题针对报表而不同（「这个货位下没有库存」/「近期没有临近效期的批次」/ …）；
- 错误态一律写明**「这不是『没有数据』」**。

### 10.1 复刻时发现并修掉的一个真缺陷

**货位明细表与库级盘点三对账在「货位名拼错」时会 500。**

两张报表共用同一套 `_warehouse_scope`；勾上 `include_children` 而货位名匹配不到任何节点时，
`scope` 是**空列表**，`", ".join(...)` 拼出来是空串，SQL 变成 `sbe.warehouse in ()` ——
MariaDB 语法错误。

**表现与影响**：用户看到的是「报表没跑起来」，而事实是「这个货位没有库存」。
**把空结果误报成故障，与把故障误报成空结果是同一类错误**——都让人做出错判断。

修法是在拼 SQL 之前早退：`if scope is not None and not scope: return _columns(), []`。
两处都已修，并加了 5 条回归测试钉住（含「早退必须在拼占位符之前」与
「空结果仍要给列定义，否则前端画不出空表」）。

**另两张报表不受影响**：效期预警与按批号查货位用的是单值相等
（`sbe.warehouse = %(warehouse)s`），不拼 `IN`，天然没有这个坑。测试里专门记了这一条，
免得后来者以为漏改了两张。

### 12.1 导出文件名乱码（已修）

**现象**：浏览器「另存为」对话框里文件名是 `ï¼y÷å` 这样的乱码。

**根因**：`link.download` 的值来自读 `Content-Disposition` 响应头。服务端下发的确实是对的
（curl 验证：`attachment; filename="货位明细表.xlsx"`），但 **`fetch` 暴露非 ASCII 响应头时
按 ISO-8859-1 解码**，JS 拿到手就已经是坏字节，再 `decodeURIComponent` 也回不来。

**我之前的判断是错的**：我曾把乱码归为「读端的问题，下载本身用的是正确文件名」——
那是基于 curl 的结果，而实际设置下载名的是**我自己这段读 header 的代码**。
curl 对不代表浏览器对。

**修法**：**不读 header，自己拼**。服务端固定用 `<报表名>.xlsx`
（`provide_binary_file` 里 `f"{_(filename)}.{extension}"`），而报表名就在我们手里。
拼出来比读回来可靠。`readFilename()` 一并删除。

**复测**：拦截 `HTMLAnchorElement.prototype.click` 读出实际 `download` 值 →
`效期预警.xlsx`，非乱码。
