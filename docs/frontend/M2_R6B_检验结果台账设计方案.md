# M2-R6B：检验结果台账双模式设计方案

项目名称：新乡海滨智能运营管理平台。

## 轮次状态

状态：REVIEWING（Owner 已确认原型与交互，待审查设计文档后进入 Vue 复刻与后端实现）。本方案为 M2-R6B 第 3 版，按 Owner 多轮反馈定稿：双模式「明细台账 + 样品表」，其中样品表为「每个样品种类一张表、一行一个批次」的数据表统计形态。

## 需求背景

现用飞书多维表格登记的检验结果台账，由于每种样品的登记信息类型不同、检验项目也不同，不适用于 HBOS LIMS 现状的"一张固定大宽表"。同时须契合 GMP 数据完整性要求：检验项目、限度、结果、判定均为受控记录，便于审计追踪。

## 方案总览（三支柱）

1. **只读受控记录视图（数据完整性红线）**：台账是只读投影，永不直接改值。每个单元格可溯源到一条受控 `HBOS Test Result`（限度冻结快照、判定引擎、电子签名、修订链、审计追踪）。修改结果必须走现有 `submit → review → approve → revise` 流程，原记录只可废止不可覆盖（ALCOA+）。
2. **样品类型展示模板（配置驱动）**：新增轻量 DocType `HBOS Ledger Template`，按样品类型（可到样品种类粒度）定义①明细模式登记信息字段及顺序；②样品表模式项目列及顺序。模板缺失时回退到"从该类型已有样品 / 质量标准自动推导"，台账永不空白。
3. **前端双视图**：明细台账（受控记录视角）+ 样品表（每样品种类一张表，数据表统计形式）。

## 前端交互定稿（Owner 已确认）

### 模式一：明细台账（受控记录视角）

- 左侧样品列表：每项显示样品名 + 状态标签 + 汇总判定角标（✗不合格 / ✓合格 / ·待判定 / ·部分合格），支持类型筛选 + 关键字搜索。
- 右侧样品卡片：
  - 登记信息区按样品类型渲染（成品显示 批数量/生产日期/有效期至/留样；工艺用水显示 水系统/取样点/取样时间/取样人）。
  - 检验项目区逐行展示 项目｜限度要求｜结果｜判定｜检验人｜记录状态。限度为规格冻结快照，判定为徽章（✓合格 / ✗不合格 / ⛔OOS候选 / 待判定），有修订记录的项目行有黄色圆点标记。
  - 底部 ALCOA+ 说明条：本台账为只读受控视图，修改必须走提交→复核→批准→修订流程。
- 下钻抽屉（点击任意检验项目行）：标准限度（冻结快照）、结果与判定、三级电子签名（检验人/复核人/批准人，未完成显示"待复核/待批准"）、修订记录（划线对比 + 原因 + 人 + 时间）、审计摘要（result_value、verdict 变更记录）。OOS 记录展示"结果不合格 → OOS候选 → 样品锁定"链路。

### 模式二：样品表（每样品种类一张表，数据表统计形式）

关键决策（Owner 确认）：**一个样品种类 = 一张表**，不是每个批次一张表、也不是每个样品类型一张表。

- 左侧下拉列表（仿飞书多维表格）：按样品类型分组、组头可收缩折叠。每个条目 = 一个样品种类（如 成品片剂A、成品片剂B、原料A、纯化水、铝箔内包材），显示"N 批检验记录"。**侧边栏不显示判定结果**。
- 右侧每样品种类一张表：
  - 首列 **序号**（1、2、3…，仅序号）。
  - 次列 **样品批号**（B240801、B240802…）。
  - 之后为该类型登记信息字段（物料编码、批数量、生产日期、有效期至、请验日期、检验时限、报告日期、留样；原料含供应商/到货日期；工艺用水含水系统/取样点/取样时间/取样人）。
  - 之后为检验项目字段（性状、含量测定、水分、干燥失重、有关物质…），单元格 = 结果值 + 单位，OOS 单元格浅红底。
  - 之后为 **判定** 列与 **记录状态** 列（数据区保留；侧边栏与表头固定标签不显示判定与状态）。
  - 数据按检测顺序以批次逐行填入，一个批次一行。
- 表头固定标签（样品卡片）：仅样品名 + 类型 + 质量标准 + 检验批次，不含批号、判定、状态。

### 视觉规范（Owner 确认）

- 表头字段字体、粗细、颜色统一（12px / 600 / 深墨色）；序号列样式独立保持。
- 判定徽章、记录状态徽章、数据单元格字号统一为 12px。
- 整体沿用制药实验室洁净严谨风格：深青侧栏、米白背景、绿色主操作、语义色 Pill。

## 后端落地设计

### 1. DocType：HBOS Ledger Template（检验台账模板）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| template_code | Data | 模板编号，如 `LEDGER-FG` |
| sample_type | Link → HBOS Sample Type | 绑定样品类型（必填） |
| material_name | Data | 可选；留空 = 该类型通用模板，填写 = 精确到样品种类 |
| reg_fields | Table → HBOS Ledger Reg Field | 明细 / 样品表模式要显示的登记字段及顺序 |
| test_items | Table → HBOS Ledger Test Item | 样品表模式项目列及顺序 |
| remarks | Data | 备注 |

子表 `HBOS Ledger Reg Field`：fieldname（对应 HBOS Sample 字段）、label（中文标题）、idx（顺序）、enabled。
子表 `HBOS Ledger Test Item`：item_name（检验项目名）、idx（顺序）、show_limits（是否在单元格悬浮/展示限度）。

### 2. whitelist 聚合 API：get_result_ledger

`lims_service.py` 新增 `@frappe.whitelist` 方法：

```
get_result_ledger(sample_type=None, material=None, mode="detail")
```

- **mode="detail"**（明细台账）：返回 样品列表（类型/状态/汇总判定）+ 每个样品 登记信息 + 逐项目受控记录（限度快照、结果值/单位、判定、检验人、记录状态、签名、修订链摘要、审计摘要）。
- **mode="table"**（样品表）：返回 分组列表，每组分 = 样品种类：reg_labels（模板字段）+ proj（项目列 + 限度）+ rows（每批次：序号、批号、登记值、各项目结果/判定/OOS、汇总判定、记录状态）。
- 数据来源：
  - 登记信息 ← `HBOS Sample`（含 Item 快照）；报告日期 ← `HBOS COA`（已发布）。
  - 检验项目 / 结果 / 判定 / 限度快照 ← `HBOS Test Result`（superseded 链只取当前有效版本；限度取 result 上的冻结快照，不随规格改版漂移）。
  - 判定 ← 判定引擎 `result_contract.judge_result` 已写入的 `verdict`。
  - 检验项目列顺序 ← `HBOS Ledger Template`；模板缺失时回退为从该样品类型已有样品任务创建顺序推导。
- 权限：复用现有 LIMS 角色校验（only_for），台账为只读查询，不提供写操作。

### 3. 回退逻辑（台账永不空白）

- 模板命中（sample_type + material 精确）→ 按模板渲染。
- 模板未命中 → 按 sample_type 通用模板；再缺失 → 从该类型已有样品的 Sample Item / 已完成任务自动推导项目集与登记字段。

## 数据流

```
HBOS Sample(+Item) ──┐
HBOS Sample Task ────┼── get_result_ledger ──► 前端双视图
HBOS Test Result ────┤        │  (只读投影)
HBOS COA ─────────────┘        └──► 判定/限度/结果/签名/修订/审计 逐项受控可溯源
HBOS Ledger Template ──► 列顺序与字段选择（缺失自动回退）
```
