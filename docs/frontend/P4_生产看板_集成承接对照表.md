## 3. #40 的 CI 问题：根因与本分支的修法

任务书指出「#40 前端构建存在接口遗漏」。核对后确认**三处**，都在**共用接口**上：

| # | 问题 | 根因 | 本分支修法 |
|---|---|---|---|
| 1 | `MobileAppNav` 导入 `type MobileNavGroup` 失败 | 产品分支的 `MobileAppNav.vue` 是 **LIMS 专用**（53 行，无该导出）；泛化版（122 行，带 props + `MobileNavGroup`）只在 #33 分支上 | 换为泛化版；默认值保留 LIMS 行为，`LimsLayout` 的 `<MobileAppNav />` 不改即通 |
| 2 | `ProductionLayout` 引用 `portal.bootstrapErrorStatus` / `portal.bootstrapError` | 这是 #33 给 store 加的字段；产品分支的 store **没有** | 改用产品分支已确立的 `usePortalSession()`（`sessionPending` / `sessionError`），与 `KnowledgeTwinLayout` / `LimsLayout` 同款，**不改 store** |
| 3 | 应用中心 / 应用切换器 / 路由里没有 production | #40 未登记共享文件改动 | 在 `AppCenter.appOrder`、`AppSwitcher` 白名单、`router/index.ts` 各加一处（见 §5 登记） |

**第 2 条是设计选择**：不去给共享的 `stores/portal.ts` 加字段（少碰共享面），
而是用产品分支已有的会话 hook —— 这也是另外两个 Layout 的现行写法。

## 4. 需要 Owner 注意的数据口径

- **质量合格率仍是写死的 99.9%**（Owner 2026-10-10 决定沿用既有看板口径）。
  IAM 边界提案 §4 明确要求「质量合格率缺真实来源时标识为未接入，不显示似真 99.9% 实测数」。
  **这两条是冲突的**，需要 Owner 裁定：是继续显示 99.9%，还是改成「待接入」。本分支**保持 99.9% 不变**，
  因为这是 Owner 最近一次的明确指令；改动留待裁定。
- **质量合格率 / 异常闭环率两个数字不是生产看板的核心交付**；产量与收率才是。
