## 1. 既有项目的形态（先摆事实）

openclaw 项目是**跑在另一台 Mac 上的自动化报表生成器**，不是网页应用：

```text
触发    launchd（ai.openclaw.dailyreport.1630.plist），每天 16:30
流程    generate_kanban.sh
          → 取 tenant_access_token
          → curl 循环把 14 张飞书表全量拉到 /tmp/kanban_cache/*.json
          → python3 generate_from_cache.py      （生成「生产管理中心看板」）
          → python3 generate_jiceng_from_cache.py（生成「基层管理人员看板」）
输出    PIL 渲染成 1920×1080 的 **PNG 图片**发出
```

它同时生成多种报表：日报（`daily_report`，含 `_guanli` 管理版）、周报（`weekly_report`）、
文本报告（`text_report`）、看板（`jiceng` / `from_cache`）、异常检查（`daily_anomaly_check`）、
能耗（`energy_june`）、异常回写飞书（`sync_anomalies_to_feishu`）。

## 2. 核心对照：**会议要改成什么样 vs 代码现在是什么样**

四条主要分歧，**逐条都指向同一个结论：会议是「决策目标态」，代码是「现状」**。

|---|---|---|---|---|

| **3** | **收率落月口径** | 按**收料日期** | 按**投料日期**（CDCA/B6 用入库日期/入库时间） | ❌ 不一致 |
| **4** | **行的范围** | 跟着在产**自动调整**；并排除欧盟线／混粉／晶种／USP／碳酸氢钠等 | **8 行硬编码在代码里**，且**无任何产品过滤逻辑** | ❌ 不一致 |

**第 4 条的佐证**：代码里既没有排除规则，也没有动态行 ——


八行写死。会议新增的排除规则（欧盟线／混粉／晶种／USP）在代码中**完全不存在**。

## 3. 意外收获：三个悬置问题当场解开

### 3.1 F13 的目标映射 —— **印证「F13 = 粗品B + 粗品C」**

代码里的 `name_map` 写得很明确：

```python

    "CDCA": "B5",                    # CDCA 的目标取自「B5」行
    "F13":  "美罗培南粗品B",
    "F13-A":"美罗培南粗品C",          # F13 显示值 = F13 + F13-A
    "亚胺培南": "亚胺培南（CEP）",
    "美罗培南": "美罗培南",
}
...
("F13（含A线）", df13_combined, targets.get("F13",0) + targets.get("F13-A",0), ...)
```

- **F13 目标 = 粗品B 目标 + 粗品C 目标** —— 与 Owner 2026-09-30 的裁定**完全一致**；
- **CDCA 的目标取自 `B5` 行**（新信息，此前不知）；
- **「无菌亚胺培南」的目标取自 `亚胺培南（CEP）` 行**（新信息）。

### 3.2 收率标准 —— 会议待办里那条，代码里已有


**除 CDCA 外全部吻合** —— 说明「收率标准」不是要另给一份新资料，**很可能就是 `月度目标产能.目标收率`**；CDCA 那处偏差需生产确认。

## 5. ⚠️ 既有项目里发现的两个缺陷（建议一并反馈）

### 5.1 无收率数据时，「收率达标率」会算成 100%（假达标）

```python
yield_data = [
    ...
    (yf13_combined if yf13_combined else 999, 0),   # 无数据 → 999，标准 0
    (ymeropenem   if ymeropenem   else 999, 0)      # 999 >= 0 恒成立
]
yield_data = [(v, s) for v, s in yield_data if v is not None]
qualified = sum(1 for v, s in yield_data if v >= s)
yield_rate = int(qualified / len(yield_data) * 100) if yield_data else 0
```

`shared_data.json` 的实际输出就是 `"yield_rate": 100` —— 而当时 F13、美罗培南都没有收率数据。
**「没有数据」被当成了「全部达标」**。这在管理看板上是**误导性**的（100% 达标会让管理层放心，实际是没算）。

**建议**：无收率数据的品种应从达标率的分母中剔除，而不是补一个恒达标的 999。

### 5.2 「已生产批数」按**投料日期**落月（与会议要求的收料日期不符）

```python
mr4b  = get_month_records(r4b,  "投料日期")
mrcd  = get_month_records(rcd,  "入库日期")
mrb6  = get_month_records(rb6,  "入库时间")   # 各品种用的日期字段还不统一
```

**同一张看板上，8 个品种用了 3 种不同的日期字段**：投料日期 / 入库日期 / 入库时间。
月末月初的交界批次（8 月底投料、9 月初收料）会被算进不同月份，**且各品种口径不一致**。

## 8. 对 HBOS 生产看板的影响（结论）

**会议那套规则是「目标态」，既有代码是「现状」，两者不一致的 4 条以会议为准。**

具体到本项目要做的事：

**沿用既有项目的**：

- 完成率 = 批数口径（`已生产批数 ÷ 目标批数`）—— **两侧一致，可沿用**；
- F13 = 粗品B + 粗品C、CDCA 目标取 B5、亚胺培南目标取（CEP）—— **映射关系可沿用**；
- 收率标准参考 `YIELD_STANDARDS`（CDCA 待定）。

**要按会议改的**：

- 数据源（待第 1 条确认）；
- 目标改用 `月度生产计划明细` 求和；
- 落月口径改用**收料日期**；
- 行改为**数据驱动 + 会议排除规则**（欧盟线／混粉／晶种／USP／碳酸氢钠等不录）。

**本项目不做的**：

- 不复制既有项目的代码或数据（按 Owner 指示，只作参考）；
- 不用它的 PNG 渲染方案 —— HBOS 是网页，用 Vue + 数据驱动。

**本文只作口径对照，不改动既有项目、不写入飞书。**
