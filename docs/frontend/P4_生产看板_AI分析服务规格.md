**每张表 3~12 行，字段是「工序名」，`项目` 列区分三种维度**：


**这三行就是 AI 的判定基准** —— 标准参数给「应然」，工艺描述给「怎么做」，设备描述给「用什么做」。

## 3. 处理

### 3.1 按产品跑，一天一轮

```
for 产品 in [4BMA, F9, F12, F13, 无菌美罗培南, 无菌亚胺培南]:
    读该产品的工艺描述（3 行）
    读该产品的台账（当月在产批次 —— 只取有变化的）
    组提示词 → 调模型
    解析结构化输出
    按「数据指纹」判重 → 写回飞书结果表
```

**只分析在产产品**（与看板范围一致：6 个）。

### 3.2 幂等：数据指纹（**这一条是硬要求**）

既有 openclaw 项目出过一个缺陷：`B6生产台账_AI测试` 里同一格被追加了 **64 次**同一句话（896 字符）。
根因是**写入前不清空、也不判重**，每次跑都往后叠。

**本服务必须做**：

```
指纹 = hash( 产品 + 工艺描述内容 + 该产品台账的最后修改时间/最大 updated_at )

写之前：
    查结果表 WHERE 产品 = X AND 工序 = Y
    若已存在且 数据指纹 相同 → 跳过（日志记 skipped）
    若已存在但 指纹 不同     → 更新该行（不是追加）
    若不存在                 → 新增
```

**一个产品一道工序一行** —— 不是每次跑追加一行。这样表不会无限膨胀，看板读到的永远是「每条工序的最新结论」。

### 3.3 模型

**待 Owner 定**：

| 项 | 说明 |
|---|---|
| 用哪个模型 | 建议选**长上下文**的（台账 + 工艺描述一起喂，有的台账 115 字段） |

## 5. 输出规格：照《4BMA降本增效实验方案分析报告》

Owner 提供的那份报告**本身就是可用的输出规格**。它的关键约定：

### 5.1 证据分级（全文贯彻）

```
【文档事实】      原文数据、条件、作者结论或计划
【分析判断】      报告自己的比较与审查
【待验证假设】    只作为下一轮验证方向
【结论：数据不足，暂不能判断】
```

### 5.2 缺数据就明说，不臆测

报告里「文档无相关数据」出现几十处，例如：

> 定量 7eβ 产出、投料基数、外标方法、取样时间、批号、重复、转料损失、终品质量与安全放大数据：
> **【文档无相关数据】**

**这是本服务最重要的行为约定** —— 宁可写「数据不足」，也不补一个像样的推测。
看板上的 `评级 = 数据不足` 正是这个原则的输出。

### 5.3 每个工序固定七段

```
当前现状 → 目标 → 原优化方案 → 已实施实验 → 实验结果分析 → 是否达到目标 → 数据完整性
```

### 5.4 评级用五维（看板只用前两维）

| 维度 | 取值 |
|---|---|
| **是否达标** | 已达标 / 部分达到 / 数据不足 / 未达标 ← **写进结果表的 `评级`** |
| **技术可行性** | 设计可审查 / 实测支持 / 概念方案 … |
| 数据支持程度 | 无实测 / N 条件 / 少量重复 … |
| 是否建议保留 | 保留实验方向 / 不保留 … |
| 是否建议继续验证 | 先小试定量 / 先补齐质量证据 … |

### 5.5 结尾给「下一阶段最该做的 N 件事」

每条带**交付证据 / 完成门槛**。

## 6. 定时

```
每天 16:30   跑分析 → 写回结果表
```

**实现方式**：与 `hbos_ocr` 不同，这个服务**不是常驻等请求**，而是**定时触发**。两种做法：

| | 做法 | 说明 |
|---|---|---|
| **A** | `launchd` 定时跑一个脚本（同 openclaw 的 `ai.openclaw.dailyreport.1630.plist`） | **与本机既有做法一致**，推荐 |
| **B** | 常驻服务 + 内部定时器 | 服务要一直开着，多一层运维 |

**推荐 A**：脚本跑完即退，不占常驻内存；与 `hbos_ocr` 那种「等请求」的服务定位不同，
两者可以共存（各自独立）。

## 7. 与取数服务的关系

**两个服务，分开**：

| | 取数服务 | AI 分析服务 |
|---|---|---|
| 触发 | 前端 HTTP 请求 | **定时 16:30** |
| 飞书操作 | **只读** | 读（台账+工艺描述）+ **写**（结果表） |
| 常驻 | 是 | 否（脚本跑完即退） |
| 端口 | `127.0.0.1:8101` | 无（不需要端口） |

都会以「结论」的形式直接影响生产决策。实现时会把它写进提示词并加一道输出校验。
