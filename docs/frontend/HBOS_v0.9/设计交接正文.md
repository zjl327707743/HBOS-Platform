### 字重与字距

实际包含450、550、600、650、740等字重与局部负字距。新规则对.page-heading、分区、认证标题设tracking 0，不等于全站标题均为0。数字启用tnum；仍需检查字体是否提供真实字重和数字特性。

### 实施与验收要求

采用4px间距基元作为生产方向，常用8/12/16/20/24/32/40/48/64。当前非整倍数、特殊偏移、连续clamp和局部响应值应先保留在实现快照，再决定是否规范化。

把全局壳、管理目录、内容网格、认证壳与数据表分层管理。不能用768/1200两档解释现实现，也不要把所有历史断点直接复制到每个业务应用。

生产目标为320px等效宽度重排、200%文字缩放可读、关键动作和焦点不被固定区域遮挡。二维数据允许局部滚动；当前390/768/1280记录不证明320与缩放已完成。

## 07  导航搜索与管理入口

### 产品壳与渐进展开

顶栏包含品牌、全局搜索、应用切换、账号入口；丰富场景有通知Mock。v0.9主顶栏没有独立动效开关，动效位于原型设置。侧栏保留核心入口，管理中心改为可展开组；管理页顶部另有五项上下文导航。[P4,P9]

refinement.js把details改造成button加内容区，保留初始展开状态、aria-expanded和aria-controls；文案用“查看/收起”。管理组每次壳重绘默认收起，当前管理页用active标记；折叠态点管理图标先展开侧栏，再打开子组。

页面切换使用hash；/hbos/admin映射员工管理；侧栏标aria-current。P.go和hashchange有脏草稿/busy处理，页面聚焦main仅覆盖相应路径。刷新、返回、深链接与辅助技术仍需按生产路由重做验收。

| 功能 | 当前行为 | 限制与生产合同 |
| --- | --- | --- |
| 全局搜索 | Ctrl/⌘+K或入口打开；上下箭头、Enter、Esc；空查询不返回记录。 | 全局已跳过isComposing/keyCode229；只在非账号页、无弹窗且非busy时打开。 |
| 搜索范围 | 本地页面、可见演示应用，丰富情景可含任务。 | 真实搜索由权限和来源服务决定，不回退全量数据。 |
| 结果去向 | Portal结果走hash；任务/应用打开摘要或边界说明。 | 需要真实业务启动、实体路径和失败恢复合同。 |
| 应用切换 | 与示例可见目录同源；常用为featured配置。 | 不承诺个人收藏、最近使用、拖排或真实授权。 |
| 管理上下文 | 五项真实button；当前项带aria-current；窄屏尝试滚动到选中项。 | 不是完整ARIA tabs控件，不假设方向键切换或状态持久化。 |

### 统一外壳的复用原则

未来业务应用复用品牌、当前应用身份、搜索与稳定返回路径，同时保留自己的任务结构。Portal一级导航不平铺全部专业功能；不能同时呈现两套竞争主导航。

原型地图、演示身份、情景与模拟确认只供交接核对，不默认进入生产工作流。每个不可用入口须说清未开通、无权、失败或未知，前端隐藏不能替代服务端授权。

## 08  选择控件与键盘焦点

### 自定义目录下拉的精确范围

controls.js只增强.admin-directory-filters中的select。原select隐藏但保留为单一状态源，旁边增加choice-trigger；选中后写回value并派发change。员工表格工具栏、账号和其他select仍可保持原生，不是全站都换成新下拉。[P11]

| 项目 | 当前实现 |
| --- | --- |
| 外观 | trigger最小44高、14/22、padding11×12、radius10；浮层radius14、blur24、z-index3000，选项最小44高。 |
| 定位 | 固定定位；宽max(trigger,220)，不超过视口−24；左右至少12；优先下方8px，空间不足尝试上方。 |
| 高度 | CSS max-height=min(300px,70dvh)，纵向滚动；长值可换行；不内置搜索或多选。 |
| 打开 | 点击或ArrowUp/ArrowDown打开；role=listbox，选项role=option，aria-selected/disabled。 |
| 选择 | 方向键、Home/End改变active descendant；Enter/Space选择；点击选项写回select。 |
| 关闭 | Esc关闭并回触发器；Tab关闭后继续Tab默认行为；外点、resize、hashchange、外部scroll或触发器移除关闭。 |
| 焦点恢复 | 选择后requestAnimationFrame按原select ID找到新触发器；重绘场景依赖ID保持和下一帧时序。 |

### 必须保留的限制

方向键遇disabled选项会停留，不会继续跳过；没有typeahead字符搜索。浮层打开后不会持续重新定位，而是部分事件关闭。目录下拉handler没有IME防护，关闭后aria-controls仍可指向已移除菜单；屏幕阅读器与滚动容器兼容待验证。

迁移建议优先使用已验证的Ant Design Vue Select或受控包装组件，实现同样视觉与业务change语义；不要照搬MutationObserver增强方式作为正式组件架构。保留禁用原因、错误、读写状态和长选项测试。

### 一个组合控件只显示一个焦点边界

全局.search-box采用12圆角完整边界；input-wrap依作用域常为9圆角。focus-within外环为2px #7563DD、offset2及白色halo；内部input去掉outline、border与shadow。通用独立控件仍有3px #5945D6焦点轮廓，导航采用向内offset。

不能为了避免双框移除键盘焦点。触发器、浮层、错误字段和被重绘对象都应保留可见焦点与可访问名称；自动化数值检查不替代人工键盘顺序和读屏确认。

## 09  可复用组件合同

以下合同用于正式组件库实施。原型目前是HTML模板函数、CSS及事件委托，不是已发布Vue组件库。不得以同名组件存在推断状态全覆盖。

| 组件 | 结构与状态 | 正式实现要求 |
| --- | --- | --- |
| Button IconButton | 主次危险、hover、pressed、focus、disabled、loading。 | 一个任务区一个主动作；忙碌防重入，不跳宽；图标有名称。 |
| Field Input Select | 可见标签、说明、必填、只读、禁用、校验中和错误。 | 标签关联ID；错误与字段关联；失败保留无关输入。 |
| Card TaskRow | 对象、标题、来源、状态、下一步；单一或明确子动作。 | 不嵌套交互元素；不靠hover暴露唯一动作；不直接办高风险业务。 |
| Tag Badge | 语义文字、图标或形态、计数口径。 | 业务状态不只靠色彩；应用域色不表示健康。 |
| Tabs FilterBar | 选中、禁用、条件、结果数和清除。 | 按实际模式提供键盘/ARIA；筛选不能扩大批量操作对象。 |
| Toast InlineAlert | 短成功、持久失败、需处理提示。 | 关键失败留在原界面；aria-live适量；不以toast代替字段错误。 |
| Dialog Drawer | 命名、滚动内容、动作、关闭、dirty/busy/unknown。 | 隔离背景、初始焦点、焦点循环及返回；清楚处理未知结果。 |
| DataState | loading、ready、empty、error、forbidden、stale。 | 区分范围、来源和原因；重试读取与重新提交分开。 |

### 实际尺寸并未全部统一

普通.btn声明min42，手机44，但更具体规则仍胜出。1280/390实测：首页首按钮40/39，工作页首按钮42/34，员工页38/34；飞书登录均56，账号安全卡仍有42等例外。手机图标min-width40/min-height44，不能称所有目标44×44。[P13]

登录展开输入在1280/390均实测44高、14/21、radius10，48px声明未胜出。搜索框内部input仅22高，不是外层命中区。个人中心记录中的首个输入位于初始隐藏区域，40px计算样本不能当作可见视口测量。以组件状态和作用域解释实值。[P13]

### 内容与接口

动作使用“保存草稿”“发布生效”“查询上次结果”等准确动词。危险操作明确对象、范围和后果；内部标识可在详情展开，用户可见名称使用自然中文但不丢失业务含义。

建议接口包含variant、size、loading、disabled；Field传label/description/error；Dialog传open/title/initialFocus/returnFocus/dirty/busy和close请求。服务层管理权限、幂等、版本与结果查询，组件不自行判断身份成功或授予权限。

## 10  工作台与数据状态

### 当前呈现与交互

工作台保留Hero、示例指标、常用应用、业务概览与设备示意；右侧三个工作路径已变为可点击按钮，分别到个人中心、应用中心和我的工作。指标点击解释来源，不查询实时经营数据。[P4,P9]

我的工作按“需要我处理、等待别人、已完成”等组织，支持关键词与来源筛选。正常情景任务集为空，丰富情景才返回示例任务；详情与来源入口均不执行审批、完成或业务写入。

应用中心查询同时过滤常用和完整目录。常用项来自平台配置，不记录最近使用。消息通知和周期汇总均为Mock；“智能工作平台”目前没有接入AI对话、知识推理或自动推荐。

| 状态 | 正式界面必须表达 | 不能混淆为 |
| --- | --- | --- |
| 加载中 | 范围、骨架、稳定布局和重试条件。 | 已登录、已授权、已保存或无限等待。 |
| 正常 | 来源、时间、口径、单位与对象对应的动作。 | 无来源的逼真实时指标。 |
| 确实为空 | 当前范围无记录及合适下一步。 | 读取失败或权限仍未知。 |
| 筛选无匹配 | 保留条件、结果数、清除入口。 | 全部数据被删除或权限被收回。 |
| 失败 | 失败来源、可用区域、重试读取和输入恢复。 | 零条记录、已提交成功。 |
| 无权或身份待确认 | 拒绝原因或正在核验；隔离旧身份内容。 | 全量权限或继续暴露旧身份数据。 |
| 陈旧或离线 | 最后成功时间、有效性、是否允许继续操作。 | 缓存就是最新，断网即默认成功。 |

### 情景覆盖的边界

顶部情景覆盖正常、丰富、空、加载、失败、会话未确认，部分情景替换整个受保护内容区；账号模块另有独立状态。不能称每个模块均实现局部加载、离线、混合失败和全部状态组合。

生产待办、通知和业务状态应有不同计数定义。等待别人、已完成或纯通知不得加入“需要我处理”；从摘要进入来源系统要保留对象和返回上下文。

管理列表使用原生table和列标题。≤680时变成卡片，data-label与值同列；表头视觉隐藏而非删除。当前行高由内容与padding形成，record-table单元格上下18px!important会覆盖旧紧凑padding；密度开关不代表所有表格都变为40px固定行高。[P3,P5,P9]

refinement.css把.modal-body直系或直系form中的.form-actions改为static，取消旧sticky重复底栏。管理角色页.sticky-actions仍可sticky；不得把“浮层操作区不粘底”扩写成全站无sticky。

### 生产合同

表格正文候选14/22；舒适/紧凑密度以内容与命中目标共同定义。数字带单位对齐，实体左对齐；排序、列显隐、列宽、保存视图按需求实施，不算现有能力。

批量操作明确当前页或全部筛选结果，预览可执行/不可执行对象；更改筛选不能静默扩大已选范围。虚拟化须保留行列关系、总数、焦点与读屏。

表单按任务分组、单列优先；状态分清未改、已改、验证中、提交中、已确认、失败和未知。失败保留输入，提供字段关联与可定位错误摘要。

Drawer适合详情与轻编辑，Modal适合短确认；长流程、专业审批与电子签名留在对应业务应用，不塞进Portal摘要弹窗。

## 12  登录与身份确认体验

### 登录视觉与优先级

登录采用左侧品牌故事和右侧身份卡。中文名称、HBOS副标、三层玻璃线框与原企业字标保留，重复中心Logo和悬浮标签已移除。手机隐藏故事与装饰，只保留品牌条与表单，优先让登录动作可见。[P6,P9,P10]

首屏飞书为主要入口，使用账号密码为次要展开入口，另有忘记密码。安全提示明确演示，不诱导填真实凭据；演示情景与说明默认折叠。

| 阶段 | 当前演示行为 | 生产接入要求 |
| --- | --- | --- |
| 选择方式 | 飞书入口或展开账号密码；取消身份确认回到选择方式。 | 按实际渠道开通状态决定入口，不伪造登录可用。 |
| 等待授权 | 显示1/3当前步骤、静态紫点、简短身份说明和单一继续动作。 | 等待用户操作不是加载；未授权不得标完成，不预读取身份。 |

账号确认取消会清理残留授权中间态，返回登录方式选择。绑定完成显示符合结果的下一步。登录与绑定空输入提交后定位缺失字段并标aria-invalid；后续字段错误关联仍需完整回归。

页面不存在真实飞书OAuth跳转、扫码、授权范围读取、邮箱发送、认证器或AI服务。模拟成功只推进本地演示状态；静态文件可直接打开不代表生产登录能离线工作。

## 13  账号安全与结果恢复

账号安全保留业务含义，不因文案自然化而合并对象或状态。个人中心区分员工身份、登录密码、飞书绑定、渠道可用性与恢复渠道。系统账号不绑定员工档案，飞书只用于本人登录。[P6]

| 流程 | 原型范围 | 正式合同 |
| --- | --- | --- |
| 身份关联 | 已关联、待关联、冲突、读取失败。 | 员工档案与登录账号分开；不得按姓名自动认领。 |
| 密码设置与变更 | 两次测试文字、影响确认、首次密码门、失败与未知结果。 | 真实策略由认证系统给出；凭据不写日志或前端存储。 |
| 飞书与恢复渠道 | 绑定状态与渠道开放状态分开；普通邮箱/本人飞书/管理员协助。 | 发送不等于送达或已读；恢复流程不任意新增邮箱。 |
| Administrator恢复 | 展示本机启动器admin-password受控恢复说明。 | 未执行任何本机命令；不在线签发恢复凭据或代登记认证器。 |
| 安全状态加载 | loading/error/stale有不同提示与恢复入口。 | 未确认最新安全状态前不能继续写入。 |

### 四类安全变更

本人更换飞书、平台管理角色交接、Administrator账号保管交接、普通账号身份恢复分别建模。角色交接只移交选定角色，账号保管交接不合并个人业务身份；新飞书已有来源账号时保留并核对账号、角色、资料与密码入口。

流程保留发起人/参与者视角、有效期、验证依据、目标账号、旧绑定边界、参与确认与一次性提交。成功文案按操作类型说明，不泛称所有原登录方式失效。拒绝、取消、过期处理测试输入与草稿，不误清仍待核对的结果。

### 未知结果优先查询

v0.8已修正密码结果未知时关闭后重开丢失状态的问题：可重新进入并查询待确认结果，不能直接再提交。异步完成后清理busy/P.busy及底页禁用状态。v0.9沿用这些机制；完整超时、竞态与异常恢复仍需生产验证。[P6,P10]

查询结果不是统一成功：账号确认查询保留unknown并增加提示；密码、恢复、解绑和安全变更查询可切换到本地完成；管理员恢复查询只核对签发记录，不能重读原链接。

原型查询返回的是本地预设结论。正式API必须提供请求标识、权威结果查询、幂等与版本冲突处理；不知道服务端是否成功时，禁止用“重试保存”代替查询。

首次密码门只在/profile渲染，没有跨路由强制锁定证据；倒计时主要由每秒检查触发，未见每次提交及异步完成时统一重验有效期。正式实现必须补齐会话与路由强制、票据时效和竞态校验。

### MFA与凭据边界

MFA仅为占位演示，不生成二维码、密钥或恢复码。正式认证器登记、密码恢复、身份交接应遵守现行安全流程；设计交接不赋予任何真实账号或权限变更授权。

## 14  管理权限与审计

管理中心面向平台管理者。普通演示成员进入管理页显示无权，演示只读身份不能保存；前端身份切换不是正式权限控制。自然中文文案仍保留准确编号、范围与业务差别。[P5]

| 模块 | 现有演示 | 不可改变的含义 |
| --- | --- | --- |
| 员工管理 | 员工档案、待关联账号、其他账号；筛选分页、详情、开户、关联、应用角色、调岗预览。 | 新建档案不自动开户；员工、登录账号、应用角色是不同对象。 |
| 部门权限 | 目录、公司/部门筛选、默认角色、个人例外、影响预览、成员准入。 | 部门默认保留个人例外；改变默认不自动确认所有成员。 |
| 角色权限 | 已发布、草稿、保存、差异、发布核验、历史恢复成草稿。 | 保存草稿不生效；发布独立确认；历史恢复不直接覆盖生效配置。 |
| 其他应用 | 接入应用与原管理入口；共享员工详情。 | 当前考勤接入不能扩写为所有应用授权贯通。 |
| 变更记录 | 中文字段/枚举、对象标识、日期/操作/结果筛选、本地分页、前后快照。 | 本地record不是服务端写入或合规审计证明。 |
| 管理不可用 | 获准范围未知或不可用的说明与返回。 | 未知不等于零条，也不能回退全部权限。 |

### 限制必须分别表达

不安排某应用角色、暂停该应用访问、停用整个登录账号是不同操作。角色发布不自动清除个人禁止、暂停、期限或停用；调岗保留个人安排、账号主键和历史归属，另行预览实际变化。

管理目录与角色条目不再使用受限高度的内部长列表，页面主体承担滚动；侧栏与弹窗仍有独立滚动区域。折叠说明、目录筛选与工作区导航属于呈现优化，不改变授权范围。

### 审计与生产数据

原型快照对password/token/secret等键脱敏，并限制深度与长度；这不是生产防泄漏认证。真实事件应由服务端生成事件ID、操作者、目标、时间、版本和结果，并按权限查询。

清楚区分查询条件与已应用条件，确定时间边界和时区。从员工、部门或角色跳转审计时验证参数生效；URL恢复筛选是生产合同，不从页面存在推断已完成。

动效默认开启，控制位于原型设置；设计系统辅助页保留测试按钮。用户关闭或系统prefers-reduced-motion为reduce时加no-motion；CSS关闭动画/transition，JS停止粒子。开关aria-checked反映用户设置，系统禁动时仍可能为true，不能当作最终有效状态。[P4,P9]

document.hidden取消rAF并为极光、扫光、装饰球暂停CSS；不代表每个登录/加载动画都有显式hidden暂停。粗指针CSS隐藏光晕与canvas，JS同时检测finePointer；触摸不先更新坐标，已修正v0.2限制。

### 生产合同与未来拖动

偏好仅保存在当前页内存，刷新重置。生产可按批准范围持久化，并显示系统约束后的有效状态；卸载释放事件和观察器，降级按实测性能而不是主观帧率。

本轮无应用拖动排序。若新增，必须独立需求，提供拖动柄、合法落点、取消、撤销、保存失败回滚，以及无需拖动的单指针替代和键盘操作。不得用拖放执行审批、删除或高风险写入。[A3]

旧运动时长表可作为未来收敛候选，不作为现已实施值。实施时优先transform/opacity，业务操作区保持稳定，减少动态不能破坏功能。

## 18  交接文件与实施顺序

### 交接文件各自负责什么

完整规范DOCX提供实值解释、业务边界、组件合同与验收要求。离线HTML用于直接打开、点击和逐屏对照；完整源码ZIP提供可维护输入、资源、构建与证据。若HTML和源码封装在同一个交接包中，其职责仍分别保留。

离线版本内嵌CSS、脚本、标志与附件，可在无网络环境演示；源码入口为dist/index.html，可用静态服务器预览。外部参考链接仍需联网，不能把无运行API误称整个文件没有任何外部URL。

完整源码指本原型的HTML/CSS/JavaScript、资产及构建材料，不是HBOS生产仓库或后端完整源码。它能支持一比一视觉参照，但不自动完成Vue组件化和业务接入。

### 按阶段迁移

第一步：以用户接受的v0.9原型为视觉基线，冻结具体视口、真实字体、路由与关键状态截图，读取本规范中的现有异值。接受状态不必重新退回“待评审”，但新增改变须单独确认。

第二步：在本地新阶段盘点现有产品结构和Ant Design Vue版本，建立主题映射与差异表，先完成Shell、导航、按钮、字段、状态和浮层。

第三步：复现工作台、工作列表、应用中心，再迁移账号与管理。保留16个产品页面的业务边界，2个辅助页仅作交接参考；避免视觉升级顺带新增收藏、拖排或业务内部页面。

第四步：分离原型Mock与真实服务，分别接入身份、权限、待办、通知、账号安全和审计。未接入的区域明确不可用或演示，不显示虚假成功。

第五步：对照视觉基线、控件状态、取消/失败/未知恢复、移动端与辅助技术回归；交付真实测试证据后才判生产完成。

### 未来应用的复用强度

保留V3展示、V2概览、V1操作、V0管理分层方向：Portal可用已接受玻璃与氛围；业务录入、审批与权限管理优先稳定可读。当前原型背景不是所有未来应用必须使用持续粒子的要求。

产品负责范围和权限，设计负责视觉与响应式，前端负责组件与API，QA负责状态、设备和证据。真实产品Authority及Typography规则的正式替换应单独批准，不由交接文件自动生效。
