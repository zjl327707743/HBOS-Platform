## 1. 为什么做这一页

Inventory 现有入口里，**只有「入库拍照识别」是仓管每天真正用的操作页，而它还是 Desk 上的 jQuery 页面**（826 行 JS + 337 行 CSS）。概览页已经前端化，点这个入口却要整页跳出 Portal。

这一页是 Inventory 前端化的**第一块操作面**，也是最大的一块。

## 2. 三条不可动摇的业务规则（本页只是换皮，不动规则）

来自现有页面的模块注释：

1. **识别服务不可用时如实提示，引导人工录入，绝不伪造结果；**
2. **识别结果不直接入账，只生成草稿，由操作员复核后自行提交；**
3. **任何字段都可人工改正，改正后再生成草稿。**

另有四条既定口径：

- **不自动创建物料主数据**——识别到未知物料只提示，不擅自建档；
- **物料级字段仅补空**（`hbos_storage_condition` / `hbos_workshop` / `hbos_shelf_life_type`），已有值锁住不被覆盖，且只有受权主数据角色可写；
- **品名以主数据为准**，本页不可改；AI 读到的值并列展示用于暴露读错；
- **物料代码必须带出**——主数据里没有该代码时，形近纠错**唯一命中才改**，多命中只列候选让人自己选（不猜）。

## 3. 视觉强度：V1

按 EA-5.4 §2.2：

| V1 要求 | 本页做法 |
|---|---|
| 信息效率第一 | 照片与校对同屏，校对区占更宽（1 : 1.02），不用弹窗、不用分步向导 |
| 动态背景关闭 | **无 aurora、无粒子、无鼠标光场** |

### 4.1 为什么是「照片｜校对」双栏，而不是上下分步

现有 Desk 页是双栏 + 步骤卡片，本页沿用双栏，但做了两处结构性调整：

**照片栏 `position: sticky`。** 校对区很长（5 组字段 + 包装行 + 原文逐行），滚到下面时照片会滚出视野。而校对这件事的**全部意义就是对着照片核**——照片滚走了，操作员就得来回滚。所以照片栏粘住不动。

**底部动作条常驻。** 「货位 / 数量 / 生成草稿」原本是第 ④ 张卡片，在页面最底部，填到一半想改货位就得滚到底。现在它 sticky 在视口底部，随时可点。**全页唯一 Primary 按钮**就是它（EA-5.4 §25）。

### 4.2 为什么用「分组」而不是原来的 5 张卡片

原页把识别字段、物料级、本批、包装、原文分成 5 张并列卡片，每张各自有说明文字，读起来像 5 件不相干的事。本页改成**一个校对面板里的 5 个分组**，组标题下直接写这一组「为什么需要你填」：

- 识别到的字段 —— 代码最可靠，品名以主数据为准；
- 物料级补充 **[须人工填写]** —— 标签上是小字，识别读不准；
- 本批信息 **[须人工填写]** —— 不在识别字段里，外购料的待检证要用；
- 包装构成 / 件数 —— 件数自动汇总，便于与标签核对；
- 标签原文逐行 —— 照片没法搜，文字可以。

**「须人工填写」用深色实底标签**，不是浅色提示——它不是「可选补充」，是**必需动作**，原来页面上这一点被弱化了。

### 4.3 ① ② ③ ④ 编号是有意义的

EA-4 提醒「编号只有在内容真的是序列时才用」。这里确实是序列：拍照片 → 识别 → 校对 → 生成草稿，**顺序不能换，跳过会出错**。所以顶部有流程指示条，当前步高亮、已过步打勾。

## 5. 状态设计（本页 7 态）

原型脚手架可逐个切换：

| 状态 | 呈现 | 关键设计点 |
|---|---|---|
| ① 未上传 | 空照片槽 + 「选择 / 拍摄照片」 | 校对区同时给「还没有可校对的内容」 |

| ③ 待校对（有可疑） | 橙色告示 + 可疑字段橙框 | 每个可疑字段带文字说明，不靠颜色单独表达 |
| ③ 待校对（无可疑） | 绿色告示 + 仍建议逐行核 | **不因「无可疑」就撤销人核要求** |
| ④ 已生成草稿 | 成功态 + 「打开草稿复核」 | 动作条**隐藏**，避免重复建单 |

### 5.1 服务不可用：不给死路，也不伪造

原页的做法是「如实提示 + 引导去 ERPNext 原生入库单人工录入」。**按 Owner 口径这不对了**——仓管不跳后台。所以本页改成：

> 识别服务暂时不可用，字段不会自动预填。你仍然要先把标签照片传上去（它是草稿的原始凭证），
> 然后照标签把下面填完，照常生成草稿——流程一步都没少，只是少了自动识别。

**注意照片仍然是必须的**：它是草稿的原始凭证，识别不了也要留。所以提示指向 ① 而不是让人跳过。

## 7. CSRF 令牌（**已解决**）

**结论：采用方案 B，已实现并实测通过。**

### 背景澄清

CSRF 校验**不是后加的限制**，是 Frappe 框架内置行为，一直在跑
（`apps/frappe/frappe/auth.py` 的 `validate_csrf_token()`，认证流程中无条件调用）。项目里从未配置过
`ignore_csrf` 或 `allowed_referrers`。此前没暴露，是因为 Portal 所有接口调用**全是 GET**
（`frappeClient.ts` 只发 `http.get`）。

Desk 页能用，是框架往 Desk 页面注入了 `frappe.csrf_token`。Portal 是独立前端、跨源，
拿不到这个注入——本地开发甚至跨端口（`sid` 是 host-only cookie，`:8080` 与 `:5178`
在浏览器看来是不同来源，连 cookie 都读不到）。

### 最终做法

`apps/hb_inventory_app/.../hbos_inventory/api.py` 新增：

```python
@frappe.whitelist()
def get_csrf_token() -> str:
    from frappe.sessions import get_csrf_token as _issue_token
    return _issue_token()
```

与 `hb_lims_app.hbos_lims.lims_service.get_csrf_token`（LIMS 独立前端用）**同款做法**，
不发明新模式。

**安全边界**：本接口不返回任何超出会话本身的信息。调用者能拿到 token，前提是已持有该会话
的有效 cookie；没有 cookie 就拿不到 token，拿不到 token 就发不出合法 POST。因此**没有削弱
CSRF 防护**。实测访客（无 cookie）调用返回 **403**，符合预期。

**刻意不做 `_require_permission()`**：token 是会话级的、不携带业务数据；在此校验库存角色只会给
「有 Portal 访问权但无库存权限」的用户多一个无意义的失败面，而真正的权限校验在
`recognize_label` / `create_intake_draft` 里逐条把关。此决定已被测试钉住（见下）。

### 实测验证（真实 HTTP）

| 步骤 | 结果 |
|---|---|
| 调 `get_csrf_token`（已登录） | 200，返回 56 字符 token |
| 带该 token 发 POST | **200** ✅ |
| 同样 POST **不带** token | 400 `CSRFTokenError`（对照） |
| 调 `get_csrf_token`（无 cookie / 访客） | **403** ✅ |

### 测试

`apps/hb_inventory_app/tests/test_governance.py` 新增 3 条：

- `test_csrf_helper_delegates_to_frappe_and_invents_no_token` —— 必须转发框架的 canonical
  实现，**不得自造 token**（自造会与 session 里那份对不上，POST 依然 400，却看起来「修好了」）；
- `test_csrf_helper_does_not_gate_on_inventory_roles` —— 行为契约，防止将来有人「顺手」加权限校验
  而不显式讨论；
- `test_csrf_helper_is_whitelisted_and_documents_itself` —— 必须 whitelisted，且 docstring 要点出
  **安全边界**而非只写「给前端用」；并确保只有一处定义。

（用 AST 取函数**代码体**再断言，排除 docstring——那里的散文正是在解释「为什么不做什么」，
直接整段文本正则会把说明本身误判为违规。）

### 被否决的方案

| 方案 | 否决理由 |
|---|---|
| **A. 配置 `allowed_referrers`** | `is_allowed_referrer()` 命中即**跳过 CSRF 校验**，是真正放宽防护。而这不是「必须取消令牌」，是「用受控接口把本就存在的值暴露给受信任前端」，没有理由削弱安全。 |
| **C. 前端自行生成** | 不可行。token 由服务端生成并存在 session 里，前端算不出来。 |

### 前端侧（待实现）

`frappeClient.ts` 需加：非 GET 请求前调用本接口取 token 并缓存，挂到 `X-Frappe-CSRF-Token`。
**将在入库页进入复刻阶段时一并接入**，现在不加——没有消费者的代码是投机。

## 10. 可访问性

- 可点区域 ≥42px（输入框/按钮 42、导航项 42、页头图标 44）；
- `:focus-visible` 2px 描边；
- 状态语义**色 + 文字并存**：可疑字段是「橙框 + 文字说明」，服务状态是「色 + 文案 + 后端标签」；
