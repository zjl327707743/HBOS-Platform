考勤全面板导航方案

门户里的考勤现在只有 3 个入口（仪表盘 / 人员管理 / 部门看板）。考勤在 Desk 侧实际有 14 个可达面——4 张报表、4 个列表、3 个操作页、3 个概览——其余 11 个在门户里一个都点不到。 本原型回答两件事：14 个入口怎么分组，以及 iframe 内嵌的观感选哪种。

本方案推翻两处既有决定，请确认。① 2026-10-02 你选的是「班次管理 / 导入 / 月度上传暂不搬进门户」——本方案把它们全搬进来； ② 当时定的是「纯页签、不内嵌」。现在改成 分组左侧栏 + iframe 内嵌。两处旧记录我会一并更正。

一 · 分组左侧栏（14 个入口）

页签放不下 14 项，改成分组侧栏，四组：概览 / 报表 / 数据与导入 / 配置。 分组依据是「用户来干什么」——看整体、看数据、搬数据、改规则。命名与后台既有的「海滨考勤工作台」侧栏保持一致，不另造一套叫法。

二 · 内嵌观感：外壳剥离

11 个后台面按项目规范（FRONTEND_IMPLEMENTATION_GUIDE.md §1.2「不得将 Frappe Desk 后台页面强行重做成独立前端」） 不重写，而是同域 iframe 内嵌。问题随之而来：直接嵌入会把 Desk 的顶栏和左侧栏一起带进来，出现「两层导航」。 左为剥离后、右为原样。

两层导航、页面变窄

  • 剥离靠注入一段 CSS 隐藏 Desk 的顶栏 / 左侧栏 / 页头，并强制内容满宽。同域所以可注入。
  • 失败即降级：取不到 iframe 文档或选择器变了，就什么都不做——最坏退化成右边那种观感，功能不受影响。
  • 代价写在明处：依赖 Desk 的 DOM 结构，Frappe 升级时可能要跟着调一次。

三 · 内嵌方案的已知代价

这几条是 iframe 方案的固有代价，改不掉，写在这里以免以后当缺陷报。若不接受其中任何一条，就得改成原生重写（工作量大一个量级）。

  • 浏览器后退 / 刷新不同步：在报表里点了钻取，门户地址栏不变，后退会退回上一个门户页而不是报表上一步。
  • Cmd+K 命令面板在报表里按不出来：焦点在 iframe 内，快捷键绑在门户窗口上。
  • 报表打印会跳出：Frappe 的打印走新窗口，会离开门户（这是浏览器行为，拦不住）。
  • 仅真实数据模式可用：mock 模式（前端独立预览）下这些列表是空的，因为 mock 没有后端路由。

待你确认的三点

  • 分组是否合理：「概览 / 报表 / 数据与导入 / 配置」四组，14 项归属如上图。
  • 内嵌观感：选 A（隐藏 Desk 外壳）还是 B（原样）？A 更好看但依赖 DOM，B 更稳但套娃。
  • 是否接受第三部分的四项代价。接受则本轮全部做完；不接受就只做报表那一组（4 项），其余留待原生重写。
