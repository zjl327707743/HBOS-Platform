### 事务 DocType（5 个 = 4 主 + 1 子表）

| DocType | 命名 | 关键设计 |
| --- | --- | --- |
| HBOS Sample（样品登记/请验单） | `HBOS-SMP-.YYYY.-#####` | 样品类型/物料/批号/来源/质量标准（仅已生效可引用）/版本快照/优先级/状态（草稿→已登记→检验中→检验完成→已放行/已拒绝/OOS锁定）；登记后关键字段锁定（validate）；待检项目快照子表 |
| HBOS Sample Item（子表，istable） | `hash` | 从规格复制的项目快照（含限度，标准变更不追溯）；task 链接回填 |
| HBOS Sample Task（检验任务） | `HBOS-TSK-.YYYY.-#####` | 样品/检验项目/检验组/检验员/分配人/应完成日期/状态（待分配→已分配→检验中→已提交→已复核→已批准/OOS候选→OOS锁定） |
| HBOS Test Result（检测记录） | `HBOS-TR-.YYYY.-#####` | 限度冻结（read_only）/结果值/原始值/公式输入/记录型结果/判定（合格/不合格/OOS候选/不适用/无法判定）/记录状态（草稿→已提交→已复核→已批准→已修订）/检验人/复核人/批准人签名+时间/superseded_by 链/仪器预留；提交后结果字段锁定（validate，基于提交前状态判断） |
| HBOS Result Revision（修订记录） | `HBOS-REV-.YYYY.-#####` | 结果/变更字段/修改前值/修改后值/修改人/时间/修改原因（全部必填，ALCOA） |

### 状态机 `workflow_contract.py`（纯逻辑，零 Frappe 依赖）

- `can_transition(flow, current, target)`：三张状态转移表（OOS 路径：任务 检验中/已提交/已复核 → OOS候选 → OOS锁定；样品 已登记/检验中 → OOS锁定）。
- `action_allowed(action, actor_role)`：动作角色矩阵（submit=Analyst/Manager；review/approve=Reviewer/Manager；revise/assign=Manager；release=Reviewer/Manager）。
- `is_final_state`：终态判定。

### 业务服务 `lims_service.py`（Frappe 层，whitelist + only_for 角色校验 + 显式事务）

- `register_sample`：校验规格已生效，从规格复制项目快照，草稿→已登记。
- `generate_tasks`：按样品项目生成任务（Manager），回填 item.task。
- `assign_task`：待分配→已分配（Manager）。
- `start_task`：已分配→检验中（本人/Manager），**自动创建检测记录（限度冻结）**；样品同步 已登记→检验中。
- `submit_result`：公式计算（含量% 等）→ 自动判定（judge_result）→ 合格/不合格写入 + OOS 候选置位 → 检验人电子签名 → 任务联动（不合格→OOS候选 + 样品 OOS锁定）。
- `review_result`：已提交→已复核 + 复核人签名（复核人不可改值，validate 强制）。
- `approve_result`：已复核→已批准 + 批准人签名；OOS 候选禁止批准；任务完成；样品全部任务批准后 检验中→检验完成。
- `revise_result`：仅 Manager；写 Revision 记录（原因必填）+ 生成新版本结果（superseded 链）→ 原记录已修订 → 任务回到已提交待重新复核。
- `release_sample` / `reject_sample`：放行（OOS 锁定禁止）/ 拒绝。

### 报表：待检任务看板（Script Report，中文）

列：任务号/样品/物料/批号/检验项目/检验组/检验员/优先级/分配时间/应完成日期/状态/超时；筛选：检验组/状态/检验员/优先级；SQL 参数化；超时标记（应完成日期已过且未批准）。

### 排障记录（重要，均已修复并固化）

1. **子表缺 `istable: 1`**：HBOS Specification Item / HBOS Sample Item 初版 JSON 缺 `istable: 1`，frappe 按普通表建表（无 parent/parentfield/parenttype 列），加载子表报 `Unknown column 'parent'`。已补 `istable: 1` 并手工 ALTER 加列（migrate 不自动补系统列），重建 TEST 规格 items。
2. **Result 提交被自身锁定拦截**：validate 锁定检查把"草稿→已提交的提交动作"误判为"提交后修改"。修正为基于**提交前状态**（before.result_status 为草稿时放行）。
3. **PYTHONPATH 覆盖问题**：容器 compose PYTHONPATH 以 app 目录为入口（`apps/hrms` 等），命令行覆盖为 `apps` 根会导致 hrms 被解析成 namespace package（`hrms.__file__ = None`）。执行脚本须保留完整 PYTHONPATH（`apps/hrms:apps/hb_attendance_app:apps/hb_lims_app:apps`）。
4. **状态机补路径**：任务 OOS 触发时处于"检验中"，状态表补 `检验中 → OOS候选`；样品 OOS 触发路径补 `已登记/检验中 → OOS锁定`。
5. **frappe.get_roles 返回 list**：`_check_action` 改为逐角色判断 `any(action_allowed(...))`。
6. **修订自转移**：任务已处于"已提交"时修订不再重复置状态（非法自转移）。
