## 3. 完整规则匹配在总数与分页之前

## 4. 原生 GET 回滚后与数据释放前的最新核验

首次读取期间已两次重新加载来源 / 当前政策和新时点，避免服务执行过程中变化。返回单次 immutable PendingManagementQueryProof，冻结原参数、结果 JSON、来源 / 政策 / 获准事实 / 姓名摘要；仅私有绑定原 service、实际 native.local.db、实际 local.session / SID / actor、Site / 数据库及来源代次。copy、跨服务 / 连接 / 会话、重复 proof 或第二次 pending 都拒绝。

Frappe 原生 GET 的 sync_database 完整 rollback 在 ClosingIterator 返回前发生，不能拿此前锁定快照当作最后证明。包装缓存响应，在原生 GET 回滚后仍绑定同一实际 DB / 会话时重新获得根锁能力，以原参数、当前政策头、锁定来源 / 事实 / 姓名与新 UTC 时间重算完整查询；结果或来源 / 政策 / 获准事实变化时扣留旧 body，返回稳定冲突 / 不可用错误。核验后再次完整 rollback，查询不提交关系事实。

原生 after_response 精确 Session.update 的一次维护提交仍受前段已核验队列 ABI、同 DB / session_obj / session / SID / actor、零既有写和空 commit 回调约束。GET 的其他或提前 / 重复 commit 全部拒绝。内部 phase="committed" 只为复用该原生维护协议，facts_committed 始终 false；查询故障不报事实 SAVE_RESULT_UNKNOWN。

只证明最后锁定读取时点的当前许可和数据一致性，不承诺数据库锁释放到网络送达之间所有状态永不变化。仍采用全来源 / 候选范围锁和内存过滤，成本随数据量增加，生产性能 / 完整入口组合尚未放行。

审查复现资源缺陷：原生 ClosingIterator 已 close 数据库 / destroy 解绑后再抛异常，abort 对旧实际 DB rollback 可能 lazy reconnect，随后无 local.db 可关闭。修复为发现实际 DB 已解绑 / 替换时直接关闭及 poison，不回滚重连；原生维护 SQL 失败也进入终态。正式回归验证 0 次重连、连接保持关闭、缓存数据不释放、方法 / ContextVar 恢复。错误和日志失败继续拒绝，仅记录 code / trace，不输出原异常或人员内容。
