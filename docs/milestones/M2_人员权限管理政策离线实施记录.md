## 2. 判定与信任边界

`parse_management_policy` 接收固定结构，Site / source_provider 由注入方独立传入；`parse_management_context` 的 Site、policy_provider_id、actor_user、actor_enabled 同样是独立注入参数，不在事实 payload 中接受 actor、approved、policy_ref、ignore_permissions、SQL 或任意处理函数。注入方式便于后续服务端构造，**本段不能证明注入来源、真实会话、原生对象存在或批准真实性**。

DTO 内嵌集合复制并规范化为 tuple，时间复用显式时区、微秒精度的 UTC 编解码规则。未知 / 多余字段、布尔版本、未知操作 / schema、重复规则 / 引用、空范围、通配符、下级范围、跨公司例外和缺少必要人员范围拒绝。SQL 样式 ID 仍只是字面引用，不被解释成查询条件；真实存在性由后续来源适配验证。

`evaluate_management_policy(..., enabled=False)` 默认返回不匹配，不访问输入依赖。显式开启后，仍重新校验直接构造的 DTO，不信任被绕过解析器的字段。actor 必须启用；一条规则内操作、公司、目标部门、人员范围和任职截止上限完整取 AND，完整规则间取 OR。不同政策 / 规则的操作、范围、期限不能混合。

政策必须 active、在半开有效区间内、有非本人 / 非 Guest 的批准声明，且批准时间不在未来、批准 revision / generation 和规范内容摘要一致。固定摘要绑定 Site、provider、policy_id、subject、revision、authority_generation、schema、时间及全部规则；排除可变 status 和 approval 自身，避免循环摘要。恢复 / 版本升级须由未来受控写服务维护 generation 和新批准，本段仅验证输入声明的一致性，没有实现政策生命周期写入。

同一政策出现多个头版本一律拒绝，避免将已撤销头和旧 active 版本同时提供后择旧放行。若注入方只提供旧快照，本段无法知道真实数据库已改变；后续必须锁定加载当前头，不能将此纯函数当成新鲜度证明。

初始本人事实维护仅允许有完整管理政策覆盖的严格收窄；新增、恢复、延期以及混合改动拒绝，不据未知关联推定“非本人”。任职增加要求已声明的唯一关联、启用 User、Employee.status=Active、有限截止且不超本条规则上限。这只核对当前事实声明，不解决 Employee Date 资格，也不生成业务权限。

严格收窄要求稳定记录 / 岗位 / 人员 / 旧受益 User / 开始时间 / 主岗标记保持，版本正确，状态只向停用 / 撤销变化，截止不延长。把恢复与缩短混合、或停用与延长混合，均不能冒充收窄。已声明当前组织仍 active 时，可以匹配离职 / 换绑人员原关系的受控结束，旧受益 User 不转移；原生数据库路径尚未接入。

组织未知拒绝 SOURCE_UNAVAILABLE；停用组织即使请求收窄也拒绝 HISTORICAL_SCOPE_REQUIRED，因为现有上下文没有可靠历史归属证据。未伪造历史范围，不把 MG20 整项记为通过。

匹配结果仅为 `OfflineManagementEvaluation(matched=...)`，始终 validation_only=true、runtime_verified=false、authorization_effect=none，包含当前上下文摘要 / 检查时间和完整政策 / 规则证据。它不是现有 RelationService 的 ManagementDecision，不能直接作为真实管理回调返回值；没有 bridge、真实许可或授权落库。
