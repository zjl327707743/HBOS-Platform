## 侧边导航模块化下拉改造（审查期间增强，随 R5 一并收口）

### 需求

海滨LIMS工作台的各部分功能在侧边导航栏中体现，按业务模块以下拉（折叠）形式分组。

### 实现（Frappe v16 原生 Workspace Sidebar 能力，零自定义 JS）

侧边导航 `海滨LIMS` / `海滨LIMS工作台` 由 `PRIMARY_SIDEBAR_ITEMS` 重构为 **5 个模块分组**，与工作台四卡片分区一一对应：

| 模块分组（Section Break） | 子项（child=1 缩进） |
| --- | --- |
| 样品管理（默认展开） | 新建样品登记 / 样品台账 / 样品类型 |
| 检验流程（默认收起） | 待检任务看板 / 检验任务 / 检验结果清单 / 检测记录 |
| 报告管理（默认收起） | 新建检验报告书 / COA 发布记录 |
| 质量主数据（默认收起） | 质量标准 / 检验项目 / 计算公式 / 检验组 |
| 审计追踪（默认收起） | 审计追踪查询 / 结果修订记录 |

分组渲染机制（源码确认于容器内 frappe 16.26.3）：`Workspace Sidebar Item.type = "Section Break"` 构成分组（`collapsible=1` 下拉箭头、`keep_closed=1` 默认收起、`child=1` 子项缩进、展开状态 localStorage 记忆）；与官方 `frappe/workspace_sidebar/system.json` fixture 结构一致。契约测试 `test_sidebar_grouped_by_module` 固化 5 分组 + 关键子项 + 顺序断言。

### 排障：Frappe v16.26.3 侧边栏 DocType 项过滤核心 bug（已 workaround）

验证中发现非 Administrator 用户侧边栏中 **DocType 项全部不可见**（仅报表项可见）。逐步定位（源码级）：

1. `frappe.boot.get_sidebar_items` 对侧边栏每项调用 `is_item_allowed()`；DocType 项判定为 `name in can_read AND name in restricted_doctypes AND has_permission`。
2. 逐条件调试确认 `can_read` 含 HBOS Sample、`restricted_doctypes`（978 项）含 HBOS Sample、`has_permission` True —— 三条件均成立仍被过滤。
3. 根因：`workspace_sidebar.py` 的 `get_can_read_items()` **缺少 `return`**（只调用 `build_permissions()` 不返回结果），`get_cached("user_perm_can_read", ...)` 的 fallback 恒返回 None → `can_read = None` → DocType 项判定恒 False。官方侧边栏（HR 等）只放 Dashboard/Report/Page 项，未触发该路径，故官方未暴露。
4. 修复方式（不修改 Frappe 核心源码，符合硬约束）：hb_lims_app 注册 **`boot_session` hook**（`setup.sync_user_perm_can_read_cache`），每次会话 boot 时按用户预置 `user_perm_can_read` 缓存（与 frappe 原生同 key、6 小时过期、值由 Frappe 权限系统计算，不改权限语义；frappe 升级修复后此预置无副作用）。契约测试 `test_boot_session_sidebar_cache_workaround` 固化。

## 报表表格列宽拖拽修复（审查期间增强，随 R5 一并收口）

### 需求

部分页面表格无法拖动列宽，列宽不足时不能展示全部信息（内容被 ellipsis 截断）。

### 排障（根因）

1. **Query Report 表格（报表 DataTable）**：frappe-datatable 原生支持列宽拖拽（表头 `.dt-cell__resize-handle` mousedown 拖拽，最小宽度 30px）与双击手柄自适应列宽（`bindPerfectColumnWidth`），但编译后 CSS 中 handle 为 `opacity: 0` 且**无任何 hover 显示规则**（源码 style.css 与 dist CSS 均确认）→ 手柄永不可见 → 无法拖拽。
2. **列表视图（List View，DocType 列表页）**：`list_view.js` 的 `apply_column_widths()` 仅按内容长度自动计算列宽（`column_max_widths`，inline `width` + `flex: 1 0 Xpx`），**无任何拖拽交互代码**，Frappe v16 原生不支持。列表视图列 div 类名含 fieldname（`.list-row-col.{fieldname}`），表头（`.list-row-head`）与全部行共用该结构，为自定义拖拽提供可行基础。

### 修复（hb_lims_app 静态资源层，不改核心源码）

- `public/css/lims_report.css` 追加：hover 表头单元格时显示拖拽手柄（`opacity: 1 !important`，含手柄自身 hover），手柄命中区加宽（9px、right: -4px）+ `cursor: col-resize` → 恢复 datatable 原生拖拽与双击自适应；并追加列表视图手柄 hover 显示样式（`.list-view .list-row-head` 内 `.list-col-resize-handle`）。
- 新增 `public/js/lims_report.js`：报表表格单元格 hover 时注入原生 title 全文提示（fixed 布局下未拖宽也能看全内容）。
- 新增 `public/js/lims_list_resize.js`（列表视图列宽拖拽，**限定 HBOS LIMS 模块 DocType 列表页**，不影响考勤等其他列表页）：monkey-patch `ListView.prototype.apply_column_widths`——原生自动算宽后恢复 localStorage 持久化列宽并幂等注入表头拖拽手柄；拖拽实时同步表头与全部行对应列（沿用原生 fieldname 选择器），**列宽持久化到 localStorage**（按 DocType+字段，刷新/重新查询后保留），双击手柄清除该列持久化宽度并复用原生自动算宽复位。因 list.bundle.js 为路由懒加载，脚本轮询等待 `frappe.views.ListView` 定义后 patch 一次。
- 新增 `public/js/lims_grid_resize.js`（**表单子表网格列宽拖拽**，限定 HBOS LIMS 模块 DocType 表单页，不影响考勤等其他表单）：Frappe v16 子表网格列宽由 Bootstrap `col-xs-N` 栅格类固定、无拖拽交互；脚本 monkey-patch `ControlTable.prototype.make`——创建 grid 实例后 wrap 其 `refresh`，每次 grid 重绘后恢复 localStorage 持久化列宽并注入表头拖拽手柄；**同时用 MutationObserver 兜底补扫**整页加载与 controls.bundle 懒加载竞态下已构建的子表控件。拖拽实时同步表头与全部数据行对应列（`data-fieldname` 选择器），**列宽持久化到 localStorage**（按 父DocType+子表字段，刷新/重新加载文档后保留），双击手柄清除该列持久化宽度并恢复 `col-xs-N` 自动栅格。
- `hooks.py` 注册 `app_include_js`（三条：lims_report.js + lims_list_resize.js + lims_grid_resize.js；`app_include_css` 已有）；契约测试新增 `test_report_column_resize_assets` / `test_list_column_resize_assets` / `test_grid_column_resize_assets` 固化 hooks 注册与 CSS/JS 关键规则。

- **结果修订记录列表行高异常修复**（用户反馈：编号与变更字段之间出现一条独立 `HBOS-TR-2026-` 且行高异常）。排障：Frappe 原生规则 `.layout-main-section .frappe-list .result { min-height: 200px }` 本意给列表结果容器 `.result` 保底高度，但**字段名恰为 `result` 的 Link 列（`.list-row-col.result`，即"结果记录"列）也匹配该选择器**，被撑高到 200px，导致整行 211px、列错位（"结果记录"列内容呈现在编号与"变更字段"之间）。修复：LIMS 列表视图全部数据行列重置 `min-height: auto; height: auto`（通用修复，避免任何字段名与 Frappe 容器类 `result/freeze/no-result` 冲突时被原生规则误撑高）。实测：`result` 列 200px→24px、行高 211px→41px，列位置连续无错位，其他 LIMS 列表行高正常，考勤等非 LIMS 页面不受影响。**浏览器缓存兜底**：`app_include_css/js` 资产 URL 原无版本号，浏览器磁盘缓存旧版 CSS 致修复不生效（`fromDiskCache: true`），hooks 资产 URL 加 `?v=2` 版本参数强制刷新，用户重新登录/刷新后加载最新样式。

## 列表视图表头/数据错位修复（审查期间修复，随 R5 一并收口）

### 需求与现象

Owner 验收反馈：结果修订记录（HBOS Result Revision）等 LIMS 列表页**表头与数据行错位**。

### 排障（根因）

文字居中增强后，列表视图 **Subject 列（第一列，含全选框）表头与数据行渲染规则不一致**：

| 位置 | 容器 | 规则 | 效果 |
| --- | --- | --- | --- |
