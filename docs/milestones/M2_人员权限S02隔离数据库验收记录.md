| 阶段 | 行为与限制 |
| --- | --- |

## 3. 实际验收结果

六类表均为 InnoDB，name / record_key 有物理唯一约束；岗位 / 任职的 source_key 也唯一，所有 `_utc` 时间字段为 Datetime(6)。六类元数据的 permissions 均为空、禁止导入和更名。

| 实际场景 | 结果 |
| --- | --- |
| 岗位修订、同键重放、过期 expected_revision | PASS；重放同一 ID，历史追加，旧版本拒绝 |
| 任职 UTC 微秒往返及主岗重叠 | PASS；+08:00 精确转为 UTC，保留 123456 微秒，重叠拒绝 |
| 收据写入后注入异常 | PASS；主记录、修订和收据全部回滚到保存点 |
| ignore_validate / ignore_permissions、普通 save / db_update / db_set / 删除 / 更名 | PASS；实际 ORM 路径拒绝，原岗位未改 |
| 不可变历史保存 | PASS；不能覆写历史修订 |
| 直接 SQL 制造重复 record_key | PASS；数据库唯一约束拒绝，证明物理约束实际存在 |
| 两连接同时用同键创建岗位 | PASS；一条主记录 / 修订 / 收据，另一请求重放 |
| 两连接为同一员工创建重叠主岗 | PASS；一条成功，另一 OVERLAPPING_PRIMARY |
| 两连接从同一旧修订更新岗位 | PASS；一条成功，另一 REVISION_CONFLICT，最终修订为 2 |

结果为 **6 项实际事务 / ORM 测试 + 3 项独立连接并发验证 PASS**，并完成 **121 / 121 离线测试 PASS（新验收工具保护 4 + 前序回归 117）**。最后只读复核 Preview 六表全空、原生计数恢复；5178 原站六表仍不存在，原生数量与前序核验一致。没有重跑无变化的前端测试。

当前证明的是该版本、该空 Preview、这些合成路径中的关系存储行为。普通角色矩阵、实际 HTTP REST / 导入、真实员工账号关联生命周期、原生关联写入 / 幻行竞态、管理政策的同步撤销、Grant 和业务提交共同事务尚未验证。REPEATABLE-READ 下可信来源重读必须专门核对，不能把三项受控命令并发 PASS 当作所有原生写入已闭环。
