## 交付内容

### 主数据 DocType（6 个，英文 name + 中文 label + 三角色权限 + track_changes）

| DocType | 命名 | 关键字段 |
| --- | --- | --- |
| HBOS Sample Type（样品类型） | `field:sample_type_code` | 类型编码 / 类型名称（原料/中间体/成品/包装材料/工艺用水/环境/稳定性/清洁验证）/ 默认留样天数（预留） |
| HBOS Lab Department（检验组） | `field:department_code` | 组编码 / 检验组名称（理化/仪器/微生物）/ 组长 |
| HBOS Test Item（检验项目） | `field:item_code` | 项目编码 / 名称 / 类别（理化/仪器/微生物/记录型）/ 方法SOP号 / 单位 / 有效位数 / 公式链接 / 默认限度模式 |
| HBOS Calculation（计算公式） | `field:calc_code` | 公式编码 / 名称 / 类型（含量%内置模板/自定义表达式）/ 表达式模板 |
| HBOS Specification（质量标准） | `format:{spec_code}-V{version}` | 规格ID / 名称 / 物料编码+名称 / 版本号 / 生效日期 / 状态（草稿/已生效/已废止）/ 标准依据 / 检验项目明细 |
| HBOS Specification Item（子表） | `hash` | 检验项目（Link，fetch 名称/SOP/单位/有效位数）/ 限度模式 / 限度上下限 / 备注 |

### 判定引擎 `result_contract.py`（零 Frappe 依赖）

- `judge_result(value, limits_type, lower, upper)`：上限/下限/区间/记录型四模式；记录型→不适用；空值→无法判定；越限→不合格（=OOS 候选，由调用方置位锁定）。
- `round_significant(value, digits)`：四舍六入五成双（ROUND_HALF_EVEN，药典修约）。
- `apply_formula(raw_params, formula_type)`：含量% = A样×C对×D稀释/(A对×W样)×100；缺参/除零→FormulaError。
- `verdict_to_label(verdict)`：合格/不合格/OOS候选/不适用/无法判定 中文映射。

### 规格生效校验（hbos_specification.py）

- `validate`：同规格 ID + 同版本号禁止重复（版本控制=复制新版本人工流程）；限度一致性（区间必须上下限齐全且下限≤上限、上限/下限模式必须填对应限度）。
- `is_spec_active(spec_name)` / `get_active_specifications()`：仅已生效规格可被样品引用（R3 的 Sample validate 使用）。

### 测试（40/40 全绿）

- `tests/test_result_contract.py`（24 用例）：判定边界（区间含上下限临界值）、上限/下限/记录型/空值、修约（0.125→0.12、0.135→0.14、1.245→1.24、1.235→1.24）、含量%公式（正常/除零/缺参）、中文映射。
- `tests/test_doctype_contract.py`（16 用例）：6 个 DocType JSON 的命名/autoname/track_changes/三角色权限（Analyst/Reviewer 只读）/中文 label/fetch_from/规格校验函数存在性。

### 设计修正（重要）

初版规格 `autoname=field:spec_code` 导致 **同规格 ID 无法创建多版本**（主键冲突），违反"版本控制"需求。已修正为 `autoname=format:{spec_code}-V{version}`（规格 ID + 版本号组合命名），版本号入名称天然支持多版本；`spec_code` 去掉唯一约束，由 validate 兜底防重。
