## 二、出库放行门禁（核心）

### 2.1 业务规则

**出库须有 QA 出具的放行手续与合格证，缺任一项不可出库。**（Owner 明确）

### 2.2 实现方式

新增 `hb_inventory_app/hbos_inventory/release_gate.py`，通过 `hooks.py` 的 `doc_events` 挂在**出库单据的 `before_submit`**。

选择 `before_submit` 而非 `validate` 的原因：草稿仍可自由保存与修改，仅在**提交**时拦截，不阻断备货过程。

### 2.3 判定范围（有意收窄）

| 单据 | 是否门禁 | 理由 |
| --- | --- | --- |
| `Delivery Note`（非退货） | **门禁** | 销售发货路径，属真正出库 |
| `Stock Entry` 且 `purpose = Material Issue` | **门禁** | 非销售领用 / 出库路径 |
| `Stock Entry`（Material Receipt） | 不门禁 | 待检物料本就该能入库 |
| `Stock Entry`（Material Transfer） | 不门禁 | 库内 / 货位间流转，含移入不合格品库 |
| `Delivery Note`（is_return） | 不门禁 | 退货是入库方向 |

### 2.4 批次取法

优先取明细行 `batch_no`；取不到则回落到 `serial_and_batch_bundle` 查 `tabSerial and Batch Entry`。

依据 M3-R1 实测结论：ERPNext v16 中 `Stock Ledger Entry.batch_no` 为空列，批次数据实际在 `Serial and Batch Bundle` / `Serial and Batch Entry`（详见 M3-R1 主文档第四节）。

### 2.5 校验逻辑

对涉及的每个批次读取 `Batch.hbos_release_status` 与 `Batch.hbos_certificate_no`：

- 状态须为 **`已放行`**；
- 合格证编号须**非空**。

任一不满足即中止提交，并给出明确提示，例如：

> 以下批次未取得 QA 放行手续或合格证，不可出库：
> `TEST-M3R1-B002`（放行状态为「待检」、无合格证编号）
> 请先在批次上录入放行状态（已放行）、放行日期与合格证编号后再提交。

### 2.6 验证结果（通过）

| 场景 | 预期 | 实测 |
| --- | --- | --- |
| 待检批次出库核销 | 拦截 | **已拦截**，提示准确 |
| 已放行批次出库核销 | 通过 | 通过（`MAT-STE-2026-00005`） |
| 待检批次内部移库 | 不拦 | 通过（未触门禁） |
| 待检批次入库 | 不拦 | 通过（未触门禁） |

## 四、效期预警报表

新增脚本报表 **`效期预警`**。

**数据源**：`Serial and Batch Entry` 关联 `Serial and Batch Bundle`（同「按批号查货位」）。

**筛选**：预警天数（默认 90）、是否含已过期、货位、物料、放行状态。

**列**：紧急度 / 剩余天数 / 有效期至 / 生产日期 / 物料代码 / 物料名称 / 批号 / 货位 / 数量 / 单位 / 效期类型 / 放行状态。

**紧急度分级**：`已过期` → `紧急（≤30 天）` → `关注（≤90 天）` → `正常`。

**效期类型**列取自 `Item.hbos_shelf_life_type`（复检期 / 有效期），对应 Owner 确认的"按产品种类区分，且分复检期与有效期两类"。

**验证**：以 `TEST-M3R1-B003`（有效期 = 今天 + 20 天）验证，报表正确返回该批次、剩余 20 天、紧急度「紧急（≤30 天）」。

## 五、库级盘点三对账报表

新增脚本报表 **`库级盘点三对账`**，对齐仓库现有纸质《物料及产品盘存记录》的口径。

**筛选**：库位 / 货位（可勾选含下级）、物料。

**列**：库位 / 物料代码 / 物料名称 / 批号 / 单位 / **ERP数量** / **货位卡数量** / **实物数量** / **差异（实物-ERP）** / 有效期至 / 放行状态。

**关键口径**：

- **按库位盘点**，不细到货位——与盘存表实际列结构一致（盘存表无货位号列）。
- **ERP数量由系统给出**（`Serial and Batch Entry` 聚合）；
- **货位卡数量与实物数量不来自系统**（分别是纸质卡记录与实盘结果），故**留空**，由现场在导出的 Excel 中填写；差异列同理。

使用流程：运行报表 → 用 Desk 报表右上角「导出」导出 Excel → 现场填写两列 → 比对差异。

**验证**：对 `3904 六车间中间库`（含下级）运行，正确返回 4 行（3 个批次分布于 3 个货位），ERP 数量正确，货位卡 / 实物列为空。

### 6.1 实现过程中踩到的两个坑（已修复，供后续复用）

1. **`Desktop Icon.link_to` / `sidebar` 必须指向已存在的 `Workspace Sidebar`**，否则抛 `LinkValidationError`。修正为指向同名工作台侧边栏。
2. **配色取值受限**：`Desktop Icon.bg_color` 仅允许 `gray` / `blue`（不是 green）；`Workspace Shortcut.color` 亦有固定枚举。初版用 `green` / `Orange` / `Grey` 导致 migrate 失败，已改为合法值。

### 6.2 ⚠ 入口缺陷更正（2026-09-23，Owner 验收发现）

本节最初交付的入口**有三个缺陷**。Owner 实际使用后报「点进去会跑到库存模块，且桌面找不到仓储库存工作台、回不来」，核查确认属实：

| # | 缺陷 | 后果 |
| --- | --- | --- |
| 1 | 顶层图标用了 **`stock`**——与 **ERPNext 原生 Stock 模块图标完全相同** | 桌面上两个一模一样的方块并排，点错即进入原生库存模块；**原生模块没有本 App 的侧边栏，用户回不来** |
| 2 | **工作台本身没有桌面条目** | 桌面按「仓储库存工作台」**搜不到任何东西** |
| 3 | 顶层条目名叫「仓储库存」而非工作台名 | 靠名字也找不到 |

**同一 App 内的对照就能看出 2 是漏做**：`hb_attendance_app` 有 `海滨考勤`（入口）与 `海滨考勤工作台`（挂在入口下）**两个**条目；本 App 只有前者。

**根因**：`hb_attendance_app` 有 `tests/test_workspace_contract.py` 把「入口必须可达」锁住，本 App **当时没建对应测试**，于是缺陷一路带到验收。另外 Frappe 在本 App 用**代码**创建 Workspace 时**不会**自动生成该图标（考勤那边是 `bench migrate` 从 workspace JSON 夹具导入时生成的），而原代码没有任何兜底。

**已修**（`workspace_setup.py`）：

1. `DESKTOP_ICON` 由 `stock` 改为 **`warehouse`**（语义贴切，与原生 Stock 一眼可分）；
2. 新增 `_sync_workspace_desktop_icon()`，为工作台建桌面条目并挂在 `仓储库存` 下（幂等）；
3. 新增 `apps/hb_inventory_app/tests/test_workspace_contract.py`（7 条静态契约），把上述三条固定住——改回去就红。

**验证**：库内实测 `仓储库存 icon='warehouse'`、`仓储库存工作台 parent='仓储库存'`；契约测试 7 条、考勤既有契约测试 16 条全通过。**未在真实浏览器验证**（需登录），建议 Owner 亲自看一眼桌面。
