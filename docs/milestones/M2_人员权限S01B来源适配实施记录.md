## 2. 来源边界与结果含义

`build_source_snapshot` 接受固定选取字段的 User、Employee、Company、Department、Designation 五类行集合，以及显式 site_id / provider_id / captured_at。拒绝缺表、重复主键、未知字段和类型错误；Frappe Check 只接收 bool 或整数 0 / 1。返回多层只读副本，调用方后续修改原输入不会影响结果；错误仅含稳定代码和固定字段路径，不回显未知键或原始人员值。

`employee_links_complete` 默认为 false，true 也只是注入方的完整性声明，**不能证明真实查询完整或可信**。所有快照、证据和 A 投影始终 validation_only=true / runtime_verified=false，coverage 仍为 provided_set_only。后续真实加载器须从服务端可信上下文证明站点、权限、来源、完整性及新鲜度，不允许从公开请求透传这些声明用于放行。

`resolve_person` 只按 Employee.name / Employee.user_id / User.name 解析。没有员工、未关联账号、悬挂账号、多员工关联和局部名单分别返回明确状态；即使存在非 Active 历史关联，也不自动取当前第一条。保留 System User / Website User 的原生事实；Guest / Administrator 不作为本适配的普通任职主体，不按原生角色推断管理权或内部员工资格。

唯一关联使用独立的 link_status=linked；qualification_status 仍为 unknown，保留账号启停、员工状态、原生 Date、组织缺口等证据与原因。当前没有确认员工 Date 资格政策，也未接入账号服务资格 / 业务批准，因此本模块**从不产生 verified 资格或 Grant**。停用账号仍可保留已知关联用于核对，不能因关联存在就恢复或允许账号。

User 与唯一 Employee 的来源别名可输出同一 canonical_person_ref；任职 DTO 仍保留其存储的 person_ref，原始 requested_ref 不被静默改写。该别名证据为后续全库任职冲突检查提供依据，本次没有实现跨别名的数据库唯一性或并发锁，不能借用 A 的局部集合检查宣称全库无重叠。

## 3. 组织、关系与时间映射

岗位映射要求公司、部门及可选岗位类别均存在；核对部门父链，拒绝停用祖先、悬挂、循环和跨公司关系。无公司分组根可以连接组织树，不能自身成为业务岗位。相同岗位标题保留不同稳定 ID 和部门引用；Company / Designation 没有本次实测的通用 disabled 字段，不编造启停值。

PositionProjection 沿用 A 原字段；公司、岗位类别、authorization_generation 与来源指纹由独立 PositionSourceEvidence 携带，未私自扩大旧协议。任职映射重新解析人员，不接受存储 subject_user 覆盖来源结果；拒绝跨公司及缺失岗位，兼任允许同公司不同部门且不修改 Employee.department。关系修订 / 代次必须显式为正整数，modified 保留不透明字符串，不转换为授权版本。

岗位证据绑定生成它的同一个不可变快照对象，不能与另一快照混用。指纹保留所检查的 User / Employee 及相应公司、部门父链、岗位类别等来源依赖；它们不是签名、真实新鲜度证明或持久化授权依据。来源缺失 / 不一致仍须在运行适配中重新核实。

API 时间解析限定带已知偏移的 RFC 3339，规范化为 aware UTC，拒绝无时区、非法偏移、未知偏移 -00:00 及超过微秒的精度。原生 Employee Date 保持 date，不暗补午夜资格规则。encode / decode 只用于拟议 `_utc` 新字段的明确约定，不能套用到原生 Site Datetime；已验证纯 Python 往返与半开区间，Frappe / MariaDB 实际序列化尚未验证。null 结束不表示长期授权已获批。
