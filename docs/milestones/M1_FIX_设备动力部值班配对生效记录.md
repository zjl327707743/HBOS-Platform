# 设备动力部 24 小时值班配对——生效记录

项目名称：新乡海滨智能运营管理平台。

分支：`feature/hbos-portal-workbench`。

状态：**已生效**（2026-10-09，Owner 授权）。

## 一、背景

设备动力部有 **24 小时值班**：早 08:00 上班、次日早 08:00 前后下班，间隔约 23.4–25.2h，被统一 18h 配对上限挡在配对之外 → 上班卡与下班卡各自落孤立 → **两天各判一次缺勤**（康东阁 9/25、郭建伟 9/24 一类）。

修复代码原在独立分支 `m1-fix-pairing-long-duty`（为保住门户分支「判定核心零改动」的约束而分开放置），2026-10-09 合入本分支并推生效。

## 二、口径确认（Owner 2026-10-09）

| 参数 | 值 |
|---|---|
| 适用部门 | 仅 `设备动力部` |
| 上班卡窗口 | **7:00–9:00**（半开） |
| 次日下班卡窗口 | **7:00–10:00**（半开，**最晚 10 点**） |
| 间隔上限 | **26h** |

**关于上限为什么是 26 而不是 28**：实测 26–28h 之间有 5 条记录，但**没有一条落在「最晚 10 点」窗口内**（分别结束在 10:54 / 12:01 / 12:03 / 12:06 / 20:01）。窗口内理论最大间隔 26.98h、实测最大仅 **25.15h**，故 26h 已宽于窗口所能产生的上限——**抬到 28 是空操作**，只会让参数与口径描述对不上。

## 三、为什么必须有「形状守卫」

实测对比（8/15–10/8 真实数据，664 人 / 50814 条打卡）：

| 口径 | Absent→Present | Present→无记录（误伤） |
|---|---|---|
| 无守卫，直接放宽到 26h | 162 | **3** |
| **有形状守卫（本次采用）** | 162 | **0** |

无守卫时，「某天误刷的上班卡 + 次日下班卡」会被配成假 24h 班，**把次日那张卡偷走**，当天正常班消失。实测命中 3 条：宋磊 9/5、王廷炜 8/19、赵龙 8/18。

两者收益相同，差别是纯粹的风险。

## 四、执行步骤（三步都动运行态）

1. **合入代码**（`5b23628`）：cherry-pick `m1-fix-pairing-long-duty` 的代码改动（`pairing.py` / `api.py` / 测试 / 工具），**不取**那批台账文档（含本分支没有的内容）。
2. **重启承载判定的容器**：`backend` / `scheduler` / `queue-long` / `queue-short`。
   **scheduler 必须重启**——它每 10 分钟跑一次 `sync_delicloud_checkin → regenerate_attendance`，不重启会在十分钟内用旧代码把结果覆盖回去。
3. **重算**：**单次调用**覆盖 `2026-08-15 → 2026-10-08`。

### 为什么必须「单次、且 range_end 取数据最大日期」

`regenerate_attendance` 的清理含**两条 DELETE**：

```sql
DELETE ... WHERE name LIKE 'HBOS-ATT-%' AND attendance_date BETWEEN range_start AND range_end
DELETE ... WHERE name LIKE 'HBOS-ATT-%' AND attendance_date > range_end
```

第二条会**删掉 range_end 之后的全部记录**——2026-09-24 的窄窗口乱序重算事故就是这么发生的（一度删除 8/15–9/21 全部记录）。

**取 range_end = 数据最大日期（10/08）时，第二条 DELETE 删不到任何东西**，危险自动消解；单次调用则不存在顺序问题。

## 五、重算前的保险

## 九、过程中的两次自我纠错（留档）

1. **第一次隔离实验无效**：我用 `git stash push <两个文件>` 想退回修复前代码，但修复**已提交**、工作区干净，stash 是**空操作**——两次重算跑的都是新代码，差异为 0。发现后改用 `git checkout <修复前的提交> -- <文件>` 才拿到真实的对照。
2. **一度误把「重算漂移」当成本次修复的副作用**：在无效实验下看到的 `Present→无记录 34 条` 实为**重算本身的漂移**（且其中 30 条属人事行政部，与设备动力部无关）。修正实验后确认为 0。
