## 三、粒度验证结果（虚构 TEST 数据）

### 3.1 验证设计

用 `TEST-M3R1-` 前缀虚构数据，构造三个场景：

| 场景 | 操作 | 验证目的 |
| --- | --- | --- |
| 1 | 批次 B001 收货 100 kg → `16-03-221`；批次 B002 收货 50 kg → `16-03-222` | 两批次分属不同货位 |
| 2 | 批次 B001 从 `16-03-221` 移库 40 kg → `16-03-223` | **同一批次散放多个货位** |
| 3 | 按批号反查货位、按货位反查批号 | 两个方向的核心查询 |

### 3.2 验证结论（通过）

**按批号 → 货位 → 数量**（核心需求，验证通过）：

| 批号 | 货位 | 数量(kg) |
| --- | --- | --- |
| `TEST-M3R1-B001` | `16-03-221` | 60.0 |
| `TEST-M3R1-B001` | `16-03-223` | 40.0 |
| `TEST-M3R1-B002` | `16-03-222` | 50.0 |

**货位 → 全部批号**（货位明细表，验证通过）：

| 货位 | 批号 | 数量(kg) |
| --- | --- | --- |
| `16-03-221` | `TEST-M3R1-B001` | 60.0 |
| `16-03-222` | `TEST-M3R1-B002` | 50.0 |
| `16-03-223` | `TEST-M3R1-B001` | 40.0 |

- "同一批次散放多货位"成立（B001 同时在两个货位）。
- "同一货位可存多批次"数据模型上成立（本次样本每个货位恰好一批，结构支持多批）。
- 移库后数量正确（100 − 40 = 60）。
- `Bin` 行数为 3，粒度是**物料 × 货位**，`Bin` 表**确实没有批次字段**（验证 `has_batch_field: False`），与 M3-R0 的判断一致。

## 四、重要更正：批次不在 `Stock Ledger Entry`，而在 `Serial and Batch Bundle`

**这是本轮最重要的发现，修正了 M3-R0 的一处关键结论。**

### 4.1 原结论（M3-R0 §2.7，已作废）

M3-R0 依据表结构判断："`tabStock Ledger Entry` 同时含 `warehouse` 与 `batch_no`"，因此"批次 × 货位 → 数量"应聚合 `Stock Ledger Entry`。

### 4.2 实测结果

实际写入后查询 `Stock Ledger Entry`：

```
SLE 行 4 条，batch_no 全部为 NULL
另有 serial_and_batch_bundle 字段，指向 Serial and Batch Bundle
```

即 ERPNext v16 的 `SLE.batch_no` 是**遗留空列**，实际不再写入。批次数据存放在：

- `tabSerial and Batch Bundle`（单据级，含 `docstatus`、`is_cancelled`、`voucher_type`、`item_code`）
- `tabSerial and Batch Entry`（子表，含 `batch_no`、`warehouse`、`qty`、`is_outward`、`is_cancelled`）

`Stock Ledger Entry.serial_and_batch_bundle` 关联到 bundle。

### 4.3 正确的聚合路径

"批次 × 货位 → 数量"必须走 `Serial and Batch Entry` 关联 `Serial and Batch Bundle`：

```sql
SELECT sbe.batch_no, sbe.warehouse, SUM(sbe.qty) AS qty
FROM `tabSerial and Batch Entry` sbe
JOIN `tabSerial and Batch Bundle` sbb ON sbb.name = sbe.parent
WHERE sbb.docstatus = 1 AND sbb.is_cancelled = 0
GROUP BY sbe.batch_no, sbe.warehouse
```

已实测该查询返回上文 3.2 的正确结果。

### 4.4 影响

- **M3-R2 的"按批号查货位"与"货位明细表"必须基于 `Serial and Batch Entry`，不能基于 `SLE.batch_no`**。
- M3-R0 §2.7 与第四节映射表的相关行已同步更正。
- 这不改变"优先复用原生"的总体结论；`Serial and Batch Bundle` 仍是原生机制，只是接入点不同。

## 八、执行方式与踩坑记录

执行方式（已写入脚本头部注释）：

```bash
docker compose cp "scripts/M3R1_货位清单.json"    backend:/tmp/M3R1_货位清单.json
docker compose cp "scripts/M3R1_建立货位主数据.py" backend:/tmp/M3R1_建立货位主数据.py
docker compose exec -T backend bench --site frontend console \
    <<< 'exec(open("/tmp/M3R1_建立货位主数据.py", encoding="utf-8").read())'
```

**踩坑 1**：不能把脚本直接重定向进 `bench console`（`console < script.py`）。`bench console` 是 REPL，多行缩进块会被拆成多个单元分别执行，`for` 循环只跑一次就被中断，表现为"只建了 1 个节点就报父仓库找不到"。必须用 `exec(open(...).read())` 整体执行。

**踩坑 2**：`exec(code)` 不带命名空间时，函数体内看不到模块级变量（`NameError: name 'COMPANY' is not defined`）。须传显式命名空间：`ns={}; exec(code, ns)`。

两处均已写入脚本注释，供 M3-R2 复用。
