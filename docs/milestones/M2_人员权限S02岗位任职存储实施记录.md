## 2. 管理与运行边界

服务和仓储默认 enabled=false；没有公开 RPC、whitelist、管理 API、Hook、自动迁移、自动锁根初始化或前端写按钮。接入方未来必须显式启用并注入可信来源加载器、服务端当前操作者、时钟和独立管理政策；客户端不能传入 subject_user、操作者、修订代次、权限布尔或写入许可。

管理政策必须返回绑定操作者、命令类型、公司、部门及目标人员的 ManagementDecision 和可追溯 policy_ref，返回 true 或错配范围均拒绝。操作前检查原生 User 启用状态，获取来源锁后再次检查政策；本段未指定实际管理人，也未把 System Manager / HR 角色或 Administrator 身份默认换算为关系管理权。

控制器许可只覆盖当前类型与记录，客户端 Document.flags、ignore_permissions 或 ignore_validate 不能取得许可；db_insert / db_update 另有校验，db_set、删除及更名拒绝。许可只能由服务端受控仓储建立。**这不是数据库访问控制**：可信服务器代码的原始 SQL / frappe.db.set_value 不经过此控制器；实际 REST、导入和框架低层路径仍需真实运行验证及入口闭环审查。

任职只维护事实，不调用 Employee.save，不修改 User.enabled、原生 Role、Role Profile 或业务权限，不生成 Grant。当前创建任职要求 Employee 来源；没有账号的 Employee 可以保留任职事实，不能据此得到账号权限。多员工关联拒绝；User-only 草案、关联变更的历史清理与撤权流程尚未实现。

## 3. 事务、修订和时间行为

四个命令为 create_position、update_position、create_assignment、update_assignment。输入限定字段；更新必须携带 expected_revision，使用 UUID 幂等键和非空原因。更新修订号严格递增，旧修订不可覆盖，标题修改不增加授权失效代次；停用 / 恢复、岗位类别或主岗语义变化会增加代次。

任职输入为带时区 RFC 3339 时间，标准化为显式 UTC；等价时区表达对应相同请求摘要。区间为左闭右开，结束可为空。缩短未来截止时间在截止前保留原代次，实际到期仍须由后续执行层检查最新期限；立即结束、延期或恢复无结束时间增加代次，避免恢复旧授权。本段未实现业务执行层或自动到期调度。

事务步骤为保存点 → 预置站点锁根 FOR UPDATE → 来源及管理检查 → 按固定顺序锁 User / Employee / Company / Department / Designation → 再读来源并比对 → 再查管理政策 → 幂等 / 修订检查 → 写主记录、不可变修订及收据。任职检查读取全部 active 事实，包括未来区间，无分页截断；按同一人员及其已核实来源别名拒绝同岗位重叠和重叠主岗，允许相邻区间及合法兼任。

同一命令键和相同规范内容重放返回原始简要结果；不同内容拒绝，重放仍需重新验证管理边界及来源。失败回滚到命令保存点；服务没有 commit，返回 transaction_pending=true，最终提交由未来外层请求事务负责。收据结果 authorization_effect=none / runtime_verified=false，不是生效授权凭据。

站点内基础关系命令采用粗粒度串行写锁，是本段的初始实现选择。它不能替代既有设计中人员生命周期、原生关联变更、岗位角色关联、Grant 或业务提交的共同锁协议。原生写入是否遵循锁顺序、事务隔离下来源重读是否足够新鲜、并发插入 Employee 关联的缺行范围、实际锁等待 / 死锁恢复及提交线性化均 **NOT_RUN**；未据内存锁测试宣称真实并发闭环。
