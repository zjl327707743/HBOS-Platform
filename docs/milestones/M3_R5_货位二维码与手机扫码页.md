## 二、设计要点

### 2.1 二维码内容

```
{站点地址}/hbos_bin?bin={货位短码}
```

例：`http://192.168.0.179:8080/hbos_bin?bin=16-03-221`

要点：

- **不含任何物料信息**，只有货位标识；扫码后由服务端实时查库，信息永远最新（Owner 在 M3-R0 已定）。
- 货位短码 = 去掉公司后缀（`16-03-221 - HB` → `16-03-221`），与纸质写法一致。
- 短码可能含中文与空格（如 `3904 六车间中间库`），入二维码前做 **URL 编码**。

### 2.2 扫码页（`/hbos_bin`）

Frappe 原生 `www` 页面，服务端渲染，**不是**前端工程。

| 行为 | 实现 |
| --- | --- |
| 未登录 | 跳转登录页，登录后**回跳本页**（`redirect-to` 整体 URL 编码） |
| 传货位短码 | 展示该货位全部在库明细 |
| 传库位 / 层（分组节点） | 展开其下**全部叶子货位**汇总展示，页首标注"库位汇总（含下级货位）" |
| 货位不存在 | 友好提示，不报错 |
| 未传参数 | 提示补充 `?bin=` |

**展示字段（全部，不脱敏）**：批号、物料代码、物料名称、数量与单位、包装规格、件数、放行状态（含合格证编号与放行日期）、来源类型、生产日期、有效期至（含效期类型）、生产车间、生产单位、供货单位、原厂批号。

页首汇总：批次数、物料数、合计数量。

排序：按货位 → 物料 → 有效期 → 批号，临期批次自然靠前。

### 2.3 货位短码解析（宽容匹配）

手输场景下做了三级匹配，依次尝试：

1. 完整名称精确（含 ` - HB` 后缀）；
2. 短码精确（`16-03-221`）；
3. **短码前缀**（输入 `3904` 可命中 `3904 六车间中间库`）。

这样即使只记得库位号（3904），也能打开对应库位的汇总页。

### 2.4 二维码打印

新增 Print Format **`HBOS 货位二维码`**（挂 `Warehouse`，60mm × 40mm 标签纸），包含：

- 货位短码（大字）+ 库位中文名
- 二维码（内联 SVG）
- 提示语「扫码查看该货位在库明细」
- 完整链接（小字，供无法扫码时手输）

二维码由 Frappe 自带的 `pyqrcode` 生成（Frappe 依赖中已有，无需新增第三方包），以**内联 SVG** 输出，打印清晰、不依赖外部图片。

### 2.5 登录边界的取舍（需 Owner 知悉）

扫码页**要求登录**（未登录跳登录页）。这是 Frappe 的默认安全边界：库存数量、批号、供应商属业务数据，不宜对互联网匿名公开。

"字段不脱敏"指的是**对已登录的普通员工**全部开放，两者不冲突。若后续希望扫码后**免登录**也能看（例如临时人员找货），需单独授权并对可见范围另作界定——本轮未做。

## 三、实现方式

### 3.1 文件清单

| 文件 | 作用 |
| --- | --- |
| `hbos_inventory/qr_utils.py` | 二维码与货位链接辅助方法（经 `jinja.methods` 注册） |
| `hbos_inventory/print_format/HBOS货位二维码/HBOS货位二维码.json` | 货位二维码标签模板 |
| `hb_inventory_app/www/hbos_bin.py` | 扫码页控制器（`get_context` 实时查库） |
| `hb_inventory_app/www/hbos_bin.html` | 扫码页模板（移动端适配） |

数据源沿用 M3-R1 实测结论：`Serial and Batch Entry` 关联 `Serial and Batch Bundle`（v16 中 `SLE.batch_no` 为空列不可用）。

### 3.2 与 M3-R4 的共用

扫码页直接复用 M3-R4 的 `print_utils.hbos_packaging_spec` / `hbos_packaging_count`，保证**扫码页与货位卡上的包装规格、件数写法完全一致**。

## 五、实现中发现并修复的问题

| 问题 | 处理 |
| --- | --- |
| **路由名含连字符导致整页 500**：`www/hbos-bin.py` 无法作为 Python 模块 import，`get_context` 不执行，模板渲染缺变量报 `'total_qty' is undefined` | 路由改为下划线 `hbos_bin`（`/hbos_bin`），并把 `BIN_PAGE_ROUTE` 同步改名 |
| 未登录跳转的 `redirect-to` 拼在 URL 后未编码，`?bin=` 被截断 | 整体 `quote(target, safe="")` |
| 上下文变量在提前 return 时未赋值，模板取到 undefined | 在 `get_context` 开头为全部变量兜底赋值 |
| **`hooks.py` 中 `jinja` 被重复定义**（M3-R4 遗留），后一个覆盖前一个，导致 `qr_utils` 未注册 | 删除重复定义，合并为一个 `jinja`（含 `print_utils` + `qr_utils`） |
| 手输 `3904` 匹配不到 `3904 六车间中间库` | 短码解析增加**前缀匹配** |
| 页首标题显示原始输入（`3904`）而非解析后的货位名 | 改用 `warehouse_label` |

**特别注意**：`hooks.py` 的重复定义是 M3-R4 遗留缺陷——因 Python 后定义覆盖前定义，`print_utils` 仍注册成功，故当时未暴露；本轮新增 `qr_utils` 时才显现。已修复。
