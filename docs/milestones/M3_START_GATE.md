# M3 启动门禁

项目名称：新乡海滨智能运营管理平台。

## 文件定位

本文件记录 M3（仓储库存数字化管理）的目标、边界、门禁条件、子轮次状态和下一步路线。

M3 由 Owner 明确授权新开，与 M1-FIX（考勤功能补漏）并列，不替代、不阻塞 M1-FIX。

当前状态：M3-R0 为 REVIEWING，等待 Owner 和 Claude 审查；M3-R1 及之后为 PLANNED，待 Owner 逐轮授权。

## 必须满足的前置条件

- M0 状态为 COMPLETED（已满足）。
- ERPNext `Stock` 模块可用（已满足；只读盘点确认 44 个非子表 DocType 存在）。
- 当前 `frontend` site 可访问（已满足）。
- `git status` 应保持 clean 后再提交本轮成果。
- 不允许提交 `.env`、备份文件、密钥、数据库、Docker volume 或运行时数据。
- 不允许提交真实业务数据、真实产品清单或真实 Excel / CSV。

## M3 目标

把仓库产品库存信息数字化，形成"产品—批次—货位"对应台账，并在此基础上支持批次查询、出库核销、效期预警、盘点导出、待检证与货位卡生成、货位二维码与手机扫码查询、入库拍照识别。

## M3 范围

M3 允许做：

- 复用 ERPNext 原生 `Item`、`Batch`、`Warehouse`、`Bin`、`Stock Ledger Entry`、`Stock Entry`、`Purchase Receipt`、`Delivery Note`、`Stock Reconciliation`、`Quality Inspection` 等标准能力。
- 只读盘点、需求确认、货位与批次建模、原生配置、报表、`Print Format`、Frappe 原生 Web 页。
- 经 Owner 逐轮授权后，创建有限的海滨自定义 Frappe App（用于海滨特有规则，不用于重写 ERPNext 已有功能）。
- 经 Owner 逐轮授权后，建设外部 FastAPI + 视觉模型的入库拍照识别服务。

M3 不允许做：

- 修改 Frappe / ERPNext / HRMS 核心源码。
- 未授权创建任何自定义 Frappe App 或 DocType。
- 开发 MES、LIMS、QMS、EHS 等完整系统。
- 未授权启动 Vue / React 独立前端。
- 未授权执行飞书真实写入。
- 飞书集成优先通过后续 `hb_feishu_app` 统一管理，不得分散写入业务模块。
- 执行 `docker compose down -v`、删除 Docker volume、重建 `frontend` site。

## 已确认的架构决策

| 议题 | 决策 | 决策来源 |
| --- | --- | --- |
| 里程碑归属 | 新开 M3 仓储里程碑，按 M0 / M1 同节奏推进 | Owner 授权 |
| 存放模式 | **固定货位 + 随机存放**：物理货位长期固定，产品 / 批次放哪个货位由入库时现场决定且允许换位 | Owner 确认（M3-R0 5.1） |
| 货位建模 | **方案 A：`Warehouse` = 货位**。`16号楼产品库 - HB` 下挂 203 个货位 `Warehouse` | Owner 确认（M3-R0 5.2） |
| 层管理 | **方案 A1**："层"作为 `Warehouse` 树的一级（`16号楼产品库 → 03区 → 第一层 → 货位`）；层不可由编码推导，需显式录入 | Owner 确认（M3-R0 5.3） |
| 非货位区域 | "工作台""退回产品区"建成叶子 `Warehouse`，直接挂在库区下，不属任何层 | Owner 确认（M3-R0 5.3） |
| 批次 × 货位台账 | 由 `Stock Ledger Entry` 聚合（含 `warehouse` + `batch_no`）；`Bin` 只到"物料 × 货位"粒度，不含批次 | M3-R0 只读表结构核对（2.7） |
| 试点范围 | 只做 16 号楼产品库（203 个货位），暂不含无菌成品库；设计预留多库房扩展 | Owner 确认 |
| 入库拍照识别 | 外部 FastAPI + 视觉模型独立服务，返回结构化 JSON，人工校对后入台账 | Owner 授权 |
| 货位二维码扫码页 | Frappe 原生 Web 页，不启动独立 Vue / React 前端 | Owner 授权 |
| 二维码内容 | 不存静态物料信息，存货位查询链接，扫码实时查库 | 参考文档（wiki） |
| 货位编码 | 格式 `16-03-NNN`（库房-库区-货位序号）；"层"是否进系统待确认 | 参考文档附件《产品库货位号统计.xlsx》 |
| 待检证 | `Print Format` / 模板生成，字段已明确 | 参考文档附件《待检证模板.docx》 |
| 货位卡 | 模板已由 Owner 提供（`自产物料/产品货位卡`），字段含品名 / 物料代码 / 生产车间 / 生产批号 / 包装规格 / 件数 / 复检期·有效期 / 入库经手人·复核人 / 入库数量·单位 / 货位号 / 待检日期 / 放行·不放行 / 出入库流水表 | Owner 提供 + M3-R0 3.8 |
| 待检 / 放行 | 货位卡暴露"待检 → 放行 / 不放行"状态门禁；实现方式待确认 | 【待确认】见主文档 3.8、7.2 第 15 项 |
| 批号规则 | 三类结构：① 原料药/中间体 `生产线-年-月-流水号(3位)`；② 混粉 `生产线-主要两组份拼音首字母-年-月-流水号`；③ 亚批 `主批号-1/-2/-3`。生产日期 = 投料当天，有效期自投料当天起算。M3 不实现批号生成 | Owner 提供（M3-R0 3.9） |
| 亚批次 | `Batch.parent_batch` 单父结构原生覆盖，无需自定义 | Owner 确认 + M3-R0 3.9 |
| 批号唯一性 | Owner 明确**不存在撞号**；`Batch.batch_id` 可直接承载业务批号，"按批号查货位"以批号为唯一键成立 | Owner 确认（M3-R0 3.9 风险一） |
| 混粉批次 | **无特殊建模**：Owner 明确混粉与成品登记流程完全相同；仓库对所有产品种类走统一登记流程，混配与来源批次追溯不在仓库范围 | Owner 确认（M3-R0 3.9 风险二） |
| 亚批次 | 按**统一登记流程**处理；如需追溯，`Batch.parent_batch` 原生可选支持 | Owner 确认（M3-R0 3.9 风险三） |
| 入库登记流程 | **所有产品种类统一**（原料药、中间体、混粉、成品、亚批），无需分类分支 | Owner 确认（M3-R0 3.9） |
| 待检 / 放行 | **出库须有 QA 放行手续 + 合格证，缺任一项不可出库**；实现方式待 M3-R2 定 | Owner 确认（M3-R0 3.8 发现一） |
| 货位卡粒度 | **一个批号只对应一张货位卡**，不论该批散放多少个货位 | Owner 确认（M3-R0 3.8 发现三） |
| 包装构成 | 件 = 5kg 一桶（两桶一纸箱）、尾桶 = 不足 5kg 单独装桶、听/瓶 = QC 或客户取样小样；业务语义已明确，承载方案待定 | Owner 确认（M3-R0 3.8 发现二） |
| 货位明细表 | 需支持"一个货位的全部批号"查询；由 `Stock Ledger Entry` 按 `warehouse` 聚合，**无需新表** | Owner 提出 + M3-R0 第四节 |
| 双计量单位 | **KG / 件**；但件数为"件 / 听 / 瓶"混合计数，承载方式待定 | Owner 确认 + M3-R0 3.8 |
| 效期预警 | 有效期口径**按产品种类区分**（原料药/中间体、亚批次从投料当天起算；混粉从混料当天起算；相同原料不同批次混合取最短批次）；期限 2 年 / 3 年不等，分**复检期**与**有效期**两种；系统在产品主数据上维护 | Owner 确认（M3-R0 3.9） |
| 出库核销 | **FIFO 先进先出**为默认，**客户指定批次时按指定先出** | Owner 确认 |

## 门禁条件

进入 M3-R1 前必须满足：

- M3-R0 已收口。
- `M3_R0_仓储库存只读盘点与需求确认.md` 第七节业务口径确认表中至少前 5 项（批号规则、货位编码规则、产品主数据、效期预警阈值、出库核销规则）已由业务负责人确认。
- 存放模式、货位建模方案、层管理方案、非货位区域处理、试点范围已确认（M3-R0 已完成：固定货位 + 随机存放 / 方案 A / 方案 A1 / 建成 `Warehouse` / 只做 16 号楼产品库）。
- 双计量单位口径已确认（KG / 件，M3-R0 已完成）；批号规则三类结构已明确（M3-R0 已完成）；批号唯一性已确认（不存在撞号，`batch_id` 直接可用）。
- **统一登记流程已确认（M3-R0 已完成）**：所有产品种类走同一套登记流程，混粉无需特殊建模、亚批次无需特殊处理。
- **包装构成的承载方式已确认（第 16 项）**——业务语义已明确，"容器类型 + 单件重量 + 件数"明细如何存待定；未定会导致 M3-R2 返工。
- 产品主数据口径已确认（第 3 项，含效期类型与期限）。

**当前无高优先级阻塞项**；剩余 4 项待确认（产品主数据、盘点口径、扫码可见信息、拍照校对责任）均非阻塞，可在 M3-R1 / M3-R2 期间并行澄清。

进入 M3-R3（出库核销）前必须满足：

- 出库核销口径已确认（已满足：FIFO + 客户指定先出）。
- **QA 放行手续 / 合格证的校验方式已确认**（已明确需校验；实现方式待 M3-R2 定）。
- 是否允许负库存已确认。

进入 M3-R4（待检证与货位卡）前必须满足：

- 待检证字段已明确（已满足）。
- 货位卡字段与版式已确认、一批一卡规则已确认（已满足）。
- 一批多货位时卡上货位号的呈现方式已设计。

进入 M3-R6（拍照识别）前必须满足：

- 外部 FastAPI 服务的部署位置、模型选型、数据留存与脱敏规则已确认。
