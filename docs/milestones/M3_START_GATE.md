# M3 启动门禁

项目名称：新乡海滨智能运营管理平台。

## 文件定位

本文件记录 M3（仓储库存数字化管理）的目标、边界、门禁条件、子轮次状态和下一步路线。

M3 由 Owner 明确授权新开，与 M1-FIX（考勤功能补漏）并列，不替代、不阻塞 M1-FIX。

当前状态：M3-R0 为 REVIEWING、M3-R1 为 REVIEWING，等待 Owner 和 Claude 审查；M3-R2 为 PLANNED（方案已就绪，待授权执行）；M3-R3 及之后为 PLANNED，待 Owner 逐轮授权。

## 必须满足的前置条件

- M0 状态为 COMPLETED（已满足）。
- ERPNext `Stock` 模块可用（已满足；只读盘点确认 44 个非子表 DocType 存在）。
- 当前 `frontend` site 可访问（已满足）。
- `git status` 应保持 clean 后再提交本轮成果。
- 不允许提交 `.env`、备份文件、密钥、数据库、Docker volume 或运行时数据。
- 不允许提交真实业务数据、真实产品清单或真实 Excel / CSV。

## M3 目标

把仓库产品库存信息数字化，形成"产品—批次—货位"对应台账，并在此基础上支持批次查询、出库核销、效期预警、盘点导出、待检证与货位卡生成、货位二维码与手机扫码查询、入库拍照识别。

## M3 范围

M3 允许做：

- 复用 ERPNext 原生 `Item`、`Batch`、`Warehouse`、`Bin`、`Stock Ledger Entry`、`Stock Entry`、`Purchase Receipt`、`Delivery Note`、`Stock Reconciliation`、`Quality Inspection` 等标准能力。
- 只读盘点、需求确认、货位与批次建模、原生配置、报表、`Print Format`、Frappe 原生 Web 页。
- 经 Owner 逐轮授权后，创建有限的海滨自定义 Frappe App（用于海滨特有规则，不用于重写 ERPNext 已有功能）。
- 经 Owner 逐轮授权后，建设外部 FastAPI + 视觉模型的入库拍照识别服务。

M3 不允许做：

- 修改 Frappe / ERPNext / HRMS 核心源码。
- 未授权创建任何自定义 Frappe App 或 DocType。
- 开发 MES、LIMS、QMS、EHS 等完整系统。
- 未授权启动 Vue / React 独立前端。
- 未授权执行飞书真实写入。
- 飞书集成优先通过后续 `hb_feishu_app` 统一管理，不得分散写入业务模块。
- 执行 `docker compose down -v`、删除 Docker volume、重建 `frontend` site。

| 效期预警 | 有效期口径**按产品种类区分**（原料药/中间体、亚批次从投料当天起算；混粉从混料当天起算；相同原料不同批次混合取最短批次）；期限 2 年 / 3 年不等，分**复检期**与**有效期**两种；系统在产品主数据上维护 | Owner 确认（M3-R0 3.9） |
| 出库核销 | **FIFO 先进先出**为默认，**客户指定批次时按指定先出** | Owner 确认 |

- 产品主数据口径已确认（第 3 项，含效期类型与期限）。

**当前无高优先级阻塞项**；剩余 4 项待确认（产品主数据、盘点口径、扫码可见信息、拍照校对责任）均非阻塞，可在 M3-R1 / M3-R2 期间并行澄清。
