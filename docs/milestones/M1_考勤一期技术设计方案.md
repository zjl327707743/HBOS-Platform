M1 优先复用以下 HRMS 原生对象：

| HRMS 对象 | M1 用途 | 状态 |
| --- | --- | --- |
| Employee | 员工主数据 | 已配置，直接使用 |
| Shift Type | 班次定义（白班/中班/夜班/行政班） | 已配置，复用并扩展 |
| Shift Assignment | 员工排班 | 已可用 |
| Employee Checkin | 原始打卡记录 | 对接 Excel 导入 |
| Attendance | 考勤结果 | 对接 Auto Attendance |

### Shift Type 设计

| 班次 | 时间 | shift_hours | M1 状态 |
| --- | --- | --- | --- |
| 白班 | 08:00-16:00 | 8 | 必须 |
| 中班 | 16:00-00:00 | 8 | 必须 |
| 夜班 | 00:00-08:00 | 8 | 必须 |
| 行政班 | 09:00-18:00 | 8 | 必须 |

技术评估：夜班跨日期（00:00-08:00）可能导致 Attendance 日期归属与人工理解不一致。M1 优先使用 Shift Type 原生跨夜配置和 Attendance `attendance_date` 字段验证。如不一致，可在月度汇总报表中补充日期归属处理。

## Excel 导入设计

### 两类导入严格区分

| 导入类型 | 数据内容 | 目标 DocType | 用途 |
| --- | --- | --- | --- |
| 原始打卡流水 | 员工 + 日期 + 上班打卡时间 + 下班打卡时间 | Employee Checkin → Attendance | 生成考勤结果 |
| 月度汇总 Excel | 员工 + 月度统计字段 | 自定义汇总表或直接展示 | 对账、演示报表、历史数据迁移 |

不得把月度汇总表错误当成原始打卡流水。

### 导入方式优先级

1. **优先**：HRMS Data Import（Frappe 原生 `data_import` 工具，支持 CSV/Excel）
2. **备选**：如 HRMS Data Import 在 Employee Checkin 批量导入、字段映射、错误处理上不满足需求，再创建 HBOS 自定义导入入口

### 自定义导入入口设计（备选）

如果 HRMS Data Import 不满足需求，设计以下结构：

- DocType：`HBOS Import Log`（导入批次记录）
- 字段：
  - 导入批次号
  - 导入人（Link: User）
  - 导入时间
  - 导入类型（原始打卡流水 / 月度汇总）
  - 来源文件名
  - 总记录数
  - 成功数
  - 失败数
  - 失败原因（Text）
- 导入流程：
  1. 上传 CSV / Excel
  2. 前端预览 / 校验
  3. 批量写入 Employee Checkin 或汇总表
  4. 记录导入批次日志

技术评估：M1 可以先不做复杂批次管理，但要保留导入批次记录结构。

### 月度汇总导入（区别于流水导入）

月度汇总 Excel 导入目标不是 Employee Checkin，而是直接填充月度汇总报表数据或独立的月度汇总 DocType，用于对账和演示。导入后不触发 Auto Attendance。

## 异常说明 / 主管确认 / 人事归档实现评估

### 当前方案

M1 优先用 HRMS 原生 Attendance Request 作为异常处理载体，流程如下：

```
员工发起 Attendance Request（类型：补卡/异常说明）
→ 主管审批（Workflow / 自定义按钮）
→ 人事最终处理（修改 Attendance 或标记已确认）
```

### 如原生无法覆盖则评估自定义 DocType

如 HRMS 原生 Attendance Request 无法满足 M1 异常处理类型（设备异常、班次错误等 6 种），则评估创建：

- `Attendance Exception`：考勤异常说明记录
  - Employee（Link）
  - Date
  - Exception Type（Select：补卡 / 设备异常 / 公出会议 / 班次错误 / 请假未同步 / 其他）
  - Description（Text）
  - Status（Select：待主管确认 / 主管已确认 / 主管驳回 / 人事已处理 / 已归档）
  - 主管确认人 / 确认时间
  - 人事处理人 / 处理时间
  - 修改内容记录

- `Attendance Correction`：考勤修正记录
  - 关联 Attendance / Employee Checkin
  - 修正前值 / 修正后值
  - 修正原因
  - 操作人 / 操作时间

技术评估：本轮不创建自定义 DocType。仅在后续实施轮次中，经用户确认后再创建。

## 飞书登录与 Employee 匹配设计

### 登录流程

```
浏览器访问 HBOS /login
→ 点击"飞书登录"
→ 跳转飞书 OAuth 授权
→ 飞书返回用户身份（open_id / 手机号 / 邮箱）
→ HBOS 根据手机号 / 邮箱 / 工号匹配 Employee
→ 匹配成功：自动关联 Frappe User，进入对应角色页面
→ 匹配失败：提示"未找到匹配员工，请联系人事"
→ 兜底：本地管理员账号登录
```

### 匹配策略

以手机号为主要匹配字段（飞书返回的手机号 ↔ Employee `cell_number`），邮箱和工号为备选。

### 权限控制

- 飞书身份只负责登录认证。
- 登录后的页面权限、数据权限、操作权限全部由 Frappe Role / User Permission 控制。
- 主管关系在 Employee `reports_to` 字段中维护。

M1 不修改 Frappe 核心认证逻辑，仅通过 Frappe Social Login Key（OAuth Provider）接入飞书。

## 权限映射

| M1 角色 | Frappe Role | 权限范围 |
| --- | --- | --- |
| 员工 | Employee Self Service | 自己的 Employee 记录 |
| 部门主管 | Department Manager（自定义） | 本部门 Employee（User Permission: Department） |
| 人事 / 考勤管理员 | HR Manager / HR User | 全公司 |
| 领导 | Report Viewer（自定义） | 汇总报表（无明细） |
| 系统管理员 | System Manager | 全量 |

部门主管通过 Frappe User Permission（Department）限制数据范围。

## 月度汇总报表与 Excel 导出

### 技术方案

- 优先使用 Frappe Query Report 实现月度汇总报表。
- 报表数据来源：Attendance（按 `attendance_date` 和 Employee 聚合）。
- 如 Query Report 性能或灵活性不足，评估使用 Script Report。

### 月度汇总字段映射

| 汇总字段 | 数据来源 |
| --- | --- |
| 员工姓名 | Employee `employee_name` |
| 部门 | Employee `department` |
| 应出勤天数 | Shift Assignment 统计 |
| 实际出勤天数 | Attendance `status = Present` 计数 |
| 迟到次数 | Attendance `late_entry = 1` 计数 |
| 早退次数 | Attendance `early_exit = 1` 计数 |
| 缺卡次数 | Employee Checkin 单边打卡计数 |
| 缺勤天数 | Attendance `status = Absent` 计数或无 Attendance 判缺勤 |
| 请假天数/小时 | Leave Application 聚合 |
| 加班小时 | Attendance `working_hours` - Shift Type 标准工时（需审批） |
| 节假日出勤 | Holiday List 匹配后的 Attendance 计数 |
| 异常待确认数 | Attendance Exception（待确认 / 待处理状态） |
| 最终考勤状态 | 处理逻辑计算（正常/异常/已确认） |
| 备注 | 手工填写或自动生成 |

### Excel 导出

使用 Frappe 原生 Excel Export 能力，或在 Script Report 中生成 `.xlsx`。

| 总记录数 | Int | |

M1 实现可以先不做复杂批次管理，但结构必须预留。如果使用自定义导入入口，则必须保留导入批次记录。

## 是否创建 hb_hr_app

结论：本轮不创建 `hb_hr_app`。

判断依据：

- M1 Demo 大部分功能可复用 HRMS 原生对象。
- 仅在以下场景需要自定义 App：
  1. 自定义导入入口（HRMS Data Import 不满足时）
  2. 自定义异常 DocType（Attendance Exception / Correction）
  3. 自定义汇总报表（Script Report 超出 Query Report 能力时）
  4. 考勤工作台自定义 Page / Workspace
- 这些场景是否触发，取决于后续 R5/R6/R7 的实施验证结果。
- 当前阶段不应为"可能需要的自定义"提前创建空 App。

## 不修改核心源码原则

M1 所有功能通过以下方式实现，不修改 Frappe / ERPNext / HRMS 核心源码：

- Frappe Hook（`hooks.py`）
- Custom DocType
- Custom Script / Client Script
- Query Report / Script Report
- Frappe Page / Workspace
- Frappe Role / User Permission
- Frappe Data Import
- Frappe Social Login Key（飞书 OAuth）
- Frappe REST API / Frappe Client
