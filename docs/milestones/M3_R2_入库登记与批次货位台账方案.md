## 二、本轮技术调研发现

调研均为只读查询，未修改任何配置或数据。

### 2.1 效期：「期限」原生可承载，但「类型」不行

`Item` 原生已有：

| 字段 | 类型 | 对海滨需求的意义 |
| --- | --- | --- |
| `has_expiry_date` | Check | 是否有效期 |
| `shelf_life_in_days` | Int | **效期天数**——2 年 = 730、3 年 = 1095，原生即可表达"期限" |
| `end_of_life` | Date | 停产日期（非效期） |

**结论**：Owner 确认的"按产品质量标准设定期限"，可用 `shelf_life_in_days` 承载，由生产日期推算到期日。但 **"复检期 / 有效期"的类型区分原生没有**，需自定义字段。货位卡上那两个勾选框对应它。

### 2.2 「件」：原生换算是固定的，装不下尾桶

`Item` 有 `uoms` 子表 = **`UOM Conversion Detail`**（原生备选单位机制，官方说明"1 Box = 12 Nos, conversion factor 12"）。

**问题**：原生备选单位是**单一固定换算系数**。而海滨的「件」不是固定值——整桶 5.00 kg、尾桶 4.33 kg，同为"件"但重量不同。

**结论**：印证 Owner 的选择——「件」只作计数单位，不参与换算；包装构成走自定义子表。

### 2.3 待检 / 放行：原生 `Quality Inspection` 不匹配"凭证"语义

`Quality Inspection` 原生存在：

| 字段 | 取值 |
| --- | --- |
| `status` | Accepted / Rejected / Cancelled（必填） |
| `inspection_type` | Incoming / Outgoing / In Process（必填） |
| `reference_type` | Purchase Receipt / Delivery Note / Stock Entry 等（必填，须挂具体单据） |
| `batch_no` | Link → Batch |
| `inspected_by` | Link → User（必填） |
| `verified_by` | Data |

**结论**：QI 是"检验记录"，要求挂单据、必填检验人，比较重；而 Owner 说的门禁依据是 **"QA 放行手续 + 合格证"**，属凭证类语义。故按 Owner 决策走 `Batch` 自定义字段；原生 QI 保留为**未来可选**（若后续要正式化检验流程再接入，不冲突）。

### 2.4 产品分类：原生只有标准 6 类

`Item Group` 现有：`All Item Groups`（根）、`Products`、`Raw Material`、`Sub Assemblies`、`Consumable`、`Services`。

**结论**：没有"原料药 / 中间体 / 混粉 / 成品"这类海滨分类，需新建分类树（Owner 已确认）。

### 2.5 更正一处我此前的误判：自定义字段**是有版本化的**

我此前看到 `hb_attendance_app/patches.txt` 为空，怀疑 M1 的 59 个自定义字段只存在数据库、未进 git。

**查证后推翻该怀疑**：实际模式在 `hb_attendance_app/hb_attendance_app/hbos_attendance/setup.py`——通过 `hooks.py` 注册 `after_migrate = "hb_attendance_app.hbos_attendance.setup.after_migrate"`，在钩子里调用 `create_custom_fields(...)` 声明式创建字段（`Employee Checkin` 3 个、`Attendance` 6 个等）。

这是**代码化、幂等、可版本化、可复现**的做法。**M3 沿用同一模式**，这也是授权新建 `hb_inventory_app` 的意义所在。

## 三、`hb_inventory_app` 设计

### 3.1 定位与边界

- 模块名：`HBOS Inventory`
- 只用于**海滨仓储特有规则**，不重写 ERPNext 已有功能。
- 不修改 Frappe / ERPNext / HRMS 核心源码。
- 与 `hb_attendance_app` 并列，各自独立，不互相依赖。

### 3.2 内容清单

| 类别 | 内容 | 承载方式 |
| --- | --- | --- |
| UOM | 新建「件」计量单位 | `after_migrate`（幂等） |
| Item Group | 海滨产品分类树 | `after_migrate`（幂等） |
| 自定义字段 | 见 3.3 | `after_migrate` + `create_custom_fields` |
| 子表 DocType | `HBOS 包装明细` | App 内 DocType JSON（版本化） |
| 报表 | 按批号查货位、货位明细表 | App 内 Report JSON（版本化） |
| Print Format | 待检证、货位卡 | App 内（M3-R4） |
| Web 页 | 货位扫码页 | App 内（M3-R5） |

### 3.3 自定义字段清单（候选）

**`Item` 上新增**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `hbos_product_kind` | Select | 产品种类：原料药 / 中间体 / 混粉 / 成品（与批号规则、效期口径对齐） |
| `hbos_workshop` | Data | 生产车间（如"六车间B线"） |
| `hbos_shelf_life_type` | Select | 效期类型：复检期 / 有效期 |
| `hbos_shelf_life_months` | Int | 效期期限（月）；与原生 `shelf_life_in_days` 二选一，需定 |
| `hbos_storage_condition` | Small Text | 储存条件（待检证用） |

**`Batch` 上新增**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `hbos_release_status` | Select | 待检 / 已放行 / 不放行（**出库门禁依据**） |
| `hbos_release_date` | Date | 放行日期 |
| `hbos_certificate_no` | Data | 合格证编号 |
| `hbos_certificate_file` | Attach | 合格证附件（扫描件） |
| `hbos_packaging` | Table → `HBOS 包装明细` | 包装构成 |

**`HBOS 包装明细`（子表）字段**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `container_type` | Select | 容器类型：件 / 听 / 瓶（可扩展） |
| `unit_weight` | Float | 单件重量（kg）；整桶 5.00、尾桶为实际余量 |
| `count` | Int | 件数 |
| `is_tail` | Check | 是否尾桶（可选，便于识别与统计） |
| `remark` | Data | 备注 |

设计要点：`container_type + unit_weight + count` 三要素可完整表达 `34件3听1瓶`（含尾桶），且 `unit_weight × count` 汇总 = 包装总量，可与 `kg` 数量交叉校验。

### 3.4 包装置放位置

**放在 `Batch` 上（一批一条，多条明细）**，理由：

- Owner 已确认"一个批号只对应一张货位卡"，包装规格是**批次属性**，卡上要打印 `34件3听1瓶`；
- 一批若分多次入库，包装明细在 `Batch` 上可**累计汇总**，恰好是"这一批总共怎么装的"；
- 若放在 `Stock Entry` 明细行上，则是"每次入库怎么装的"，与货位卡按批出卡的口径不一致。

（注：本项为方案建议，未单列询问；若 Owner 认为需按每次入库分别记录，可在授权时调整。）

## 四、关键实现路径

### 4.1 入库登记

- 用原生 **`Stock Entry`（Material Receipt）**，明细行填 `batch_no` + `qty` + `t_warehouse`（货位）。
- 需配合已开启的 `Stock Settings.enable_serial_and_batch_no_for_item`（M3-R1 已开）。
- `Batch` 在首次入库时创建（或由车间信息预建），同时录入 `hbos_packaging` 与效期字段。

### 4.2 「按批号查货位」与「货位明细表」

**基于 `Serial and Batch Entry`**（M3-R1 实测确认；`SLE.batch_no` 在 v16 为空列不可用）：

```sql
-- 批号 → 货位 → 数量
SELECT sbe.batch_no, sbe.warehouse, SUM(sbe.qty) AS qty
FROM `tabSerial and Batch Entry` sbe
JOIN `tabSerial and Batch Bundle` sbb ON sbb.name = sbe.parent
WHERE sbb.docstatus = 1 AND sbb.is_cancelled = 0
GROUP BY sbe.batch_no, sbe.warehouse;

-- 货位 → 全部批号
SELECT sbe.warehouse, GROUP_CONCAT(DISTINCT sbe.batch_no), SUM(sbe.qty)
FROM ... GROUP BY sbe.warehouse;
```

`Bin` 仅用于"物料 × 货位"结存，不含批次。

### 4.3 出库门禁（M3-R3 使用，本方案预埋字段）

出库校验 `Batch.hbos_release_status = 已放行` 且 `hbos_certificate_no` 非空，否则拦截。字段在本轮建好，校验逻辑留 M3-R3。
