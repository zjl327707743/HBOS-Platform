## 2. 实际发现与修复

本段 Preview 为 Frappe 16.26.3 / MariaDB 11.8.8、REPEATABLE-READ，实际 `innodb_snapshot_isolation=1`。先以普通 SELECT 建立旧快照、另一连接提交变更后，锁定读会报 **1020 / Record has changed since last read**。初次十项验收中五项失败：InnoDB 已终止事务，原保存点失效，旧异常处理再回滚保存点产生 **1305 / SAVEPOINT does not exist**，遮蔽了原冲突。

现对 Frappe 的 QueryDeadlockError 进行完整回滚以清理框架事务状态，返回 **RELATION_TRANSACTION_RETRY_REQUIRED** 并保留原异常链；同时使已进入的嵌套来源锁上下文失效，避免捕获内层失败后继续复用旧锁。不会在函数内部自动重放或提交，不调整数据库隔离级别 / 全局配置。

调用方遇到该错误必须终止整个请求，外层尚未提交的工作也可能已被数据库丢弃。重新发起完整请求，重新加载来源、检查管理政策和版本 / 幂等键；不能只重试失败 SQL 或继续外层旧业务流程。正常结果仍 transaction_pending=true，由调用方在同一事务内承担提交责任。未来 HTTP 层必须把这种失败明确映射为可重新提交的冲突，不静默吞错。本段没有实现该入口。

五项旧快照用例明确断言：旧请求失败、新请求重新执行，随后正确拒绝冲突或识别重放。它们没有以测试前清空快照来掩盖问题，也没有声称同一已失效事务能直接刷新。
