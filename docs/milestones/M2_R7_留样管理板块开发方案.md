2. **变更历史编号错位**：08 版变更历史中"记录二=留样登记、记录三=留样观察"与现行记录编号（一=登记、二=观察）错位一格，疑为变更说明笔误。

## 三、桌面方案评审结论

两份桌面方案业务梳理质量高，本方案吸收其全部业务成果；技术路线与本平台架构不符的部分全部修正，不采纳。

### 3.1 采纳

- 法规 → 系统实现映射表（方案一 §1.1、方案二 §二）。
- 记录字段清单（方案二 §3.5）——数据模型字段设计的直接输入。
- 两条审批链梳理与触发场景（用户投诉 / 检验结果分析 / 生产异常 / 上市前研发 / 其他）。
- 风险点：全检量动态绑定、受托方留样标识、观察批选取模式、留样与稳定性样品隔离（方案二 §八）。
- "P2 登记先行是合规地基"的分期判断。

### 3.2 修正（不采纳原因）

| 桌面方案内容 | 修正 | 原因 |
| --- | --- | --- |
| SQL `CREATE TABLE` 建表（方案一 §2.1） | Frappe DocType JSON | HBOS 全部业务承载为 Frappe 原生 DocType（既有 13 个 DocType 先例），SQL 层由 Frappe 自动管理 |
| 独立标签表 / 库存变动表（方案一表 5/6） | 标签=Print Format；库存流水=Stock Log 子表 + Audit Log | 标签是登记单打印视图无需建表；库存变动以通用流水子表（第七节）覆盖使用/销毁/续留/调整全部来源，变更审计由 R6D 覆盖 |
| 自研/Activiti 工作流引擎（方案一 §6.2） | 状态字段 + whitelist 方法 + workflow_contract 状态机 | 与 M2-R3 已交付模式一致，零 Frappe 依赖可离线单测 |
| 12 周独立里程碑（方案一 §6.1） | M2-R7A~D 四个子轮，嵌入既有轮次体系 | 遵循项目"每轮可验证、可审查、可回滚"节奏 |

### 3.3 两份桌面方案均未覆盖、本方案补充

1. **与检验闭环衔接**：现有 `HBOS Sample` 的 sample_source 已含"留样"来源。留样登记支持从检验完成批次（HBOS Sample 关联）一键创建，打通"请验 → 检验 → 留样"链路，这是 GMP"留样应能代表被取样批次"的最强实现方式。映射规则见第九节。
2. **审计复用**：直接注册进 M2-R6D `HBOS Audit Log`（write-once + sha1 防篡改），不自建审计。
3. **前端路径**：遵循项目前端规范——原型先行、Owner 审查、Vue 复刻、生产部署（R6 系列已验证的流程）。

## 四、业务规则数字化定案

以下规则为系统校验逻辑的唯一口径，全部来自规程 v09，字段命名见第五节。

### 4.1 留样分类与数量规则

| 规则 | 系统实现 |
| --- | --- |
| 仅三类留样：关键物料 / 成品（原料药）/ 外售产品 | `HBOS Retention Product.category` 三选一；包装材料、中间产品不提供留样路径 |
| 每批留样，留样量 = 全检量 × 2 倍 | 登记时若录入全检量（Float + UOM）则自动计算 2 倍并允许人工复核；贵重 / 小批量样品按实际填写。**UOM 一致性闸（rev4）：仅当 `full_test_qty_uom == default_uom` 时允许自动计算 2 倍；不一致时禁算，提示"全检量单位与产品默认单位不一致，请人工填写留样量"（不做换算）** |
| 全检量 < 1g 按 1g 计 | 登记校验：全检量数值 < 1 且 UOM 为 g 时提示按 1g 计（非硬拦截，留样量人工确认） |
| 独立包装：1 倍检验用量 = 1 个最小包装 | `package_count`（Int，最小包装件数）+ `package_spec`（Data，包装规格）记录 |
| 液体物料不留样 | `Product.is_liquid=1` 时登记**硬拦截** |
| 委托生产样品由受托方留样 | `Product.is_outsource=1` 的产品登记时提示"由受托方留样"并可标记转出；**转出登记直接以「已转出」状态创建（不经在库，current_qty=0，写受托转出审计事件，rev6 见 6.1）**；在库受托留样亦可由 Manager 执行 transfer_out 转出（写受托转出流水） |
| 国外药典 / 客户另有要求按其要求 | `retention_qty_rule` 允许"按客户要求"覆盖默认 2 倍 |
| 留样包装、储存条件与原物料一致 | 从 Retention Product 带出，可改可查 |
| **单位一致性（UOM 受控）** | 见 5.1/5.2：UOM 唯一来源为产品主数据 `default_uom`（Select 受控枚举），下游全部只读带出；不一致即硬拦截（不做换算，远期） |

### 4.2 期限与观察规则

| 规则 | 系统实现 |
| --- | --- |
| 留样期至 = 复验期/有效期 + 3 年 | 登记时自动计算（`retention_due_date`），允许人工修正并留痕 |
| 观察期至 = 复验期/有效期 + 3 年（与留样期同） | 观察计划以 `retention_due_date` 为终点 |
| 每 1 年观察一次外观性状，含 0 月基线 | 观察偏移（月）：0、12、24、36……直至观察期至；计划日期 = 留样日期 + 偏移月数 |
| 原料药成品每年每产品选 3 批作观察批 | 选取留痕（5.2 字段）+ **数量校验**：同产品同 obs_year 已选 3 批后第 4 批拒绝（见 5.3 观察批数量校验）；自动选取（最新 3 批/随机）为后续配置项 |
| 外售产品每批都观察 | 该类产品登记时自动置 `observed_flag=1`，obs_selected_reason=外售产品每批（不受 3 批上限约束） |
| 观察结果填《留样观察记录》，定期汇总报 QC 主管 | 观察记录 + 观察计划看板（应观察未观察标红） |
| 留样期间异常及时报告 QC 主管 | 观察记录异常结论必填异常描述，异常状态在看板置顶 |

### 4.3 使用审批链（记录三数字化）

```
触发场景（用户投诉 / 检验结果分析 / 生产异常 / 上市前研发 / 其他）
  → 申请部门填单（样品/批号/规格/数量 Float+UOM/原因）
  → QC 资源管理员确认留样库存量（确认即预占 reserved_qty，锁协议见第七节）
  → QC 负责人批准 → QA 负责人批准 → 质量管理负责人批准
  → 留样管理员取样（原子扣减，见第七节），库存操作流水留痕
  → 未经批准不得调用（无批准的申请单不产生任何库存扣减路径）
```

### 4.4 处理/销毁审批链（记录四数字化）

```
每季度：到期清单（留样期至 ≤ 季度末）
  → 留样管理员填处理申请（名称/批号/数量 Float+UOM/原因/方式/地点）
     原因三选一：留样期满销毁 / 留样期满继续留样 / 其他
  → QC 主管 → QC 负责人 → QA 审核 →（QA 负责人，4/5 级可配置，见 6.5）→ 质量管理负责人批准
  → 销毁：QA 现场监督，处理人/监督人双签，3 个月内完成（自 qm_approved_at 起算）
  → 续留：更新该留样"留样期至"新值（变更进审计日志 old/new value）
```

### 4.5 台账规则

- 《留样产品清单》（附件二）→ 主数据 `HBOS Retention Product`，每年 1 月由 QC 维护更新，修改全部留痕（DocType 修改历史 + 审计日志）。
- 留样标签（附件一）→ Print Format 打印 `HBOS Retention Sample`，字段：类别勾选、品名、批号、数量、来源、有效期/复验期、留样人、留样日期、留样期至、观察样品是/否。
- 稳定性考察样品**不属于留样**：不从"稳定性样品"类型的 HBOS Sample 生成留样（边界硬隔离，规则见第九节）。

## 五、数据模型（Frappe DocType）

新增 5 主 DocType + 1 子表（延续既有命名与风格：HBOS 前缀、naming_series、中文 label、Select 状态字段、主数据 `field:xx_code`）。数量字段一律 **Float 数值 + UOM 字符串**（rev2），UOM 一律从产品主数据只读带出（rev3）。

### 5.1 HBOS Retention Product（留样产品主数据，附件二电子化）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| product_code / product_name | Data | 主数据命名 `field:product_code` |
| category | Select | 关键物料 / 成品（原料药）/ 外售产品 |
| storage_condition | Data | 储存条件（与物料一致） |
| retention_qty_rule | Select | 全检量 2 倍（默认）/ 按实际 / 按客户要求 |
| full_test_qty | Float | 全检量参照（数值） |
| full_test_qty_uom | Select（**受控枚举**） | 全检量单位 |
| **default_uom** | Select（**受控枚举**） | 默认计量单位——**全板块 UOM 唯一权威来源**。options 内置受控清单：g / kg / mg / mL / L / 瓶 / 支 / 袋 / 桶 / 盒 / 其他（扩充仅 Manager 改主数据，下游全部只读引用） |
| is_liquid / is_outsource | Check | 液体不留样（登记拦截）/ 受托方留样（提示转出） |
| obs_rule | Select | 每批观察（外售产品）/ 每年选 3 批（原料药成品）/ 不观察 |
| is_active | Check | 停用产品不再登记新留样 |

### 5.2 HBOS Retention Sample（留样登记，记录一电子化）+ 子表

主表字段（对齐记录一表头）：

| 分组 | 字段 | 类型 | 说明 |

### 5.3 观察批选取与数量校验（rev4 修订）

`obs_selected_reason=年度观察批` 的选取受数量上限约束，并带并发防护：

- **校验规则（3 批口径定稿，见待确认项 3）**：同一 Retention Product、同一 obs_year，年度观察批数量 **上限 3 批（硬校验）**；"3 批"为**目标值而非强制恰好值**——年度内该产品在库批次不足 3 批时，允许少于 3 批选取，不强制凑数；看板展示"当年已选 N/3"并在 N<3 时给完整性提示（"XX 产品 YYYY 年度观察批仅选 N/3，可补选"），不足选取不构成流程阻断，但作为观察计划看板的常驻提示项供 QC 主管汇总时核查。
- **并发防护（rev4）**：第 4 批选取的 validate 计数在**产品行 FOR UPDATE 锁内执行**——`SELECT … FOR UPDATE` 锁定该 Retention Product 行后统计已选批数，超限即拒绝，再提交。两个并发选取事务被产品行锁串行化，不会出现双方都读到 N=2 后同时通过。
- 适用范围：仅约束 `obs_rule=每年选 3 批` 的产品（原料药成品）；`obs_rule=每批观察`（外售产品）不受此限。
- 看板支撑：观察计划看板报表展示各产品"当年已选 N/3"（N=3 满员、N<3 完整性提示），超选尝试审计留痕（log_type=越权拦截）。
- 释放回退：已选取的观察批如需更换，先取消原批选取（obs 字段清空 + 审计），再选新批；不提供直接改（保证选取历史可追溯）。

## 七、库存一致性、数量语义与并发控制

### 7.1 数量语义（rev3 统一定义）

| 量 | 定义 | 存储 |
| --- | --- | --- |
| retention_qty | 登记留样量（原始量，不变） | 落库 |

| qty_delta | 流水带符号变动量（入库 +，出库 −） | Stock Log 落库 |
| remaining_qty | 流水快照（= 变动前 current_qty + qty_delta） | Stock Log 落库 |
| package_count | 包装件数（独立于计量数量，不换算） | 落库 |

**可用量口径（rev5 修订，消除与 7.3 特例的冲突）**：
- **可用量展示与判断**（库存确认前置校验、台账与报表展示、前端 fetch"还能用多少"）一律使用 `available_qty = current_qty - reserved_qty` 派生计算。
- **库存写操作的锁内复核**（执行、销毁、转出、调整、释放）不重复使用 available_qty 判断，按 7.3 各操作规则直接校验 `current_qty` / `reserved_qty`（执行复核本单预占、销毁与转出以 current_qty 为基准并前置 reserved_qty == 0）。available_qty 判断适用于无预占语境的"还剩多少"，不适用于已在锁内、预占语义已展开的操作级复核。

### 7.2 锁模型（四步协议，全操作统一）

所有库存写操作（**confirm_stock / execute_usage / execute_disposal / transfer_out / adjust_stock / 释放预占**，rev4 将库存确认纳入）统一执行：

```
1. 校验（无锁读）  ：读取 current_qty / reserved_qty，业务前置校验（角色、状态、UOM）
2. 锁行（FOR UPDATE）：SELECT current_qty, reserved_qty FROM `tabHBOS Retention Sample`
                       WHERE name=%s FOR UPDATE   ← 行级排他锁
3. 锁内复核        ：重新读取锁内值，按操作类型复核（见 7.3）
4. 写入并提交      ：更新 current_qty / reserved_qty + 写 Stock Log 流水（确认/释放不写出入
                     库流水但写审计事件）+ commit
                     （任何一步失败整体回滚，不留半扣减状态）
```

### 7.3 各操作锁内复核规则（rev4 修正）

| 操作 | 锁内复核 |
| --- | --- |
| confirm_stock（库存确认+预占） | `current_qty - reserved_qty >= apply_qty`（锁内重读两值计算，防并发确认读到相同可用量导致超额预占）；通过则 `reserved_qty += apply_qty` |
| execute_usage（使用执行） | **本单预占有效性**：`reserved_qty >= apply_qty`（本单预占仍在，未被驳回/取消路径释放）**且** `current_qty >= reserved_qty`（总量守恒，结存足以覆盖全部在途预占）；两条件满足即扣减（`current_qty -= apply_qty; reserved_qty -= apply_qty`）。**不再用 available_qty 判断本单可执行量**（rev4 修正：available_qty 已扣除本单预占，再以其 ≥ apply_qty 判断会要求"申请多少就必须额外多留多少"，逻辑错误） |
| execute_disposal（销毁执行） | `qty == current_qty` **且** `reserved_qty == 0`（整批销毁必须无在途预占且数量与结存一致；数量不等于结存拒绝并提示差额，见 R7C 负向用例） |
| transfer_out（受托转出） | `reserved_qty == 0`（有在途预占不得转出）且 current_qty 如实转出 |
| adjust_stock（手动调整） | 调整后 `current_qty >= reserved_qty`（**不得低于预占量**，否则预占悬空无法兑现）且 `current_qty >= 0` |
| 释放预占（驳回/取消，rev6 修正） | **前置：本单必须已过库存确认**（from-state ∈ {待QC批准, 待QA批准, 待QM批准, 已批准}，即本单持有预占；草稿/待库存确认阶段的驳回与取消**不触发释放**）。锁内复核 `reserved_qty >= apply_qty` 仅防重复释放。**不校验本单预占状态直接按聚合值扣减，会把未预占单的驳回错误扣到其他单的预占上，造成预占账目永久性错乱**（如 A 单已确认 qty=10，B 单确认前被驳回 qty=5，字面执行会把 A 的预占错扣 5） |

> 销毁复核说明：销毁数量校验基准为 `current_qty`（结存量）而非 available_qty——销毁是整批终结操作，前置 `reserved_qty == 0` 已保证 current_qty 与 available_qty 相等，两口径在此汇合。

### 7.4 并发正确性

- **使用 vs 使用并发（确认阶段）**：两单同时 confirm_stock，FOR UPDATE 串行化 + 锁内重读可用量，预占总量不超结存（rev4：确认阶段已在锁内校验）。
- **使用 vs 使用并发（执行阶段）**：两单同时 execute_usage，行锁串行化，各自扣自身预占，结存不为负。
- **使用 vs 处理并发**：销毁执行前置 reserved_qty==0，与使用预占互斥；两单并发时锁内复核必然一单失败。
- **使用 vs 转出并发**：转出前置 reserved_qty==0；使用执行复核预占仍在。与预占互斥保证两单并发恰好一单成功。
- **单一写路径**：current_qty / reserved_qty 的变更代码仅存在于 登记入库 / confirm_stock / execute_usage / execute_disposal / transfer_out / adjust_stock 六个系统方法 + 驳回释放，DocType 层拦截用户手工编辑（permissions + validate 双保险）。
- **账实一致**：Stock Log 流水累计 + 0 = current_qty；留样台账报表提供"流水对账"校验列，不一致标红（运维兜底）。
