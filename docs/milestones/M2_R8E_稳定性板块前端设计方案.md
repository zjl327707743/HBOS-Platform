## 1. 设计目标

稳定性板块前端按现有 HBOS LIMS 的桌面信息架构设计，优先解决三类使用问题：

1. 让 QA / QC / 稳定性管理员一眼看到时间点、检测和报告的风险分布。
2. 让操作人员围绕“通知/方案 → 入箱 → 时间点 → 结果 → 报告”连续工作，减少跨页面查找。
3. 让延期、结果修订、显著变化、冻结快照、SoD 和审计状态在界面上可见，但不把前端提示误当成后端校验。

## 3. 信息架构

稳定性模块挂载在现有 `海滨 LIMS` 工作台下，沿用左侧分组导航。原型先覆盖方案第十节建议的 7 个视图：

| 视图 | 页面名称 | 主要用户 | 核心任务 |
| --- | --- | --- | --- |
| 1 | 稳定性工作台总览 | QA / QC / Manager | 看风险、看待办、定位临近时间点 |
| 2 | 考察申请与方案 | QA / QP / Manager | 维护通知单、方案、批次、条件和重点项目 |
| 3 | 样品入箱与台账 | 稳定性管理员 / QC | 入箱、标签、库存和样品流水追踪 |
| 4 | 取样与检测计划 | 稳定性管理员 / QC | 月度时间点、计划日期、实际日期、延期审批 |
| 5 | 结果录入与趋势 | QC / Reviewer / QA | 录入结果、显著变化依据、趋势查看、评估倒计时 |
| 6 | 报告与有效期 | QA / QP | 报告审核批准、版本链、外推建议和 QA 判定 |
| 7 | 变更 / 稳定性室 / 设备 | QA / Manager / 设备管理员 | 变更实施、温湿度记录、设备故障和影响样品 |

## 4. 统一页面骨架

### 4.1 桌面端

- 左侧导航宽度与既有 LIMS 原型保持一致，稳定性模块使用青绿色主色，风险状态使用语义色。
- 顶部保留面包屑、全局搜索、通知、当前用户和角色。
- 内容区采用“页面标题 + 业务状态条 + 筛选/动作栏 + 主工作区”的固定节奏。
- 表格默认密度偏紧，首列为业务编号，最后一列为动作；关键字段使用等宽字体便于追踪。
- 详情优先使用右侧抽屉，不打断当前台账上下文；需要长流程时再进入完整页面。

### 4.2 移动端

- 侧栏收缩为图标栏，筛选区可横向滚动，表格改为卡片化摘要 + 横向滚动明细。
- 时间点卡片保留“计划日 / 有效截止日 / 状态 / 当前动作”四个字段。
- 结果录入和审批按钮固定在底部操作区，避免长表单中丢失主动作。

## 5. 关键交互设计

### 5.1 状态与风险表达

状态颜色只表达业务语义，不代表权限：

| 语义 | 颜色 | 示例 |
| --- | --- | --- |
| 已批准 / 已完成 | 绿色 | 已批准、报告已批准、在箱 |
| 进行中 / 检测中 | 青绿色 | 方案执行中、检测中、待审核 |
| 待处理 / 临近 | 琥珀色 | 待取样、3 日内到期、延期审批中 |
| 风险 / 逾期 / OOS 候选 | 红色 | 逾期派生、显著变化候选、设备超限 |
| 草稿 / 已取消 / 只读 | 灰色 | 草稿、已作废、冻结快照 |

“逾期”前端显示为由日期派生的风险提示；“延期审批中”是独立流程状态，不能覆盖或伪装成已延期。

### 5.2 期限三层模型

时间点和计划台账统一展示三列日期：

- **计划检测日** `planned_due_date`
- **有效截止日** `effective_due_date`
- **政策硬上限** `policy_latest_due_date`

延期抽屉显示完整日期链：`planned ≤ requested ≤ approved ≤ policy_latest`。缺少批准日期时，只显示申请中，不直接改变有效截止日。

### 5.3 结果版本和快照

- 结果列表默认只展示当前生效结果；修订链在详情抽屉展开。
- 草稿/待复核版本显示“在途版本”，旧版仍标记“当前生效”。
- 规格、方法、条件和限度采用“冻结快照”标签；界面提供来源版本，但不允许从结果页直接编辑。
- `is_current`、`current_result` 和版本切换由受控业务方法完成，原型只展示结果。

### 5.4 SoD 和操作签名

- 动作按钮旁展示当前角色和下一签署角色。
- 不符合 SoD 时按钮进入禁用态并提供原因提示；后端仍需再次校验。
- 原型采用“操作签名 + 审计追踪”表达，不宣称 GMP 合规电子签名。

## 6. 七个视图的页面方案

### 6.1 稳定性工作台总览

首屏提供 4 个 KPI：待取样时间点、检测中、待复核报告、临近/逾期。下方为时间点执行趋势、风险清单和近期时间点台账。

首屏主动作：`新建考察通知`、`打开本周计划`、`查看待复核`。启动门禁提示固定在页面顶部，当前原型显示“5 项待确认”，避免用户误以为可以进入 R8A 实施。

### 6.2 考察申请与方案

采用左侧单据列表 + 右侧详情摘要布局。列表支持单据类型、状态、产品、负责人筛选；详情显示状态流、批次、储存条件、重点项目和冻结版本。批准前允许编辑，批准后改为版本化入口。

### 6.3 样品入箱与台账

以库存台账为主：样品编号、产品/批号、条件、房间、入箱日期、当前状态、剩余数量。入箱动作完成后可打印标签；入箱超过生产 1 个月不直接显示“拒绝”，而显示“强制评估”提醒。

### 6.4 取样与检测计划

默认打开月度看板，支持月份切换、条件筛选和计划/实际日期切换。台账行必须同时显示计划日期、有效截止日、延期状态和检测窗口。延期申请使用独立抽屉，申请与批准不合并为一个按钮。

### 6.5 结果录入与趋势

采用“左侧时间点列表 + 中部结果表单 + 右侧趋势摘要”三栏结构。结果表单显示结果版本、当前生效指针、限度冻结快照、显著变化规则、基线和 5 个工作日评估倒计时。

趋势图只绘制当前生效结果；未批准的新版本使用虚线预览并带“在途，不影响当前生效值”说明。原型不计算统计控制限。

### 6.6 报告与有效期

采用报告列表 + 报告摘要 + 外推助手面板。外推助手只给出建议区间、依据和缺失信息，不自动写入有效期；QA 判定是明确的独立动作。

### 6.7 变更 / 稳定性室 / 设备

页面内使用三个轻量级标签页：变更实施、温湿度记录、设备与故障。故障详情能关联受影响房间、样品和时间点；温湿度记录对超限和缺卡做语义标记，但本板块不做自动采集。

## 7. 原型交互清单

- 左侧 7 个视图切换，刷新后保留当前 hash 路由。
- 表格行可打开右侧详情抽屉，动作按钮给出状态化提示。
- 月度计划支持上月/下月切换、看板与台账切换。
- 结果页支持项目切换、在途版本提示和趋势点查看。
- 报告页支持外推建议展开、QA 判定按钮和版本链抽屉。
- 移动端在 390px 宽度下保持可读，关键按钮不溢出。

## 8. 后续 Vue 复刻建议

原型经 Owner 审查后，建议按以下顺序进入实现：

1. 先复刻稳定性工作台、计划看板和样品台账，建立 `get_stability_ledger` 只读聚合查询。
2. 再复刻结果录入与趋势，建立 `get_stability_trend` 只读聚合查询，动作全部调用业务方法。
3. 最后复刻报告、变更、稳定性室和设备页面，并补齐错误态、空态、权限态和审计态。
4. 仅在 R8A 启动门禁 11.3 的 5 个未闭环事项完成且 Owner 审查通过后，进入 DocType 和后端实现。

## 9. 验收要点

- 视觉：与现有 LIMS 的导航、表格、按钮、抽屉和语义色保持一致。
- 业务：7 个视图覆盖方案第十节规划，不遗漏延期、结果版本、报告 QA 判定和设备风险。
- 合规：不把逾期派生、操作签名或前端禁用当成后端权限和状态机实现。
- 数据：只使用 `TEST-HBOS-M2-STB-*` 演示数据，不出现真实客户、批号、人员或设备数据。
- 工程：本轮只交付设计文档、HTML 原型和截图，不进入 Vue 生产工程，不同步生产 `/hbos-lims`。
