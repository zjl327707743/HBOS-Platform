## 2. 完整政策与事实同事务检查

锁顺序沿用关系服务：relations-v1 根锁 → 当前政策头及其固定修订 → 固定来源范围 / 事实历史。原生政策仓储要求精确 Site / 数据库 SHA256、InnoDB、REPEATABLE-READ 和同一根锁能力。使用当前头，不缓存许可、不挑历史 active 版本；撤销政策即使有旧成功收据也不能继续重放。

服务先完成严格请求字段解析，再根据可信当前主记录、不可变修订及锁定来源生成上下文，包含旧 / 新岗位或任职、实际管理人、公司 / 部门、人员范围、受益 User、有效期与当前时点。完整单条规则必须独立满足操作、岗位范围、人员范围和任职截止；不能跨规则 / 政策拼接，有限政策不能创建无限期任职。批准仍须精确服务端清单与当前修订一致，主体及批准 User 当前启用；Administrator / HR / 业务角色不自动放行。

来源解析后第一次核对；锁定所需原生来源并重新加载政策 / 来源后第二次核对，来源摘要及政策匹配必须一致。事实、修订和收据写入后，以新时点和当前政策再次检查；过期 / generation 变化等失败由原保存点回滚三类写入。服务不自行 commit，结果仍 transaction_pending=true、runtime_verified=false、authorization_effect=none，没有业务 Grant。

**最后一次服务内检查不等于提交前闭环。**外层收到 pending 后延迟提交时的过期、真实 before_commit / 最终来源重验、提交失败及提交结果未知，仍需 HTTP 整请求事务边界实现。MG19 保持 PARTIAL。

## 3. 来源失效后的可靠历史收窄

前序实时来源解析会拒绝停用部门，旧历史也没有明确保存 Employee 当时的公司 / 部门，不能仅从来源指纹推断归属。本段每个新受控修订保存 management_scope_v1，绑定精确 Site、provider、事实类型 / UUID / 修订 / 确定性修订键、原公司 / 部门、人员 ID / 公司 / 部门、旧受益 User，以及受保护岗位修订 / generation。

完整 source_evidence_json 的摘要写入历史 snapshot 内的 _management_evidence_digest，再由原有 content_digest 绑定该 snapshot。读取时核验确定性键、主表 / 历史一致性、版本、摘要、明确范围与岗位历史。篡改来源证据而保持旧 snapshot 会拒绝。历史 proof 只能由服务端仓储生成，客户端额外字段拒绝。

历史路径仅允许保持稳定事实身份的严格收窄。任职只能在原人员、岗位、旧受益 User、开始时间与主岗事实下缩短期限或降低状态；不能把结束 / 撤销与延期、恢复或换绑组合。岗位只能在原公司 / 部门 / 标题 / Designation 下降低状态，不能借清理同时改名。仍须当前有效完整管理政策匹配原历史范围，管理人和批准人不能失效。

因此离职、User 停用、Employee 换绑 / 转部门 / 消失、组织停用或岗位失效后，可按可验证历史撤销原任职；新 User 不继承旧关系，也不将范围迁到当前部门。缺失历史、旧版本缺 management_scope_v1 或篡改证据时关闭该路径，不自动补造或迁移历史。通用实时来源适配器的严格规则没有放宽。

MG20 的上述离线及指定原生场景通过；HTTP 入口和完整独立连接来源生命周期仍未覆盖，整项保持 PARTIAL。

## 4. 同键重放与落库兼容修复

同键首先核对请求摘要，再读取原命令对应的不可变 after 修订；更新命令同时读取原 expected_revision 的 before 修订。后续已有新修订时，原 before / after 仍用于原命令判定，当前主记录另验稳定身份，不能用更新后的当前记录假充旧事实。每次重放重新核对实际管理人、当前政策和来源；返回原 record_id / revision 且不追加写入。撤销政策后旧成功收据仍拒绝。

真实首轮验收发现产品适配缺陷：完整管理匹配 JSON 写入既有 policy_ref Data 字段，超过默认 140 字容量；Frappe 拒绝落库。修复为 management-match-v1: 加完整匹配的 SHA256（固定 84 字符），完整 policy_id / revision / generation / rule_id / approval_ref / policy_digest 保留在 source_evidence.management_match 中，并受历史 snapshot 摘要绑定。没有截断证据、改表或绕过原生长度校验。

新增正式回归使用各 140 字符的 rule_id / approval_ref，读取两类实际修订 DocType JSON 核对 Data 容量，验证完整证据、精确摘要与历史锚。该缺陷已修复，首轮失败保留在机器证据中。
