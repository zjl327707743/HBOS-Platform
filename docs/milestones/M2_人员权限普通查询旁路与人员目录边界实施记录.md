## 1. 域和边界

八类 HBOS 岗位、任职、事实修订、命令收据、写锁、管理政策及政策修订只能由受控仓储与服务维护 / 最小投影读取。新 read / lookup 政策不以 Administrator、System Manager、原生角色、共享或客户端 flags 补足。四个固定管理 GET、四个 POST 的默认关闭绑定、当前完整政策 / 来源及提交 / 返回前复核保持前序实现，本轮不安装生产包装。

原生 User / Employee / Department / Designation / Role 目录属于 ERP/HR 原生权限域，不能全球换成 HBOS 管理政策。people_access 显式输出 authorization_domain=native_personnel、management_policy_applied=false，仍 read_only=true、position_authorization_connected=false。它不读取本段关系 / 政策存储，不把账号角色当作岗位 Grant，也不能宣称等同管理 lookup 的人员范围。

## 2. 普通入口的明确拒绝

新增 native_read_boundary.py，并通过 Hook 精确注册八类 has_permission / permission_query_conditions、before_request；两个受保护模型基类使用 NativeReadProtectedDocument。固定拒绝消息不带目标、人员、政策或 SQL。普通 HTTP 采用原生 PermissionError 403，无统一管理 API 成功数据；目录错误沿用既有 HTTP 200 内 INVALID_REQUEST 的 Portal 契约。

| 入口 | 本段处理 |
| --- | --- |
| REST v1 / 显式 v1 resource、v2 document / doctype / controller RPC | 目标八类集合、记录、count、copy、meta、method 以及写入口统一拒绝 |
| client、reportview、form.load、search、export / template、Desk / app | 原生方法与路径的目标、fields、filters、嵌套文档显式分类；读 / 统计 / 搜索 / 导出均拒绝 |
| save / insert、savedocs、run_doc_method / legacy cmd | JSON / dict / list 文档同样拒绝；识别 v1 路径后缀、v2 特殊路由和短名 run_doc_method；runserverobj 仅保守分类，未宣称实际合法分派 |
| 原生 Query Report / Custom Report | 服务端只读固定 Report.ref_doctype / report_type / reference_report，保护引用链最多八步；缺失、异常、循环、超深拒绝，不执行 Report SQL |
| 原生模型 / 共享 | has_permission / check_permission 在原生 Administrator / ignore_permissions 之前拒绝；permission_query_conditions 抛异常以避开共享 OR 条件；HTTP 共享分支在 dispatch 前拒绝 |

客户端分类不执行表达式、SQL 或任意方法。嵌套深度12、节点1024、字符串65536上限，已识别原生入口畸形输入拒绝；普通参数文字恰好等于保护 DocType 名称也会保守拒绝。批次混合保护 / 非保护请求不返回部分保护数据。非目标 ERP/HR、自定义固定受控入口继续各自边界。

原仓储实际使用 ORM insert/save，不能全部拒绝 create/write。只有 is_controlled_write 的私有 ContextVar 精确 doctype / key 能力才允许这两种模型权限；已有 name 必须与 record_key 一致，插入命名前仅精确 record_key 可作未来 name。read/select/report/export/share/delete/rename 即使在该能力内也不允许。客户端 ignore_permissions、Administrator 及伪造 flags 不生成能力；既有记录验证与不可变修订保护仍执行。

## 3. 人员目录输入修复

非空 phone（去首尾空白后）INVALID_REQUEST，get_list/count 零调用；空/None/空白保持原列表兼容。原手机号仍仅脱敏展示；不是对所有原生 REST / ERP 电话字段执行新的全局隐私策略。此前脱敏展示结合 LIKE 过滤可被用作号码探测，本段关闭这一筛选通道。
