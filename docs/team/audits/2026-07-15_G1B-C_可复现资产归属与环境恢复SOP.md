## 3. G1B-B 运行态偏差记录

### 3.1 偏差发现

G1B-B 报告第 4.4 节记录了 `nginx -s reload` 操作，但将其描述为「标准的 Nginx 运维操作，不修改 Compose 配置，不修改 Nginx 配置，不属于禁止操作」。

**本轮审查发现：该操作超出了 G1B-B 原始允许范围。** G1B-B 的边界是「按依赖顺序启动已退出容器，验证全服务恢复」。`nginx -s reload` 属于对运行中容器的主动干预，是必需的恢复动作，但应在报告中被明确标记为**执行偏差**。

### 3.2 正式偏差记录

| 偏差项 | 详情 |
|--------|------|
| **操作** | `nginx -s reload`（在 frontend 容器内执行） |
| **触发条件** | Redis、Worker 和 WebSocket 恢复后，HTTP 仍返回 502 |
| **证据** | frontend 容器（Nginx）的 DNS 缓存仍指向 backend 旧 IP 地址 |
| **操作性质** | 运行态重载——未修改 Nginx 配置文件、未重建 frontend 容器、未修改 Compose、未写数据库 |
| **执行前后对比** | 执行前 HTTP 502 → 执行后 HTTP 200 |
| **偏差类型** | 本轮原始允许操作列表之外的**必要恢复动作** |
| **影响评估** | 不影响最终数据和源码完整性。属于运行态恢复的合理补充操作。 |

| Property Setter name | doc_type | property | 与 HBOS 代码的关联 |

**非阻塞结论：** 空白 Site 执行 `install-app hb_attendance_app` + `migrate` 后，所有 HBOS 配置资产（Custom Field、Workspace、Desktop Icon、Sidebar、Report 等）均应自动出现。员工数据、考勤数据、导入日志和附件属于业务数据，需要通过数据库备份恢复，不应代码化到 Git。

**阻塞项：** Owner 需要提供 `.env` 文件（含数据库密码等 Secret），这是安全凭证，不能放在 Git 中。正确的流程是 `.env.example` 提供模板，Owner 通过安全渠道传递实际值。

### 9.5 Nginx reload 使用条件
