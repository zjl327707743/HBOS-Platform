## 12. Property Setter 验证

### 12.1 结果

| Property Setter | 状态 |
|---|---|
| HBOS Attendance Import Log-naming_series-default | **MISSING** |
| HBOS Attendance Import Log-naming_series-options | **MISSING** |

### 12.2 空白 Site 总数

```text
Property Setter 总数 = 186
```

正式环境 = 188，空白 Site = 186。差异 = 2 条 HBOS 相关 Property Setter。

### 12.3 分析

G1B-C 报告的结论是「2 条 Property Setter 会由 Frappe 保存 DocType 时自动生成，属于 DocType JSON 的隐式覆盖」。

**本轮实证结果：** 这 2 条 Property Setter 在空白 Site 中**没有自动出现**。原因是：

- Property Setter 是在 Frappe UI 中保存 DocType 表单时由系统自动生成的运行时记录
- `install-app` + `migrate` 流程中，DocType JSON 被加载并创建了数据库表，但未触发「保存 DocType 表单」这个 UI 操作
- 因此 2 条 naming_series 相关的 Property Setter 没有生成

### 12.4 影响评估

| 影响维度 | 评估 |
|----------|------|
| HBOS 功能是否正常 | **是**——DocType JSON 中的 `fields[0].default` 和 `fields[0].options` 已经定义了相同的值 |
| 新 Site 是否可正常使用 | **是**——naming_series 行为由 DocType JSON 字段定义驱动 |
| Property Setter 缺失是否阻塞 | **否**——这 2 条是运行时镜像，不是独立配置 |

### 12.5 结论

G1B-C 报告中「Property Setter 不构成独立配置缺口」的结论**原则正确**，但「会自动生成」的表述需要修正为：

> 2 条 Property Setter 不会在 `install-app` + `migrate` 流程中自动生成。它们仅在 UI 中保存 DocType 表单时由 Frappe 系统创建。DocType JSON 中的字段定义已提供等效功能，缺失这 2 条 Property Setter 不影响系统正常运行。
