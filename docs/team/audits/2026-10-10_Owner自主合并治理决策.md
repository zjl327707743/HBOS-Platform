# HBOS Owner 自主合并治理决策（2026-10-10）

## 决策及过渡说明

项目 Owner 明确选择自 2026-10-10 起对 `feature/hbos-portal-product` 采用 **Owner 自主合并**，以减少日常低中风险、隔离候选迭代的非必要人工等待。本决定不宣称不存在既有审批规范：此前 `CONTRIBUTING.md` 与 `10_团队日常开发SOP.md` 要求非作者 GitHub Approve，本次通过单独的治理 PR 修订该书面规范。治理 PR 作为过渡案件，由 Owner 的明确指令授权合并，保留独立审查记录和 CI 证据；不虚构非作者 Approve 或 GitHub 自动门禁。

## 适用范围与共同门禁

- 仅 `feature/hbos-portal-product` 的低中风险、未开放真实数据/模型分发的代码集成，可由 Owner 本人以 Squash Merge 合并本人 PR。
- 每次仍需独立技术审查、关闭阻断项、明确 Owner 当轮决定、最新 HEAD/BASE 核对、CI 成功、差异和敏感材料检查、PR 讨论闭环以及合并审计。
- `main` 继续要求非作者正式 Approve 和现有 Ruleset；正式 IAM、登录会话、敏感数据导出、关键业务写入、授权门禁削弱、数据库迁移和生产发布等高风险变更不受该例外覆盖。
- AI 技术复审通过 **不等同** GitHub 的 `Approve`；未收到审核不得写成已批准。旧 Reviewer 请求可保留为可选，也可在记录后移除。
- 代码合入产品分支不代表 P1 安装、部署、公司员工授权或真实模型、知识资料分发许可。

## 首个应用与边界

适用于 Twin V1 [PR #31](https://github.com/zjl327707743/HBOS-Platform/pull/31)，获准候选 `a38345ed8808a53f199bcdf580068d31f7ec866e`（tree `286c9f575f0269122cca4ee6a1371bfa3e43aef4`），原产品基线 `72e5b1728981b7ef102a2c9ee033ce0452c400e7`。该候选已完成独立 R01 复审及三项 CI；合并仅接收已审 Twin V1 代码，真实模型仍属于私有合成评审范围，候选工程映射不因此升级为已核实物。

本治理决策实施后，PR #31 的新产品 BASE 必须重查，与治理增量形成的试合并 tree、CI 及合并范围一致才可执行 Squash Merge。旧试合并 tree 不得冒充新产品版本结果。

## 来源分支保留

仓库 `delete_branch_on_merge=true` 且产品来源分支可能没有删除保护。Twin 来源分支 `feature/twin-experience-v1` 被 Owner 要求保留；合并前必须建立指向冻结候选 HEAD 的安全留存引用。若自动删除原来源 ref，应从同 SHA 安全恢复并核验；不可仅因 GitHub 试合并/旧工作区存在就宣称来源已保留。
