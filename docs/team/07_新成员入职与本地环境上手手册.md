## 1. 入职前准备（Owner 操作）

新成员正式上手之前，Owner 需要完成以下准备工作。**如果你是 Owner，请按顺序操作；如果你是新人，请确认 Owner 已完成这些步骤。**

### 1.1 添加 GitHub 协作者

HBOS 仓库是私有的，新成员需要获得访问权限：

1. 打开 https://github.com/zjl327707743/HBOS/settings/access
2. 点击 **"Add people"**，输入新成员的 GitHub 用户名
3. 选择角色为 **"Write"**（允许推送代码和创建分支）
4. 发送邀请，让新成员在邮箱中接受邀请

同时确认新成员拥有 **HRMS 仓库**的访问权限（HBOS 依赖 HRMS 应用）。

### 1.2 发送 .env 文件

`.env` 文件包含数据库密码、API 密钥等敏感配置，**不能提交到 Git 仓库**，必须通过安全渠道单独发送：

- 通过 **飞书私聊**发送 `.env` 文件
- 或者通过 **1Password / Bitwarden** 等密码管理器共享
- **不要**通过微信、邮件等不安全渠道发送

### 1.3 确认新成员电脑要求

| 要求 | 最低配置 |
|------|----------|
| 操作系统 | macOS 12+ / Windows 10+ (WSL2) / Ubuntu 20.04+ |
| 内存 | 16 GB（Docker 至少需要 8 GB） |
| 硬盘 | 剩余 30 GB 以上 |
| 网络 | 能稳定访问 GitHub 和 Docker Hub |

> **提示**：本项目开发环境使用 Docker，无需手动安装 MariaDB、Redis 等中间件，Docker 会统一管理。

## 2. 第一天：环境搭建

环境搭建分为 6 步，按顺序执行即可。**不要跳过任何一步**，每一步完成后确认结果再继续。

### 2.1 安装必要软件

#### macOS 用户

```bash
# 1. 安装 Homebrew（如果还没有）
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 2. 安装 Git
brew install git

# 3. 安装 Docker Desktop
# 从官网下载：https://www.docker.com/products/docker-desktop/
# 安装后打开 Docker Desktop，等待 Docker 引擎启动完成（菜单栏图标变绿）
```

#### Windows 用户

1. 安装 **WSL2**（Windows Subsystem for Linux 2）
   - 参考官方文档：https://learn.microsoft.com/zh-cn/windows/wsl/install
2. 安装 **Docker Desktop**，并在设置中启用 WSL2 集成
3. 安装 **Git for Windows**：https://git-scm.com/download/win

> **确认 Docker 安装成功**：在终端运行 `docker --version` 和 `docker compose version`，看到版本号即表示安装成功。

### 2.2 获取代码

```bash
# 1. 创建项目目录
mkdir -p ~/Projects
cd ~/Projects

# 2. 克隆 HBOS 主仓库
git clone https://github.com/zjl327707743/HBOS.git
cd HBOS

# 3. 克隆 HRMS 应用到运行时目录
#    HRMS 来自 Frappe 官方仓库（frappe/hrms），version-16 分支
git clone https://github.com/frappe/hrms.git runtime/apps/hrms
cd runtime/apps/hrms
# 切换到项目版本矩阵指定的固定 commit（当前为 v16.12.0）
git checkout v16.12.0
cd ../../..
```

> **注意**：`runtime/apps/hrms` 这个路径是固定的，不能放在别的位置。Docker 容器会从这个路径加载 HRMS 应用。
>
> **版本锁定**：`v16.12.0` 是当前项目版本矩阵指定的 HRMS 版本。`version-16` 是维护分支名，用于获取更新但不用于锁定版本。新成员首次搭建时，应以项目版本矩阵（`docs/team/templates/VERSION_MATRIX.md`）中记录的 commit 或 tag 为准，而不是使用浮动分支。

### 2.3 配置 .env 文件

将 Owner 发给你的 `.env` 文件放到项目根目录：

```bash
# 假设 Owner 发给了你 .env 文件，把它放到项目根目录
mv ~/Downloads/.env ~/Projects/HBOS/.env

# 检查文件是否存在
ls -la ~/Projects/HBOS/.env
```

> **安全提醒**：`.env` 文件已经在 `.gitignore` 中，不会被提交到 Git。**不要**把这个文件分享给任何人，也不要通过任何渠道传播。

### 2.4 启动 Docker 容器

```bash
cd ~/Projects/HBOS

# 启动所有服务（首次启动会拉取镜像，可能需要 5-10 分钟）
docker compose up -d

# 查看容器状态，确认 9 个容器都在运行
docker compose ps
```

正常的输出应该显示 9 个容器（具体容器名取决于 Compose 项目名和副本编号），状态均为 `running`（或 `Up`）。Compose 服务列表如下：

| Compose 服务名 | 用途 |
|---------------|------|
| `frontend` | Web 前端（Nginx） |
| `backend` | Frappe 后端（Python） |
| `scheduler` | 后台任务调度 |
| `queue-short` | 短任务执行 |
| `queue-long` | 长任务执行 |
| `db` | MariaDB 数据库 |
| `redis-cache` | Redis 缓存 |
| `redis-queue` | Redis 消息队列 |
| `websocket` | WebSocket 实时通信 |
| `configurator` | 配置初始化（一次性） |
| `create-site` | 站点初始化（一次性） |

> **注意**：上表是 Compose 服务名（在 `docker compose exec <服务名>` 中使用）。实际容器实例名会加上项目名前缀和副本编号（如 `hbos-m0-r3a-backend-1`），根据当前环境的 `COMPOSE_PROJECT_NAME` 决定，每次部署可能不同。日常操作应优先使用服务名，不要记忆容器实例名。 |

如果某些容器没有启动，查看日志排查原因：

```bash
docker compose logs <容器名>
```

### 2.5 初始化应用

容器启动后，还需要安装应用和站点数据：

```bash
# 1. 进入 backend 容器
docker compose exec backend bash

# 2. 在容器内安装 HRMS 应用（如果尚未安装）
bench get-app hrms --resolve-deps
bench --site frontend install-app hrms

# 3. 安装自定义考勤应用
bench --site frontend install-app hb_attendance_app

# 4. 运行迁移，确保数据库表结构是最新的
bench --site frontend migrate

# 5. 重新构建前端资源
bench build

# 6. 退出容器
exit
```

> **说明**：`hb_attendance_app` 是项目的自定义应用，包含自定义 DocType（`hbos_attendance_import_log`）、自定义 Workspace（海滨考勤工作台）、3 个报表和 1 个页面。安装后会自动创建这些内容。

### 2.6 验证环境

在浏览器中打开以下地址，确认一切正常：

| 地址 | 预期结果 |
|------|----------|
| http://localhost:8081/login | 看到 Frappe 登录页面 |
| http://localhost:8081/desk | 登录后进入 Desk 主界面 |

**登录凭据**：

- 用户名：请向 Owner 索取开发环境的账号和密码
- 默认管理员通常是 `Administrator`，密码在 `.env` 文件中或由 Owner 提供

登录后，你应该能看到：

- 左侧边栏的模块列表
- **"海滨考勤工作台"** Workspace（表示自定义应用安装成功）
- 顶部搜索栏可以搜索 DocType

登录 http://localhost:8081/desk 后，花 15-20 分钟熟悉界面：

### 3.3 理解项目结构

```
HBOS/
├── .env                    # 环境变量配置（不提交到 Git）
├── docker-compose.yml      # Docker 服务编排
├── Dockerfile              # 后端镜像构建文件
├── nginx/                  # Nginx 前端容器配置
├── runtime/                # 运行时目录
│   └── apps/
│       ├── hrms/           # Frappe HR 定制版
│       └── hb_attendance_app/  # 自定义考勤应用
├── sites/

```

**关键概念速查**：

| 概念 | 说明 |
|------|------|
| Frappe Framework | 底层全栈框架，提供 ORM、权限、REST API、Web 界面等 |
| ERPNext | 基于 Frappe 的 ERP 系统，提供财务、库存、HR 等模块 |

| DocType | Frappe 的数据模型，类比数据库表 + 表单 + 权限配置 |
| Workspace | 自定义工作台页面，组织快捷方式和卡片 |
| Bench | Frappe 的 CLI 管理工具，用于安装应用、迁移、构建等 |
| Site | Frappe 的站点实例，一个数据库对应一个 site |

## 4. 第一次修改完整演练

这是你最重要的上手练习。跟着步骤完成一次完整的"修改 -> 提交 -> PR"流程，你就能掌握团队的日常工作方式。

### 场景假设

我们做一个最小的改动来熟悉流程：**在自定义考勤应用的 Workspace 描述中加上你的名字，证明你成功完成了环境搭建**。

### 4.1 创建功能分支

```bash
cd ~/Projects/HBOS

# 确保从最新的 main 分支开始
git checkout main
git pull origin main

# 创建你的功能分支（用你的名字拼音替换 yourname）
git checkout -b feat/yourname-onboarding-test
```

### 4.2 做一个小的代码修改

打开 `runtime/apps/hb_attendance_app/hb_attendance_app/workspace/海滨考勤工作台/` 目录下的 Workspace JSON 文件，在描述字段中加上你的信息。

如果你不确定具体改哪个文件，可以先找一个简单的文件来修改。比如，可以在 `runtime/apps/hb_attendance_app/hb_attendance_app/hooks.py` 中加一行注释：

```python
# 在文件顶部或合适的位置添加
# 团队成员：<你的名字> - 环境搭建完成
```

### 4.3 验证修改

修改完成后，重启后端让改动生效：

```bash
# 进入容器
docker compose exec backend bash

# 重新构建
bench build

# 退出容器
exit
```

然后刷新浏览器 http://localhost:8081/desk，确认你的修改已经生效。

### 4.4 提交代码

```bash
cd ~/Projects/HBOS

# 查看修改了哪些文件
git status

# 添加修改
git add apps/hb_attendance_app/

# 提交（遵循 conventional commits 格式）
git commit -m "feat: add onboarding test comment"

# 推送到远程仓库
git push -u origin feat/yourname-onboarding-test
```

### 4.5 创建 Pull Request

1. 打开 https://github.com/zjl327707743/HBOS
2. GitHub 通常会在页面顶部提示你刚推送了新分支，点击 **"Compare & pull request"**
3. 如果没有提示，点击 **"Pull requests"** -> **"New pull request"**
4. `base` 选择 `main`，`compare` 选择你的分支
5. 填写 PR 标题和描述：
   - **标题**：`feat: onboarding test - <你的名字>`
   - **描述**：简要说明这是入职测试 PR，验证环境搭建和开发流程
6. 点击 **"Create pull request"**

### 4.6 代码审查与合并

1. 通知 Owner 来 Review 你的 PR
2. Owner 会在 PR 页面进行 Review，可能会提出修改建议
3. 如果有修改建议，在本地修改后再次提交，PR 会自动更新
4. Review 通过后，Owner 会合并 PR 到 `main` 分支
5. 合并后，删除你的功能分支：

```bash
git checkout main
git pull origin main
git branch -d feat/yourname-onboarding-test
```

> **恭喜！** 你已经完成了 HBOS 项目的第一次代码贡献。这个流程就是团队日常开发的标准流程。

## 5. 常用操作速查

把这一节放在手边，日常开发会经常用到。

### 5.1 启动和停止服务

```bash
# 停止所有服务（保留容器和数据）
docker compose stop

# 停止并删除容器（数据保留在 Volume 中）
# ⚠️ 注意：docker compose down 会删除容器和网络，但保留 Volume 数据
# 🔴 禁止：docker compose down -v 会删除所有 Volume，数据库会永久丢失！
docker compose down
```

### 5.2 进入容器

```bash
# 进入后端容器（最常用）
docker compose exec backend bash

# 进入数据库容器
docker compose exec db bash

# 进入 Redis 容器
docker compose exec redis-cache bash
```

### 5.3 查看日志

```bash
# 查看所有容器日志
docker compose logs

# 查看后端日志并实时跟踪
docker compose logs -f backend

# 查看最近 100 行日志
docker compose logs --tail=100 backend

# 查看 worker 日志（调试后台任务时很有用）
docker compose logs -f queue-short
docker compose logs -f queue-long
```

### 5.4 常用的 Bench 命令

Bench 是 Frappe 的命令行管理工具，需要在容器内运行：

```bash
# 先进入容器
docker compose exec backend bash

# 启动开发服务器（支持热重载）
bench start

# 数据库迁移
bench --site frontend migrate

# 重新构建前端资源（修改 JS/CSS 后需要运行）
bench build

# 安装新应用
bench --site frontend install-app <app_name>

# 创建新的 DocType
bench new-doc <app_name> <doctype_name>

# 运行测试
bench --site frontend run-tests --app hb_attendance_app

# 查看所有已安装的应用
bench --site frontend list-apps

# 进入 Frappe 控制台（类似 Django shell）
bench --site frontend console

# 备份数据库
bench --site frontend backup

# 恢复数据库
bench --site frontend restore <backup_file>

# 退出容器
exit
```

### 5.5 数据库操作

```bash
# 进入后端容器
docker compose exec backend bash

# 连接 MariaDB
bench --site frontend mariadb

# 常用 SQL 示例
# 查看所有表
SHOW TABLES;

# 查看 DocType 对应的表结构
# DocType 名称 "hbos_attendance_import_log" 对应的表名是 "tabhbos_attendance_import_log"
DESC tabhbos_attendance_import_log;

# 退出 MariaDB
EXIT;
```

### 5.6 运行测试

```bash
# 进入容器
docker compose exec backend bash

# 运行指定应用的测试
bench --site frontend run-tests --app hb_attendance_app

# 运行指定模块的测试
bench --site frontend run-tests --app hb_attendance_app --module hb_attendance_app.tests

# 运行指定测试文件
bench --site frontend run-tests --app hb_attendance_app --doctype hbos_attendance_import_log
```

## 7. 常见问题

### 7.1 Docker 相关问题

**问题：`docker compose up -d` 失败，提示镜像拉取错误**

```bash
# 解决方案 1：配置 Docker 镜像加速器
# 在 Docker Desktop 设置 -> Docker Engine 中添加：
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me"
  ]
}

# 解决方案 2：使用代理
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
```

**问题：容器启动后立即退出**

```bash
# 查看退出的容器日志
docker compose logs <容器名>

# 常见原因：.env 文件缺失或配置错误
# 检查 .env 文件是否存在且内容完整
ls -la .env
```

**问题：Docker 占用磁盘空间过大**

```bash
# 清理未使用的镜像、容器和数据卷
docker system prune -a

# 仅清理未使用的数据卷
docker volume prune
```

### 7.2 端口冲突

**问题：启动时报错 "port is already allocated"**

```bash
# 查看哪些进程占用了 8081 端口
lsof -i :8081

# 如果端口被占用，可以修改 docker-compose.yml 中的端口映射
# 或者停止占用端口的进程
```

端口使用清单：

| 端口 | 服务 |
|------|------|
| 8081 | Web 前端（Nginx） |
| 3306 | MariaDB |
| 6379 | Redis 缓存 |
| 6380 | Redis 消息队列 |

### 7.3 登录失败

**问题：浏览器打开 http://localhost:8081/login 无法访问**

```bash
# 确认 Nginx 容器正在运行
docker compose ps frontend

# 确认 backend 容器正在运行
docker compose ps backend

# 如果容器都在运行，查看日志
docker compose logs frontend
docker compose logs backend
```

**问题：账号密码错误**

- 请向 Owner 确认开发环境的账号和密码
- 如果忘记密码，可以进入容器重置：

```bash
docker compose exec backend bash
bench --site frontend set-admin-password <新密码>
```

### 7.4 权限不足

**问题：`git push` 报 403 或权限拒绝**

```bash
# 确认已经接受 GitHub 协作者邀请
# 检查邮箱，搜索 "invited you to" 关键词

# 如果仍然失败，确认 SSH Key 配置正确
ssh -T git@github.com

# 或者改用 Personal Access Token 认证
# Settings -> Developer settings -> Personal access tokens -> Tokens (classic)
```

**问题：Docker 命令需要 sudo**

```bash
# 将当前用户加入 docker 组
sudo usermod -aG docker $USER

# 重新登录后生效
```

### 7.5 应用安装失败

**问题：`bench install-app` 报错**

```bash
# 常见原因 1：hooks 依赖未满足
# 检查 hooks.py 中的依赖项
cat runtime/apps/hb_attendance_app/hb_attendance_app/hooks.py

# 常见原因 2：数据库迁移冲突
# 强制迁移
bench --site frontend migrate --force

# 常见原因 3：应用路径不对
# 确认应用在正确的目录下
ls -la runtime/apps/hb_attendance_app/
```

### 7.6 修改代码后不生效

```bash
# 1. 进入容器
docker compose exec backend bash

# 2. 清除缓存
bench clear-cache

# 3. 重新构建前端资源
bench build

# 4. 如果修改的是 Python 代码
bench --site frontend migrate

# 5. 退出容器
exit

# 6. 重启后端容器
docker compose restart backend
```

## 8. 团队沟通

### 8.1 什么时候找 Owner

以下情况**直接找 Owner**，不要自己硬扛：

- 环境搭建超过 2 小时还搞不定
- `.env` 文件没收到或内容有问题
- GitHub 仓库访问不了（确认已接受邀请后）
- 登录后看不到"海滨考勤工作台"Workspace
- Docker 容器反复启动失败，自己排查超过 30 分钟
- 不确定某个功能该不该做、怎么做

### 8.2 什么时候先自查

以下情况**先自己查一查**，找不到答案再问：

- 某个 Frappe 框架 API 怎么用？ -> 先去 https://docs.frappe.io 查
- 某个 DocType 的字段含义？ -> 先去 Desk 里打开该 DocType 查看
- 代码报错了？ -> 先在 `docker compose logs backend` 里看完整错误信息
- 数据库表结构？ -> 先用 `bench --site frontend mariadb` 连上去看
- 之前有人做过类似的功能吗？ -> 先在 `git log` 里搜关键词

### 8.3 提问的艺术

问问题时，请提供以下信息，能帮助 Owner 更快地帮你解决问题：

1. **你正在做什么**（目标是什么）
2. **你执行了什么命令**（完整命令，不要只描述）
3. **完整的错误信息**（从日志里复制，不要截图）
4. **你已经尝试过什么**（排除已排查过的方向）

示例：

> 好的提问：
> "我在安装 hb_attendance_app 时遇到错误。执行的命令是 `bench --site frontend install-app hb_attendance_app`，报错信息是 `ModuleNotFoundError: No module named 'xxx'`。我已经确认应用在 `runtime/apps/hb_attendance_app/` 目录下，也跑了 `bench migrate`。请问可能是什么原因？"

> 不好的提问：
> "安装失败了，怎么办？"

### 8.4 利用 AI 辅助开发

在开发过程中，可以善用 AI 工具提高效率：

- **Claude Code**：本项目已配置了完整的开发规范（`.claude/` 目录），你可以直接让 Claude Code 帮你写代码、排查问题、解释代码逻辑
- **GitHub Copilot**：在 VS Code 中提供代码补全
- **ChatGPT / Claude**：用于理解 Frappe 框架概念、Python 语法问题等

> **注意**：AI 生成的代码提交前**必须 Review**，确保理解每一行代码的含义。不要把你不理解的代码提交到仓库。
