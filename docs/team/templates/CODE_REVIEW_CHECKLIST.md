# 代码审查检查清单

## 审查前（提交者）

- [ ] 代码已自测通过
- [ ] 测试已编写并全部通过
- [ ] 没有调试代码（console.log、print 等）
- [ ] 没有注释掉的大段代码
- [ ] Commit message 符合规范
- [ ] PR 描述完整
- [ ] 没有提交 .env、Secret、真实数据
- [ ] 没有提交 Excel、CSV 数据文件

## 审查中（Reviewer）

### 功能正确性

- [ ] 代码是否实现了 PR 描述中的功能
- [ ] 边界情况是否处理
- [ ] 错误处理是否完善
- [ ] 是否有潜在的空指针/空值问题

### 安全性

- [ ] 是否有硬编码的密钥或密码
- [ ] 用户输入是否经过验证
- [ ] 数据库查询是否使用参数化
- [ ] 敏感数据是否被记录到日志

### 代码质量

- [ ] 函数是否过长（>50 行需拆分）
- [ ] 文件是否过大（>800 行需拆分）
- [ ] 是否有深层嵌套（>4 层）
- [ ] 命名是否清晰
- [ ] 是否有重复代码

### 架构

- [ ] 是否修改了 Frappe/ERPNext/HRMS 核心源码
- [ ] 是否在正确的 App 中实现
- [ ] 是否使用了正确的扩展方式（Custom Field vs 直接修改）
- [ ] 数据库迁移是否正确

### 测试

- [ ] 新功能是否有测试
- [ ] 测试是否覆盖主要场景
- [ ] 测试是否可重复执行

### 文档

- [ ] 是否需要更新文档
- [ ] API 变更是否注明
- [ ] 数据库变更是否注明

## 审查结果

- [ ] 批准（Approve）— 无关键或高优先级问题
- [ ] 评论（Comment）— 有建议但不阻塞合并
- [ ] 请求修改（Request Changes）— 有必须修复的问题

## 特定检查项（Frappe 项目）

### DocType 变更

- [ ] 是否已导出为 JSON
- [ ] 是否在 fixtures 中配置
- [ ] 是否有对应的 Patch（如需要）
- [ ] 是否与现有 DocType 冲突

### Custom Field 变更

- [ ] 是否已导出为 Fixture
- [ ] 字段名是否使用小写+下划线
- [ ] 是否添加了合适的 Label

### Report 变更

- [ ] 是否包含 .json + .py + .js 三个文件
- [ ] 查询是否有性能问题
- [ ] 是否添加了权限过滤

### Workspace 变更

- [ ] 是否已导出为 JSON
- [ ] 是否在 hooks.py 中配置
- [ ] 链接和卡片是否正确
