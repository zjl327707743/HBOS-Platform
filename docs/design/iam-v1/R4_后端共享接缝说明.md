## 3. 原有 HR summary 与本人流必须分开

本轮实际读到的现行结构是：

- `portal/provider.py:22-23` → `portal/summary.py:60-65` → `page/hbos_attendance_dashboard/dashboard_data.py:get_data`。
- `dashboard_data.py:12` 要求 HR/管理角色；`:27-31` 全量 active Employee，`:36-47` 按日期 raw SQL 全量 Attendance，没有本人/部门授权约束。
- `portal/summary.py:13-57` 真实输入只使用 `anomaly_people/total_late/total_early/total_absent`，输出 DTO 是 `app_id/generated_at/status/metrics`，metric 项有 id/label/value/tone/deep_link。不能把旧聚合结果贴上“本人”标签。
- `portal/routes.py:5-6,26-29` 只把稳定路径映射到 `/app/hbos-attendance-dashboard`。因此仅增加 can_enter 会把员工送往旧 HR 入口；本候选 provider 路由适配也必须同步收窄。

已继续核对平台路由：`apps/hbos_portal/hbos_portal/services/routes.py:41-58,66-88` 接受应用前缀下稳定路径及同源绝对本地实现路径，`frontend/hbos-portal-web/src/services/businessNavigation.ts:13-14,47-49` 将 `/hbos/` 目标交给现有 SPA Router。因此新的本人 resolver 返回 `/hbos/attendance/me` 与现行平台路径契约兼容，不需要为这一同源路径另改平台 resolver；这只是源码兼容结论，运行 `NOT_RUN`。考勤自己的新 resolver 仍须白名单校验输入，不能把任意路径或 caller employee/department 参数原样带到本人服务。

候选没有猜测新的 dashboard payload，也没有把旧 get_data 改成接受一个 employee 参数就当权限成立。新本人 summary 必须从当前 session 求 Employee 后限制数据源，并满足已存在的 Portal SummaryDTO；不能先取全量再在浏览器过滤。旧 HR 流的保留范围及新本人流的能力边界由后端契约明确分开，不能使用 `legacy OR new` 作为宽松兜底。未安全实现的部门 summary/导出保持不可用。

## 4. 重要兼容限制与后续证据

1. 新初始密码只在受控领取时生成。OAuth `(user, created)`、重定向、header、普通安全资料、日志和审计都不承载口令；首次改密复用既有 reauthenticate/set_password。密码已修改的用户再次 OAuth 不得被重置。
2. `_write_password` 原有强度检查、锁、原生哈希、revoke、ticket invalidation、commit、login_as 均保留，只在最终成功后增加服务端 flags；既有 require_proof/MFA 逻辑未改。finalize hook 的实际 Frappe after_request 时序、事务与失败行为仍须锁定源码并隔离验证，不能靠此 diff 宣称原子性已完成。
3. Employee/Department 选择 before_validate 接缝，避免把关联保护只放在保存后；上游控制器/多个 App doc_events 的实际组合顺序、副作用、缓存及异常回滚仍按 A1 上游 pin 和 B 隔离实测确认。新增 IAM 自有 DocType 的控制器也须自行保护，不能只依赖这份共享 hook。
4. 原生 query/has_permission hook 不保护 raw SQL、get_all、ignore_permissions、脚本报表、导出和后台任务。#49/#42 当前未合入链路不在本 patch 夹带；旧全量报表对普通/受限主体必须保持拒绝，后续旁路清单需单独逐项验证。
5. 取消同步姓名兜底与游标兼容方案见 A1 证据文档；当前六文件候选未修改同步 api.py、未停调度、未重算或纠正历史。
6. 新状态/能力/关联服务缺失时本候选不能运行，禁止用静默 except/Mock/粗角色兜底让其看似通过。正式文件/模型白名单、字段、服务签名、限流/并发/审计和隔离来源统一写入唯一开工单。
7. 保持本六文件范围，不扩改 `services/bootstrap.py`。该文件 `:39-49` 当前仅返回身份/品牌/apps 元数据；`frontend/hbos-portal-web/src/stores/portal.ts:78-81` 随后自动请求 tasks、summaries 和 twin。B 的 request gate 必须逐方法拒绝临时态业务请求；Portal 的 post-bootstrap FirstPasswordGate 仅在重新确认状态后挂载业务 RouterView，ready 后才能允许业务刷新。允许 bootstrap 不等于允许它后续触发的业务 API。此最小允许列表、拒绝响应不含业务字段/总数、Gate 结算后的刷新与会话失效均为 B 必测项，不是已实现行为。
