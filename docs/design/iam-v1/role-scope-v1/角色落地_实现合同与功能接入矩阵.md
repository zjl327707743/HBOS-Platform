## 1. 角色来源与最小模型

选择**执行时读取不可变发布版本、事务内切换角色发布指针**。不向每位员工复制 allow Rule，不新建手工规则投影入口。每个请求先解析该员工关联，再读取对应角色的唯一当前 release，逐 operation 与其 scope_binding 成对求值。新角色发布后，两个引用者的下一请求读取同一新版本；草稿不参与求值。

考勤稳定键：`attendance/staff`、`attendance/clerk`、`attendance/admin`，与批准设计的三个键对应。中文标题可修改而不影响权限。上限分别为 SELF、具名 DEPARTMENT、具名 COMPANY，由服务器固定，草稿 API 不接收上限、管理边界或原生角色映射。

为未开户员工也能配置角色、准确预览，关联对象采用原生 **Employee / Department**，不以“已有 User”作为角色关联前提；业务执行仍由当前 Frappe Session 解析唯一有效 Employee，账号、身份关联和密码保持原有权威。此为原候选 User/Department 关联表的工程收敛，不建立第二套身份模型。

以下为拟新增 **3 个父 DocType + 2 个严格受控子表**，不是必须三张物理表。全部位于 `apps/hbos_portal/hbos_portal/hbos_portal/doctype/<snake_case>/`，module 为 HBOS Portal，原生 permissions 为空，禁止 rename、普通 REST 写、独立子表写和无来源导入。控制器复用 `guards.require_controlled_write()` 并单独检查 release 不可变。

`scope_ref` 由服务器将固定枚举映射至 Department/Company 做原生 Link 存在性验证，不把大写枚举误当 DocType，不新增任意对象类型。

Department 关联仅 DIRECT staff 或 NONE，不得默认 clerk/admin。Employee 不存在显式关联时按 FOLLOW_DEPARTMENT 解析；DIRECT 无有效 release、组织失效或 review_required 均拒绝，不回退更宽默认。普通员工无 responsibilities；clerk 明确多个部门但不含下级；admin 初版明确一个公司。所有角色的 `attendance.read` 仍固定 SELF。

角色管理域与业务可授范围独立：role.management_scopes 固定该角色可使用的公司域；发布人须有所有域的 `iam.roles.publish`，且能管理全部直接及继承引用者和被授范围。不能因为人数为零放行，不能以考勤管理员原生角色推导 IAM 编辑权。若以后要跨公司复用，须显式扩展受控管理边界并重验，不在功能草稿里暗增。

| 考勤 `portal/permissions.py` | 现有纳管账号旧路径默认拒绝继续存在。每个名单内路径完成原生必要权限与 query/write 范围实测后，才替换该路径拒绝；File/Prepared Report/RQ 在执行/下载时重验，不整体关闭 |

`scope_ref` 的 Data 配合显式 Link 校验、role 指针空值与 FOLLOW 模式的命令唯一性，必须进入 DocType/数据库并发测试，不能只依赖表格约定。

正向角色执行与旧限制的组合需明确两种结果：旧路径现有 allow 在未 opt-in 主体上保持；opt-in 后不能借旧 allow 恢复角色发布已撤销的功能。旧限制只作 veto（包括当前有效 deny、临时禁用、明确 gate/许可期限与未完成首次改密），不把“原来没有新功能 allow”当成 deny，也不抹掉已过期许可限制。每项迁移给出原始行和有效语义的来源指纹。

原生权限映射只接受受控服务所需的最小 DocPerm；不分配 System Manager/HR Manager。新建专用原生 Role 是否必要，须在同步后以当前原生 DocPerm 与服务入口实测决定并记入 release allowlist；**本候选不预先增加任何原生 Role**，当前所有新业务 operation integrated=false。禁止“临时加 HR Manager 使测试通过”。

发布 context_revision 覆盖：role 域/草稿/当前 release；直接与部门默认关联及职责；全部相关 Department 的当前 Employee 集合和 User 关联、状态/禁用/旧 Policy 版本；操作者权限及可授范围；operation registry 版本。无关 App 变化不使 context 无效。

**锁与并发合同**：所有角色关联变更按稳定排序先锁本 App 角色，再锁角色相关 Department 范围、关联、Employee、User、旧 Policy 与审计键；原调岗命令必须加入同一锁协议。部门成员增加/调出要取得相同 Department 锁；索引范围锁与当前读共同覆盖成员幻读。预览和发布都重算集合指纹，预览后变化返回 409。禁止先拿 RR 旧快照再声称锁住集合；遇到冲突整笔回滚，不能静默沿用旧预览自动重试写。

请求重放须重验当前授权，request_id 绑定 actor、operation、payload；相同请求返回同一安全结果且只一份 release/审计；同 ID 异内容 409。角色发布后的撤权下一请求生效，旧页面结果失效清理，但未关联角色变化不重挂本人页或清草稿。
