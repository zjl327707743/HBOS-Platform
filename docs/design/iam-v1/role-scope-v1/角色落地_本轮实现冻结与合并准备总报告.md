## 实现与实际业务

五个精确模型：App Role、Role Release、Role Feature 子表、Role Assignment、Role Scope 子表。没有新增身份主实体；原生权限数组为空，不给三个角色批量 HR/System Manager。员工、角色发布、部门默认均是正式 Vue 页面；草稿不生效，发布原子切换不可变版本，重验管理域、可授范围、所有直接/继承引用、成员集、旧规则活性和本人验证。取消、403、409及故障不产生部分授权。

32 项包括 SELF、具名部门面板/详情、公司面板、班次及排班、原生更正全状态链、规则及重算、原有三类报表、月度暂存、导入日志及请假/加班/调休、三项私有 XLSX、排班导入及考勤原始/月度导入。确切方法见 [功能接入矩阵](角色落地_首批交接与未完成项.md)。

部门和公司读写均先核验员工与整个请求期间的可证历史。HR 主部门与明确负责范围分开；不隐式含下级。公司包含无部门员工，部门角色不能借此扩大范围。历史不足时明确局部覆盖，全部未知则拒绝；SELF 独立。读路径当前锁定读取，RR 冲突重新授权；写冲突409。原生全量报表、File、Prepared Report和旧全量任务守卫保留。

原始导入生成真实 Checkin，并调用既有 HRMS 计算生成来源关联的已提交 Attendance；月度汇总只写原生暂存。整批源文件、员工、日期、公司与当前输入指纹在确认执行时重新核对；禁止伪造服务器路径、跨公司、缺失历史和来源变更。File 原生文档、日志、业务和审计同事务；故障实测发现的文件孤儿已通过原生 File 事务回滚修复并复验。月度暂存通过数据库 JSON_TABLE 先筛获准员工再返回载荷。

私有导出复用原渲染器，真实检查 XLSX 内容边界；同 SID 撤权后旧文件拒绝，恢复后重验。下载同时核验当前范围、来源、私有文件路径和内容指纹。实际 RQ worker 消费一个合成旧全量任务，执行前按存储的原操作者拒绝，业务指纹不变；这与单独 hook 测试区分记录。
