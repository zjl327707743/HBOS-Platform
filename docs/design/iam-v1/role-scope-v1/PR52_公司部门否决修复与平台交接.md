策略是**拒绝整笔公司范围请求**。`role_access.legacy_veto` 对当前用户和主部门的现行规则，检查同操作或 `app.enter` 的有效部门 deny 是否属于所请求公司；命中则统一拒绝。既有 `policy._matches` 的允许语义、范围上限、SQL company OR、事实保护均未放宽。禁用部门也不被作为历史数据绕过理由。

依赖公司范围的接口即使附带部门过滤，也服从整笔拒绝；独立部门责任范围、SELF 和无关操作按原语义判断。没有禁止时，公司无部门员工继续可用，部门角色不能借空部门扩权。不是新增第二套权限判定器。

原生 Department Policy 不允许保存该具体重要操作，具体操作的正式样例使用 User Policy；部门来源使用合法 `app.enter`。测试中被原生校验拒绝的组合未通过 SQL 强塞，也不计作有效复现。
