# R5 原型适配与验证说明

本轮仅原型与设计资料。R4 B 开工单、正式模型/API/环境仍未批准；没有新增正式 schema 或授权语义。Owner 易用性结论为 `PENDING_OWNER`。

## 一套显示、编辑、提交

员工页和应用页只发送同一 `open(employeeId, tab, appId)`，App 集中挂载一个 EmployeeDrawer；AppUsageList 与 WorkSettings 同源读取。部门默认应用使用同一个内嵌 WorkSettings，subjectKind 指定 Department 演示对象。没有抽屉套抽屉、复制规则表单或两份独立状态。

`work-policy.js` 将日常工作投影到现有 R4 合成判定器：摘要、逐操作对象、来源、范围限制及前后影响。`workAccess.js` 是唯一工作安排保存命令，经过 saveDemo 后只写命名目标的最小 patch；不赋值全量快照、不替换 session。保存前后复查管理员和revision，失败回滚、草稿保留。无修改保存不写规则、版本或成功记录。

普通勾选只触碰被调整的工作。缩小范围保存明确允许集合，取消勾选生成针对当前已登记对象的限制，不能因删掉allow又回到部门允许。必要入口随工作协调，但整个应用所有动作都做前后对象判定，发现非预期激活其他写入/导出/重要操作时拒绝自动提交。有限禁止保留范围含义，不宣称未来所有对象都被禁止。

复杂既有范围限制无法无损编辑时显示业务明细并保持只读；不会自动覆盖。个人APP门禁确实限制了部门动作时，来源显示该限定；为另一操作协调入口而未影响的工作不改来源。未接入导出不计为可用，不通过勾选开启。高风险仅显示实际资格下结果，不借预览探针伪装已获资质。

停用备份只存本员工本应用的入口规则于 `suspendedAppGates` 合成状态，原动作规则保留；恢复前展示实际结果。继承来的部门停用不能由个人“重新启用”伪成功绕过。普通恢复不顺手删除/重新授予重要操作，其他员工及应用保持不变。此演示备份结构不是已批准的后端模型；B 若继续实施须重新核对服务端命令、并发和停用/恢复语义。

## 身份、数据与视觉

R4 permission.js 不改。已有登录/本人安全组件业务不改，稳定Employee/User键、账号复用、独立一次临时口令、首用改密、MFA/恢复/换绑、冲突/停用与本人参数拒绝覆盖保留。技术关联字段仅在管理抽屉受限折叠信息中显示。UI选择目标员工不改变当前会话本人。

R5 namespace为 `hbos.iam-v1.r5.synthetic.v5`，R3/R4记录不读不清除。默认合成管理员工作台只用于评审；退出后仍可使用既有登录原型。`createSeed()`保留原五人行为夹具，`createSeed({expanded:true})`供页面使用29员工、长姓名/部门、待处理账号和未确认节点。确认态不由打卡数量推断。未确认节点既禁UI也被原型新建/调岗/工作命令拒绝。

共享token统一32/24/16间距、1280内容上限、720抽屉、16正文/14辅助文字；登录Hero尺寸保留。主页面无水平滚动，窄屏表格在内部滚动，长名称可点击/键盘打开完整资料。页内切换保留筛选和分页，抽屉离开前处理草稿；固定操作区不遮最后一项。
