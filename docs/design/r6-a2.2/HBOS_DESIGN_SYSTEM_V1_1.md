# HBOS 前端规范 v1.1 · R6-A2 候选

状态：**R6A2_DESIGN_REVIEW_READY / 待 Owner 视觉与任务验收**。这份规范对应当前 Vue 样板的实际表现；不是正式页面实施或权限策略变更。

## 1. 设计方向与品牌连续性

沿用 HBOS 的 H 标识表现、蓝紫品牌、项目字体栈与 Ant Design Vue。外壳使用克制的蓝紫浅色与轻阴影，工作画布保持柔和，内容表面以高可读白底为主。身份、当前任务和主要动作形成稳定层级。员工与权限页面不使用厂区照片、粒子或持续装饰动画。

与 R6-A 的变化是结构性的：个人中心从头像菜单进入且隐藏管理局部导航；列表采用成熟表格和手机任务卡；员工角色用职责比较卡与搜索选择器；角色模板以分组阅读态呈现，编辑时才出现勾选。不能用本规范给旧 HTML 换色后宣称实施完成。

## 2. 三层页面结构

| 层级 | 桌面 | 手机 | 状态约定 |
|---|---|---|---|
| 工作台全局 | 76px 顶栏；首页、我的工作、应用中心、管理中心 | 64px 顶栏；工作台导航菜单 | 普通员工没有管理入口；本轮员工、角色安排与角色模板路径完整可操作，其余已有工作台入口只作导航保留 |
| 管理局部 | 224px 侧栏；1280 时 208px | 顶栏下 48px 局部标签 | 员工管理 / 部门安排 / 角色与权限 / 变更记录；低频工具收纳到“更多管理工具” |
| 页面任务 | 路径 → 28px 标题与一句说明 → 内容与动作 | 16px 页边距；任务自然纵向排列 | 不把个人设置和管理他人放在同一组菜单，不把技术字段放进首屏 |

个人页无管理侧栏，最大内容约 1160px；管理员仍保留身份和“返回管理中心”。管理者为人事员工时展示员工资料，只有明确的内置 Administrator 才显示系统账号和员工档案不适用。飞书绑定不表示 Employee 已关联。

## 4. 公共组件及状态合同

组件展示入口：预览右上“设计预览” → “统一组件规范”，亦可打开 `/#/spec`。

|---|---|---|

| `PageHeading` | 项目页面标题结构 | 路径、标题、一句任务说明、区域主要动作；无 API/版本噪声 |
| `StatusTag` | 统一轻量语义标签 | 色彩 + 文字 + 点或图标；访问状态与需要处理分开 |
| 员工工具栏 | Input allowClear / Select showSearch / Tag | 姓名工号搜索、部门、账号状态、可关闭筛选标签与清除；切回保留 |
| 员工表格 | Table / Checkbox / Pagination | 头像姓名、工号、部门岗位、账号、需要处理、直达动作；悬停与选中；固定表头；分页 20 行合成样例，与现有查询页大小一致 |
| `EmployeeDrawer` | Drawer / Tabs / Descriptions | 固定对象身份与底部动作，资料 / 账号 / 应用角色自由切换；手机全屏；未保存关闭时可继续编辑 |
| 角色比较卡 | 语义 radio + Ant 图标 | 普通员工、部门考勤员、考勤管理员按用途、核心能力、范围比较；支持方向键与焦点 |
| 范围选择 | Select multiple / showSearch | 部门可搜索、已选可见；不默认包含下级；公司恰好一个受支持公司；本人范围无需额外勾选 |
| 角色功能分组 | Collapse / Checkbox（仅编辑） | 使用既有 registry group；阅读态显示启用文字与图标；搜索与展开保留全部真实功能映射 |

## 5. 页面模板与密度

**个人中心。** 顶部身份卡含姓名、账号类型、部门岗位、工号与关联状态；下方为带图标的密码、飞书与恢复设置行。每行一个主要动作。普通员工未关联时不展示虚构员工字段；内置系统账号单独说明。无可保存能力的偏好不做假开关。管理员诊断、他人账号、职责交接和 Desk 不占本人主要区域。

**员工列表。** 三张概览卡分别定位当前合成员工、待开通与待核对；数量不代表公司总人数。已有员工开户与新增建档分开。正常已开通或个人访问受限不自动成为待办。一个页面纵向滚动主体，列表不再套独立纵向滚动。常规行含两行信息；紧凑密度只缩小行距与头像，不缩正文。桌面可选择行，当前页全选与行选择有中文可访问名称。

**员工详情与角色。** 资料、账号、应用角色是分区，不强迫每次通过四步向导。首次开户与密码设置才使用顺序提示。角色任务直接为：应用 → 来源 → 比较角色 → 明确负责范围 → 核对并模拟验证保存。单独设置替换部门来源，不叠加。个人禁止、暂停与需核对的期限仅在相关人员处突出。

**角色模板。** 应用与角色选择、职责摘要、当前生效/待发布、分组功能、变更摘要。先保存草稿再预览和确认发布。未修改不得重复保存或发布。阅读态没有整页 disabled checkbox。高风险功能不通过全选或范围扩张自动获得。本轮只展示已接入考勤角色，其余原生角色与仓库级范围不伪造。

**确认弹层。** 标题动作明确；前后变化用标签、文字与颜色共同表达；验证在确认前。对象身份与范围必须在同一确认中能读到。手机改为单列对比并允许弹层内滚动，不缩小内容。

## 6. 反馈、微交互与错误恢复

候选动效：悬停 160ms，Ant 控件/抽屉/弹层使用 160 / 200 / 240ms token。只改变颜色、阴影与位置过渡，不让行或按钮跳动。切回页面不重演骨架；筛选、草稿和滚动在当前身份内保留。减少动态效果规则将非必要动画与过渡降至 1ms；本轮工具无法切换系统偏好，运行态单独列未测。

| 情况 | 界面行为 | 正式实施仍须保留 |
|---|---|---|
| 保存成功 | 原位置忙碌 → 成功摘要，账号或安排状态更新 | 只依服务端已确认的结果，不由前端推算授权 |
| 保存草稿 | “修改已保存，尚未影响员工”；当前生效保留 | 不可变 release、草稿版本与发布预览 |
| 409 | 当前修改保留；核对最新内容、重新验证后确认 | 旧预览和 proof 失效；版本与 context_revision 检查 |
| 403 | 当前身份仍登录，保留可安全保留的编辑 | 管理域与 capability 的服务端拒绝 |
| 5xx | 不假成功；先核对保存结果再重试 | 原 request_id、幂等与未知结果读取，不盲目重复写 |
| 401 / 切换身份 | 清除上一身份详情、编辑、核验与预览 | portalSessionCoordinator、generation、会话失效与跨身份清理 |
| 取消 / 返回 | 确认取消不写入；保留编辑选择；关闭未保存需明确选择 | 不隐式保存，不自动扩大管理域 |

## 7. 中文文案原则

主要界面说任务结果：“负责哪些部门”“增加/移除什么”“保存后是否影响员工”。`operation_id`、`scope_binding`、`proof`、CSRF、版本冲突编号留在工程附件或必要诊断中。用“为保护账号，请验证本人身份”，不让管理员理解内部校验字段。

“访问受限”描述状态；“待开通 / 待核对”才是需要处理的任务。“暂停此应用”“停用账号”“不安排此角色”“恢复部门安排”不共用一个含糊开关。期限 DTO 不完整时提供核对说明，绝不承诺“永久有效”。

## 8. 响应式与可访问性

必须检查实际 CSS 1440、1280、390 视口；每张截图附 DPR、位图尺寸、工具缩放说明。手机侧栏转局部标签，员工表格转任务卡，详情为全屏，角色比较卡纵向排列，重要操作可完整触达。长姓名、部门和错误文字允许换行。

键盘顺序、可见焦点、模态循环、Esc、返回触发控件及选择器搜索分别验证。Select 内 Esc 仅关闭选择器，不能连带关闭抽屉。角色比较卡支持方向键。主要手机动作至少 44px；辅助图标目标不得与邻近目标挤压。

最终背景上的文字/语义色/控件边界/焦点样本对比度见 `evidence/contrast-checks.json`。样本检查不构成全站 WCAG 合规声明。真实浏览器 200% 与真人首次理解验证独立记录；缺少工具或人时如实 NOT_RUN，不能用 CSS zoom、缩小视口或脚本断言替代。
