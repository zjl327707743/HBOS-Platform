# 飞书自动开户与受控账号变更

本说明接续 PR #21 的固定 Mac Site 与服务器部署工具。普通登录不增加换绑步骤；企业 Secret、人员映射、索引、模型和认证票据均留在受保护的运行环境，不发布到 Git。

## 企业与成员证据

用户已完成 `feishu-config` 和程序发现的企业确认，无需再次配置 Secret。一次新授权已证明：Site、授权用户与应用所属企业匹配，人员 ID 匹配，五个接口均成功，但成员 `status` 字段缺失。旧实现把这一步与租户拒绝共用 `tenant_rejected`，现在分别报告企业缺失/不匹配、应用企业不匹配、成员接口/人员 ID、状态缺失/类型、未激活/冻结/离职。

当前最小权限申请为**应用身份** `contact:user.employee:readonly`，用于取得成员状态，已由本人提交、待审批发布生效。用户 OAuth 仍只请求基础身份 `contact:user.base:readonly`，不增加部门或聊天读取权限；保持既有获准成员范围，不按企业名称或首位登录者增加允许企业。

成员核验要求 `is_activated`、`is_frozen`、`is_resigned` 为明确布尔值，且已激活、未冻结、未离职；可见的 `is_exited` / `is_unjoin` 为真仍拒绝。缺失必要状态保持拒绝并说明最小解决方式，缺失可选字段保持未知。获准企业及应用范围内当前内部成员记录是准入依据，部门字段不是额外的全员登录前置条件。

脱敏诊断仅记录 Site、源码/build 版本、阶段安全错误码、企业/人员是否存在及匹配、状态字段存在性/类型/判定、部门存在性、HTTP 和数字接口错误码。文件位于目标 Site private，0600，不记录 OAuth code、Secret、Token、身份值或完整资料；不重放已用 code。诊断编号仅供本机定位，内部诊断报告不进 Git。

## 自动开户、拼音与可选密码

已验证且已有有效绑定的身份进入原 User。无任何绑定记录的获准成员由单一服务在一笔事务中创建永久 Website User、绑定并进入；失败回滚，不产生孤立账号。已停用账号与撤销/替换关系不走重新开户。不按姓名、拼音或邮箱认领原账号，不授予 Desk、System Manager 或业务审批角色。

显示名称使用已验证姓名；登录别名由锁定版本 `pypinyin==0.55.0` 生成小写全拼，常见多音姓按姓氏读音处理。拉丁姓名规范化，空名、数字开头和保留名称使用 member 前缀，限制长度。重名依次追加 2、3；数据库 User.username 唯一约束及独立连接锁处理并发。别名不是身份依据，多音字显示可由本人/运维核对，已有 User 与业务关联不批量改名。

新 User 无密码记录，无共享默认密码，空密码不能登录。本人可以先仅用飞书工作；需要密码时，在账号与安全主动请求已绑定本人收件验证码，保留已有 MFA 后设置。Frappe 原生用户名登录已启用，两种入口仍进入同一 User。虚拟 User 地址不可作为恢复邮箱。

已有账号，包括 Administrator，先密码/MFA 登录，再从账号与安全授权本人飞书并明确确认绑定。登录表单中填的用户名不授权 OAuth 绑定；不删除冲突或自动转移权限。Administrator 忘记密码使用当前 Site 的本机 `admin-password` 隐藏输入工具，不开放匿名恢复。

## 三种受控变更

账号与安全提供低频分步入口：

- **更换本人飞书**：保留同一 User、密码、角色与业务资料，只替换验证后的外部身份。
- **管理员职责交接**：双方使用自己的永久个人账号，仅转移明确勾选的已有管理角色，保留作者与账号。需要 `HBOS Account Handover Manager` 专项角色；迁移只创建该角色，不自动授予任何用户。
- **Administrator 保管人交接**：单独高风险流程。当前保管人密码/MFA 重新认证、Site 专项许可、接任者本人飞书与来源账号验证、接任者设置并验证新密码和新 MFA、双方明确确认后才提交。本轮真实 Site 未启用该交接许可，也未改变真实 Administrator 归属。

邀请为 20 分钟、单次、操作绑定的 URL fragment，兑换后只建立 HttpOnly 验证浏览器；拿到邀请不等于登录目标账号。交接接任者在独立浏览器完成验证，不共享当前保管人的密码或 Session。独立 rebind/handover OAuth 意图不走自动开户，不签发管理员会话。

双方核对当前 User、旧/新身份短指纹、已验证企业应用范围、来源账号、将失效的入口、角色与影响。普通用户只能查看参与的操作。取消、超时、相同身份、未完成验证或冲突不改变旧绑定。

新身份已占用时默认拒绝，优先使用个人账号承接职责。确需迁出必须在具体新身份验证后由发起人重新认证并明确批准，来源账号本人验证可用密码及已有 MFA，确认仍有有效密码入口。两账号变更一笔事务提交，保留来源账号、数据和角色，不交换身份或账号。不提供手填 open_id 覆盖接口，通用绑定仍拒绝冲突。

原身份无法使用时，由专项组织授权进入“旧身份的普通账号归属”，新身份仍须真实验证。可以明确归属到经本人验证的永久普通账号，或明确创建普通账号；不继承 Administrator 权限、密码或业务归属。停用账号不能通过该路径绕过。

## 切换与审计

关系唯一性包含 provider、tenant、app、id_type、external_id；有效身份与同一范围 User 分别唯一。关系记录及不可改写的变更事件保留原因、操作者、双方确认、操作 ID、时间和角色，不改历史业务作者。

提交持有目标 User、安全版本和身份锁；身份锁与自动开户共用，唯一索引为最后防线。安全版本和账号 epoch 撤销旧请求、所有旧 Session、绑定/设密/恢复票据，之后须重新登录。非法 Authorization 请求头不能跳过旧 Cookie 版本检查。

Administrator 切换同时撤销目标旧飞书、密码验证记录、登记的原生 MFA/恢复默认项、重置 key、Session、API key/secret、原生 OAuth token/code、Passkey 和社交登录关联；仅接任者验证的新密码与 MFA 生效。Frappe 默认豁免内置 Administrator 的 MFA，HBOS 登录门禁另行强制，既有已登记 Administrator MFA 也不能绕过。发现未知 auth hook 或无法核对的认证提供方结构则在提交前拒绝，不能把未核入口说成已撤销。

共享飞书 App Secret 与其他系统凭据不轮换；主机/数据库运维权限须另行交接。切换失败不偷偷恢复旧负责人；回退作为新的受控操作。只有被交接明确选择的角色才变更，团队整体企业准入政策保持不变。

已完成变更的通知只通过已批准的本人渠道发送，不读聊天、不群发。状态区分排队、队列失败、飞书确认发送、投递失败与状态未确认；通知失败不回滚已完成的撤销。通知中无密码、验证码或恢复链接。

## 验收范围

合约测试、原生 SQL/密码/Session、两独立连接并发及隔离高风险测试与真人验收分别记录。破坏性保管人测试要求 freshly-created `account-regression.*` / `platform-smoke.*` Site 且两项测试开关均启用，不在真实 P1 或其复制业务库测试 Administrator。CI 的合成身份断言不代表飞书真授权、验证码真实收件或真人交接成功。

本人飞书进入原 Administrator、第二位获准员工自动开户/重复登录、本人收件验证设密与实际恢复仍待权限生效及当事人操作。真实换绑/职责/保管人交接未执行；须明确人员、目标和页面确认。公司服务器、固定 IP 与正式 HTTPS 留后续，不阻塞本地修复、构建或 PR 同步。
