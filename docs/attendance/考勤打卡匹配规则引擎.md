# 新乡海滨考勤打卡匹配规则引擎

## 一、班次定义

| 班次 | 上班时间 | 下班时间 | 跨天 | 工作时长 |
|------|---------|---------|------|---------|
| 早班 | 08:00 | 16:00 | 否 | 8h |
| 行政班 | 08:30 | 17:30 | 否 | 9h（含午休1h） |
| 中班 | 16:00 | 00:00（次日） | 是（下班跨天） | 8h |
| 晚班 | 00:00 | 08:00 | 是（上班跨天） | 8h |

### 关键时间窗定义

| 时间窗 | 范围 | 涉及的打卡类型 | 歧义来源 |
|--------|------|--------------|---------|
| 早班上班窗 | 07:30–08:30 | 早班上班、行政班上班、晚班下班 | 早班 vs 行政班 上班混淆；晚班下班 vs 早班上班 混淆 |
| 行政班上班窗 | 08:00–09:00 | 行政班上班、早班迟到 | 早班迟到可能被识别为行政班正常上班 |
| 下午下班窗 | 15:30–18:00 | 早班下班、行政班下班 | 可通过下班时间反推班次 |
| 午夜窗 | 23:30–00:30 | 中班下班、晚班上班 | 中班 vs 晚班 混淆 |
| 清晨窗 | 07:30–08:30 | 晚班下班、早班上班、行政班上班 | 三种打卡混合，最复杂窗口 |

---

## 二、总规则：优先级递减

规则按优先级从高到低执行。高优先级规则命中后，不再执行低优先级规则。

```
优先级 0（最高）：排班锚定规则
优先级 1：        跨天连续性规则
优先级 2：        配对反推规则
优先级 3：        时间窗 + 邻近度打分规则
优先级 4（最低）：兜底/异常标记规则
```

---

## 三、优先级 0：排班锚定规则

### 规则 0.1：有排班则排班优先

**前提**：员工在当天的 `Shift Assignment`（排班记录）已存在。

**逻辑**：
1. 读取员工当天的排班班次类型（早班/行政班/中班/晚班）。
2. 以排班班次的上下班时间为锚点，进行打卡匹配：
   - **上班卡**：取当天最接近「上班时间」且在允许范围的打卡记录。
   - **下班卡**：取当天最接近「下班时间」且在允许范围的打卡记录。
3. 夜班跨天处理：晚班（00:00–08:00）的排班归属日期 = 排班开始日期（即 00:00 所在的日期）。该排班日期的上班卡在当天 00:00 附近，下班卡在当天 08:00 附近（或次日 08:00，取决于系统存储方式）。

**上班卡允许范围**：
- 最早 = 上班时间 − 60 分钟（提前最多 1 小时打卡有效）
- 最晚 = 上班时间 + 宽限分钟数（见迟到规则）

**下班卡允许范围**：
- 最早 = 下班时间 − 30 分钟（早退边界）
- 最晚 = 下班时间 + 120 分钟（加班候选，最多延后 2 小时）

**输出**：
- 排班班次明确 → 直接匹配 → 标记 `match_source = "shift_assignment"`
- 匹配成功则跳过优先级 1–4

### 规则 0.2：排班不准但打卡不匹配

如果按排班锚定后，在允许范围内找不到打卡记录：
- 标记为「缺卡」异常，进入优先级 1 尝试无排班匹配（作为兜底）。
- 兜底匹配结果标记 `match_source = "fallback_no_punch_in_window"`

## 四、优先级 1：跨天连续性规则

### 规则 1.1：午夜窗（23:30–00:30）判定

**场景**：一条打卡记录落在 23:30–00:30 区间。

**判定逻辑**：
1. 检查该员工在 15:00–17:00 区间是否有打卡记录：
   - **有** → 该员工很可能在值中班。午夜打卡 = **中班下班卡**。归属日期 = 15:00–17:00 那条打卡所在的日期。
   - **没有** → 继续检查 22:00–23:59 区间是否有打卡：
     - **有** → 午夜打卡 = **中班下班卡**（中班下班晚于 00:00）。
     - **没有** → 午夜打卡 = **晚班上班卡**。归属日期 = 打卡日期。

**输出**：
- 判定为下班卡 → `punch_type = "out"`, `shift = "中班"`
- 判定为上班卡 → `punch_type = "in"`, `shift = "晚班"`
- 匹配成功则 `match_source = "cross_day_continuity_midnight"`

### 规则 1.2：清晨窗（07:30–08:30）判定

**场景**：一条打卡记录落在 07:30–08:30 区间。

这是最复杂的窗口，有三种可能：
- 晚班下班（约 08:00）
- 早班上班（约 08:00）
- 行政班上班（约 08:30）

**判定逻辑（按顺序执行）**：

**Step A — 检查是否为晚班下班**：
1. 检查该员工在当天 00:00 前后（前一天 23:30–当天 00:30）是否有打卡：
   - **有且被优先级 1.1 判定为晚班上班卡** → 当前 07:30–08:30 打卡 = **晚班下班卡**。
   - **有且被优先级 1.1 判定为中班下班卡** → 不是晚班，跳到 Step B。
2. 检查该员工前一天是否有晚班排班（Shift Assignment = 晚班）：
   - **有** → 当前打卡 = **晚班下班卡**。
   - **没有** → 跳到 Step B。

**Step B — 检查是否为早班或行政班上班（执行优先级 2–3）**：
- 如果 Step A 未命中晚班下班，则将该打卡标记为「上班卡候选」，进入优先级 2（配对反推）和优先级 3（时间窗打分）来确定是早班还是行政班。

**输出**：
- 判定为晚班下班卡 → `punch_type = "out"`, `shift = "晚班"`, 归属日期 = 前一天（晚班上班日期）
- 判定为上班卡候选 → 进入优先级 2–3

### 规则 1.3：中班下班跨天归属

中班下班时间 00:00 落在次日。中班上班卡在当天 16:00 附近。

**逻辑**：
1. 如果一条打卡被判定为「中班下班卡」且时间在 00:00 之后：
   - 归属日期 = 前一天（中班上班日期）。
   - `in` = 前一天 16:00 附近的打卡，`out` = 当天 00:00 附近的打卡。
   - 这对 in/out 绑定到同一个班次（中班），归属到上班日期。

## 五、优先级 2：配对反推规则

当优先级 0（排班）未命中，且优先级 1（跨天）已处理完午夜/清晨判定后，剩余的「上班卡候选」进入配对反推。

### 规则 2.1：下班时间反推班次

**核心思路**：早班和行政班的上半时间很接近（8:00 vs 8:30），但下班时间差别明显（16:00 vs 17:30）。因此，**用下班时间反推班次**是准确率最高的方法。

**逻辑**：
1. 对于已被标记为「上班卡候选」（07:30–09:00 区间）的打卡，在当天查找配对的「下班卡候选」（15:00–18:00 区间）。
2. 如果找到一条 15:30–16:30 的下班卡：
   - 配对 → **早班**（in=上班候选卡, out=该下班卡）
   - 因为早班下班在 16:00，行政班下班在 17:30，16:00 前后半小时的打卡明确归为早班。
3. 如果找到一条 17:00–18:00 的下班卡：
   - 配对 → **行政班**（in=上班候选卡, out=该下班卡）
4. 如果上班候选卡在 15:00–18:00 区间找不到任何下班卡：
   - 标记为「缺下班卡」，进入优先级 3 仅按上班时间邻近度打分。

**特殊情况 — 只有下班卡、没有上班卡**：
- 如果 15:30–16:30 有一条打卡但没有配对的上班卡 → 标记为「早班缺上班卡」
- 如果 17:00–18:00 有一条打卡但没有配对的上班卡 → 标记为「行政班缺上班卡」

**输出**：
- 配对成功 → `match_source = "pairing_reverse_infer"`
- 置信度：高（下班时间差 1.5 小时，区分度高）

### 规则 2.2：上班时间邻近度辅助配对

当规则 2.1 无法配对（缺下班卡）时，仅用上班时间邻近度做最佳猜测：

| 上班打卡时间 | 判定 | 置信度 | 说明 |
|------------|------|--------|------|
| 07:30–07:55 | 早班上班（提前） | 高 | 行政班 8:30 上班，不会这么早 |
| 07:55–08:05 | 早班上班（准时） | 高 | 非常接近 8:00 |
| 08:05–08:15 | 早班上班（迟到） | 中 | 可能是早班迟到 5-15 分钟 |
| 08:15–08:25 | **模糊区** | 低 | 早班迟到 15-25min 或行政班提前 5-15min |
| 08:25–08:35 | 行政班上班（准时） | 高 | 非常接近 8:30 |
| 08:35–08:50 | 行政班上班（迟到） | 高 | 行政班迟到 5-20 分钟 |
| 08:50–09:00 | 行政班上班（严重迟到） | 中 | 也可能是早班严重迟到 |

**模糊区处理（08:15–08:25）**：
- 查找该员工历史 5-10 个工作日的班次规律：
  - 如果历史都是早班 → 判定为早班迟到
  - 如果历史都是行政班 → 判定为行政班提前
  - 如果混合 → 优先按行政班提前判定（宁可算早到不冤枉迟到）
- 如果无历史数据 → 标记为「模糊区 - 需人工判定」

### 规则 2.3：全天配对完整性检查

每个员工每天应有一套完整的 in/out 配对：

| 场景 | 判定 | 处理 |
|------|------|------|
| 有 in + 有 out + 配对成功 | 正常出勤 | 记录班次、计算迟到/早退 |
| 有 in + 无 out | 缺下班卡 | 标记异常，班次按 in 时间+规则 2.2 判定 |
| 无 in + 有 out | 缺上班卡 | 标记异常，班次按 out 时间+规则 2.1 判定 |
| 无 in + 无 out | 缺勤（全天） | 标记缺勤，除非有请假记录覆盖 |
| 有 in + 有 out + 不配对 | → 进入规则 2.4 | |

### 规则 2.4：多卡配对（一天超过 2 次打卡）

如果员工一天打卡超过 2 次：
1. 将所有打卡按时间排序。
2. 尝试所有可能的 (in, out) 配对。
3. 对每个配对打分（分数 = 与标准班次 in/out 时间的匹配度）。
4. 选取得分最高的一对作为主班次 in/out。
5. 多余的打卡标记为「多余打卡 - 待核查」（可能是加班打卡、误打卡、补卡等）。

## 六、优先级 3：时间窗 + 邻近度打分规则

当优先级 0–2 均无法给出确定结论时，使用纯时间窗打分。

### 规则 3.1：单次打卡打分表

对每条未匹配的打卡，计算其属于各个班次的可能性分数：

```
分数 = 时间邻近分 + 历史频率分 + 合理范围分
```

**时间邻近分（满分 100）**：

| 打卡时间 vs 班次上班/下班时间 | 分数 |
|---------------------------|------|
| 偏差 0–5 分钟 | 100 |
| 偏差 5–15 分钟 | 85 |
| 偏差 15–30 分钟 | 60 |
| 偏差 30–60 分钟 | 30 |
| 偏差 > 60 分钟 | 0 |

**历史频率分（满分 30）**：
- 该员工过去 20 个工作日中，此班次出现频率：
  - 频率 ≥ 80% → +30
  - 频率 50–79% → +15
  - 频率 < 50% → +0
  - 无历史 → +0

**合理范围分（满分 20 或 致命扣分）**：
- 打卡时间在班次允许范围内 → +20
- 打卡时间与班次上班/下班时间偏差超过 90 分钟 → 直接排除（该班次不可能）

**最终判定**：选取得分最高的班次。如果最高分与次高分差距 < 10 分 → 标记为「低置信度 - 建议人工复核」。

### 规则 3.2：中班上班 vs 早班下班（16:00 附近）

16:00 是一个特殊节点：既是早班下班，又是中班上班。

| 打卡时间 | 判定 | 置信度 |
|---------|------|--------|
| 15:30–15:55 | 早班下班（早退候选） | 高 |
| 15:55–16:05 | **模糊区** | 低 |
| 16:05–16:30 | 中班上班（迟到候选） | 高 |

**16:00 模糊区处理**：
- 如果该员工当天有早班上班卡（07:30–08:30）→ 16:00 打卡 = 早班下班卡
- 如果该员工当天无早班上班卡 → 16:00 打卡 = 中班上班卡
- 如果以上都判断不了 → 查历史规律，标记低置信度

## 七、迟到、早退、缺卡判定规则

### 规则 7.1：迟到判定

前提：班次已确定。

| 条件 | 判定 |
|------|------|
| 上班打卡时间 ≤ 上班时间 + 宽限分钟 | 正常 |
| 上班打卡时间 > 上班时间 + 宽限分钟 | **迟到** |

宽限分钟默认值：

| 班次 | 宽限分钟 | 迟到阈值 |
|------|---------|---------|
| 早班 | 5 分钟 | 08:05:00 之后算迟到 |
| 行政班 | 5 分钟 | 08:35:00 之后算迟到 |
| 中班 | 5 分钟 | 16:05:00 之后算迟到 |
| 晚班 | 10 分钟 | 00:10:00 之后算迟到（夜班宽限稍长） |

### 规则 7.2：早退判定

| 条件 | 判定 |
|------|------|
| 下班打卡时间 ≥ 下班时间 | 正常 |
| 下班打卡时间 < 下班时间 | **早退** |

### 规则 7.3：缺卡判定

| 条件 | 判定 | 严重程度 |
|------|------|---------|
| 有上班卡、无下班卡 | 缺下班卡 | 中 |
| 无上班卡、有下班卡 | 缺上班卡 | 高 |
| 无上班卡、无下班卡、无请假 | 全天缺卡（旷工候选） | 严重 |

### 规则 7.4：加班识别（候选）

| 条件 | 判定 |
|------|------|
| 下班打卡时间 − 班次下班时间 ≥ 30 分钟 | 加班候选（需审批确认） |
| 下班打卡时间 − 班次下班时间 ≥ 60 分钟 | 显著加班候选 |

## 九、置信度与人工复核机制

每条匹配结果附带置信度标记：

| 置信度 | 条件 | 处理建议 |
|--------|------|---------|
| `high` | 排班匹配、或配对反推成功（下班时间明确区分） | 自动通过 |
| `medium` | 时间窗打分差距 ≥ 10 分、或历史频率 > 50% | 自动通过，月度抽查 |
| `low` | 模糊区判定、时间窗打分差距 < 10 分 | 进入人工复核队列 |
| `unknown` | 无历史、无排班、无配对、打分全低 | 必须人工判定 |

**模糊区汇总（需重点人工关注的场景）**：

| 模糊区 | 时间范围 | 风险 |
|--------|---------|------|
| 早班 vs 行政班上班 | 08:15–08:25 | 中 |
| 早班下班 vs 中班上班 | 15:55–16:05 | 中 |
| 中班下班 vs 晚班上班 | 23:55–00:05 | 高 |
| 晚班下班 vs 早班上班 | 07:55–08:05 | 高 |

## 十、实施建议

### 优先实施路径

**第一优先级（最大收益）**：确保 Shift Assignment 覆盖所有员工。
- 排班是准确率的最大杠杆。有排班 → 匹配准确率 95%+。
- 早班/行政班混淆：如果员工排班已确定，根本不需要猜测。

**第二优先级**：下班时间反推规则（规则 2.1）。
- 早班 vs 行政班的最强区分信号就是下班时间（16:00 vs 17:30）。
- 即使没有排班，下班打卡也能以高置信度反推班次。

**第三优先级**：跨天连续性规则（规则 1.1–1.3）。
- 解决夜班跨天的打卡归属问题。
- 核心方法：检查员工在 00:00 附近是否有「另一条打卡」来做配对。

**第四优先级**：历史规律学习。
- 对于模糊区（如 08:15–08:25），查员工历史班次频率。
- 需要积累至少 2-4 周数据后才生效。

### 系统实现建议

1. **先落排班，再算考勤**：每月/每周提前录入 Shift Assignment，这是整个规则引擎的基础。
2. **批量处理优于实时处理**：建议每天/每班次结束后统一跑一次匹配，因为配对反推需要看到完整的 in+out。
3. **保留原始打卡流水**：所有匹配结果应可追溯到原始打卡记录，便于人工复核时对照。
4. **异常驱动人工介入**：不要让系统自动处理低置信度结果。将低置信度结果推送到「异常复核」队列，由人事确认。

## 十二、与 HRMS 原生考勤的关系

本规则引擎作为 HRMS 原生 Auto Attendance 的**增强补充层**：

1. **HRMS 原生**：依赖 Shift Assignment 做 Auto Attendance，排班完整时准确率高。
2. **本规则引擎**：处理 HRMS 原生难以覆盖的场景：
   - 员工排班缺失时的打卡匹配
   - 跨天班次的归属判定
   - 早班/行政班混淆的自动识别
   - 多打卡、缺卡、模糊区的人工复核队列
3. **数据流**：打卡流水 → 规则引擎预处理（匹配班次+配对） → HRMS Auto Attendance（生成考勤） → 规则引擎后处理（迟到/早退/缺卡/加班标记）。
