**Goal:** 以 `feature/hbos-portal-product` 分支为基准，在当前 HBOS 上新增门户工作台，并用同域 iframe 内嵌现有 Frappe 考勤页面。

## 背景实测结论（写代码前必须知道）

以下均已在本机实测确认，不是推断：

1. **Frappe 响应头 `X-Frame-Options: SAMEORIGIN`**（来自 `hbos-m0-r3a-frontend-1:/etc/nginx/snippets/security_headers.conf:1`）。5178 与 8080 端口不同即不同源，直接跨源 iframe 会被浏览器拦截。故必须做单一源代理。

2. **`/app/*` 会 301 到 `/desk/*`**；未登录时 301 到 `/login?redirect-to=...`。实测认证后真实地址是 `/desk/hbos-attendance-dashboard`。`/app/...` 也能用（靠 301），但 R2 的 mock 映射直接写 `/desk/...` 少一跳。

3. **portal provider 返回的稳定路径是 `/app/hbos-attendance-dashboard`**（`hb_attendance_app/hbos_attendance/portal/routes.py` 的 `CURRENT_DASHBOARD`）。R3 之后走这条路。

4. **Vite 产物落在 `dist/assets/`，与 Frappe 的 `/assets/` 冲突**。R4 必须设 `VITE_BASE=/hbos/`。dev 阶段不冲突（Vite dev 从 `/src/`、`/@vite/`、`/@fs/` 提供）。

5. **portal 分支的 `hbos_portal/tests/fake_providers.py` 在 Python 3.9 上跑不起来**：函数签名里的 `list[str] | None` 是运行时求值的 PEP 604 语法。补 `from __future__ import annotations` 即可，已在临时副本实测 14 tests 通过。

6. **门户前端在本机可构建**：`npm install` 拉 117 包约 5 分钟，`npm run build`（`vue-tsc -b && vite build`）通过，3.65s。portal 分支文档记录的「build Gate PENDING（npm 超时）」在本机不成立。

7. **三条移植目标路径当前都不存在**（`frontend/`、`apps/hbos_portal`、`hbos_attendance/portal/`），全部是纯新增，无覆盖风险。

8. **`.gitignore` 没有 `dist/`**，只有 `node_modules/`。Task 1 必须补，否则构建产物会被提交。

- [ ] **Step 1: 替换 `vite.config.ts`**

整体写成：

```ts
import { defineConfig, loadEnv } from 'vite'
import vue from '@vitejs/plugin-vue'
import { fileURLToPath, URL } from 'node:url'

// Frappe 拥有的路径前缀。其余路径留在 Portal SPA 内。
// 必须收敛到同一来源：Frappe 发 X-Frame-Options: SAMEORIGIN，
// 只有浏览器可见来源完全一致时 iframe 才被允许加载。
const FRAPPE_PATHS = [
  '/api',
  '/app',
  '/desk',
  '/assets',
  '/files',
  '/private',
  '/login',
  '/logout',
  '/method',
  '/printview',
  '/socket.io',
  '/favicon.ico',
]

export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), '')
  const proxyTarget = env.VITE_FRAPPE_PROXY_TARGET || 'http://127.0.0.1:8080'
  const proxy = Object.fromEntries(
    FRAPPE_PATHS.map((path) => [
      path,
      { target: proxyTarget, changeOrigin: true },
    ]),
  )

  return {
    // R4 生产形态必须设 VITE_BASE=/hbos/，否则 Vite 产物 dist/assets/
    // 会与 Frappe 的 /assets/ 撞路径。
    base: env.VITE_BASE || '/',
    plugins: [vue()],
    resolve: {
      alias: {
        '@': fileURLToPath(new URL('./src', import.meta.url)),
      },
    },
    server: {
      host: '0.0.0.0',
      port: 5178,
      proxy,
    },
  }
})
```

原文件只在 `dataMode === 'frappe'` 时挂代理、且默认目标写的是 `8081`（本机 Frappe 实际在 `8080`）。这里改为**始终挂代理**并纠正默认端口——单一源是 iframe 方案的前提，不能只在 frappe 模式下成立。

<script setup lang="ts">
import { onMounted, ref } from 'vue'
import { useRoute } from 'vue-router'
import { resolveBusinessRoute } from '@/services/portalProvider'

const route = useRoute()
const src = ref('')
const error = ref('')
const title = ref('业务应用')

onMounted(async () => {
  const appId = String(route.query.app ?? '')
  const stablePath = String(route.query.path ?? '')

  if (!appId || !stablePath) {
    error.value = '缺少业务应用参数'
    return

    src.value = await resolveBusinessRoute(appId, stablePath)

})

import type { Router } from 'vue-router'
import { resolveBusinessRoute } from '@/services/portalProvider'

// 稳定 /hbos/... 路由属于 Portal SPA 自己；解析到其他路径说明该 App 当前
// 由 Frappe 实现，交给门户内的 iframe 承载，而不是整页跳出门户。
export async function openBusinessRoute(
  router: Router,
  appId: string,
  stablePath: string,
) {
  const resolved = await resolveBusinessRoute(appId, stablePath)

  if (resolved.startsWith('/hbos/')) {
    await router.push(resolved)
    return
  }

  await router.push({
    name: 'business-embed',
    query: { app: appId, path: stablePath },
  })
}
