## 2. 未移植 / 已拒绝（保留 Base 的加固）

| # | head 的做法 | 处置 | 理由 |
| --- | --- | --- | --- |
| 1 | 名单硬编码 338 个工号 | **拒绝** | Base 名单 0 字面量，走 `HBOS Attendance Policy Assignment` 业务数据 |
| 2 | 飞书凭证硬编码 `APP_TOKEN` 字面量 | **拒绝** | Base 全 env 化；本分支硬编码字面量扫描 = 0 |
| 3 | 删除飞书出站总开关 `feishu_write_enabled()` | **拒绝** | 出站 kill switch 必须保留，默认关闭 |
| 4 | 删除 4 个旧引擎 | **保留 Base 的删除** | `daily_feishu_sync`/`generate_attendance`/`pair_checkins`/`shift_matcher` 在 Base 已删并有测试守门 |
| 5 | 35 天回溯 + 第二条无界 `DELETE … attendance_date > %s` | **拒绝** | Base 的 bounded DELETE 已从结构上修复月末丢失；无界删除是治理测试明令禁止的 |
| 6 | 删导出私有（`is_private` 1→0）+ 删 `_require_export_permission` | **拒绝** | Base 治理测试硬断言 |
| 7 | 删写接口角色门禁（`_require_hr_read/_write`、`frappe.only_for`） | **拒绝** | 员工范围与主管越权隔离必须由服务端保证 |
| 8 | AI prompt 回显姓名/工号/部门 | **拒绝** | Base 明确「姓名、工号、部门未发送」；Base 自带 `test_prompt_minimizes_identity_but_keeps_review_facts` |
| 9 | `department_board_data.py` 去掉 `rule_code`+`effective_from` 版本化解析 | **拒绝** | 版本化解析保证历史重算稳定；Base 已同时具备版本化与「返回全部绑定」 |
| 10 | `roster_export.py` 把 `EXEMPT_REASONS` 名单硬编码回源码 | **拒绝** | 会命中 Base 的名单治理测试 |
| 11 | `shift_management.js` 视觉层 | **未移植（保留 Base）** | 其视觉与已拒绝的后端机制（`rule_code`→docname 绑定、逐字段保存生成多版本、删规则看板转义）在同一批函数内纠缠；拆分风险高于视觉收益。**代价：该页视觉与其它 5 页不一致（需单独一轮）** |
| 12 | 「已通过请假不计缺勤」「周末豁免」 | **未移植** | Base 以 `tabAttendance` 为唯一权威口径（已含请假派生结果），可分离但属冗余；取更严口径 |
