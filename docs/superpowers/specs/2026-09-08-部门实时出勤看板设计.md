# 部门实时出勤看板 设计文档

- 日期：2026-09-08
- 项目：HBOS（新乡海滨智能运营管理平台）· `hb_attendance_app`
- 归属：M1-FIX-B5 后续追加（按 Owner 2026-09-08 确认，不新开大轮）
- 状态：DESIGNED（待 Owner 复核本 spec 后进入实施计划）

## 1. 目标与范围

在海滨考勤工作台中新增「部门看板」：以**部门人员**为单位，展示**当日实时出勤快照**，并支持**多日回顾**（选任意历史日期看当日快照）。

- 实时 = 读取数据库内最新打卡 + 每 10 分钟已有定时任务从得力云同步打卡，页面提供手动「立即同步」触发即时拉取（节流）。
- 判定口径（Owner 已确认）：**排班优先 + 规则推断**——优先 HBOS Employee Schedule；无排班的用固定班次绑定 / 名单归类推断；推断不出的人只显示「在册待确认」，不标未打卡异常。
- 迟到/未到点提示采用**保守判定**：只在班次起算点确定且无跨天歧义时标注；疑似场景仅提示不定性。
- 实施路线：**独立 Desk 页面 MVP + 自动轮询 + 手动同步 + 保守当日迟到判定**（即「实时增强版」方案，Owner 2026-09-08 确认）。

边界（本功能不做）：

- 不重做已封板的异常口径（迟到/早退/缺勤定性以月度考勤汇总 / 考勤结果报表为准）。看板是快照提示，不与报表互相矛盾。
- 不做跨天自动判定：跨天班次归属已由排班表日期锚定，看板跟随排班表日期。
- 不引入 Vue/React 独立前端；沿用现有 Desk 自定义页面模式（与 hbos-attendance-dashboard 同风格）。
- 不轮询考勤机本身；不新增业务 DocType；不改 Frappe/ERPNext/HRMS 核心源码。
- 回顾日期不晚于今天；不展示未来日期。

### 2.2 页面控件

- 顶部工具条：
  - 部门下拉：默认「全部部门」，选项 = 所有 Active 员工所属部门（去重、中文排序）。
  - 日期输入：默认今天；早于今天的为「回顾」模式。
  - 「查询」按钮。

- 上半：统计卡（按所选部门/全厂聚合）：在册 / 应出勤 / 已到岗 / 未打卡(已到班次点) / 请假 / 休息 / 豁免 / 待确认 / 出勤率。
- 下半：明细表（见 §5），按部门分组、逐人一行，状态用色块徽标。
- 只读展示，无业务写库。

## 3. 数据源与口径

### 3.1 数据源

| 数据 | 来源 | 用途 |
| --- | --- | --- |
| 员工在册 | `tabEmployee`（`status='Active'`） | 部门成员集合 |
| 当日排班 | `HBOS Employee Schedule`（`schedule_date=目标日期`） | 期望班次/休息/请假（最高优先级） |
| 已通过请假 | `HBOS Leave Record`（`approval_status='已通过'` 覆盖目标日期） | 请假补充 |
| 打卡事实 | `Employee Checkin`（`DATE(time)=目标日期`，GPS/手机打卡已标记 `hbos_check_type`） | 已到岗/首卡/末卡/卡数 |
| 闭环考勤（回顾用） | `tabAttendance`（`attendance_date=目标日期`，`docstatus<2`） | 历史日权威状态 |
| 名单 | `rule_lists.py`（EXEMPT/ADMIN/SAFETY/FOOD…）+ `pairing.py`（SPECIAL/FOUR_SHIFT…） | 豁免/名单归类 |
| 固定班次绑定 | `HBOS Employee Shift`（is_primary 优先）与 `Employee.hbos_fixed_shift` | 无排班时的规则推断 |

### 3.2 豁免与不计

- `EXEMPT_NUMS` 人员：显示为「豁免」，不计入应出勤、不判到岗异常。
- 手机/GPS 打卡视为已出勤（沿用系统既有口径）。

## 4. 期望状态解析（排班优先 + 规则推断）

对每位在册员工按以下优先级解析「当天期望」，产出 `expected` 对象：

1. **排班表**（HBOS Employee Schedule 该日记录）：
   - `leave_type` 非空 → `请假`
   - `shift_type='休息'` → `休息`
   - 否则 → `上班`，班次类型 = `shift_type`，起算点确定（映射 BUILTIN_SHIFTS 的 start/late，含 `早班/中班/夜班/晚班/行政班/8:30班/无菌早(12h)/无菌晚(12h)`）。
2. **固定班次绑定**（无排班时）：取该员工主绑定规则（HBOS Employee Shift `is_primary`，否则 `hbos_fixed_shift`）→ 规则 `shift_type`，start/late 用规则字段、缺省回落 BUILTIN_SHIFTS。确定 → `上班`，起算点确定。
3. **名单归类**（无排班且无绑定）：用 `roster_classify.classify` 结果：
   - 行政班名单（ADMIN_NUMS）且工作日 → `上班`（行政班 08:30，起算点确定）；周末 → `休息(行政班周末)`。
   - 安全倒班（SAFETY_NUMS）无排班 → `上班`（班次体系标签「安全倒班」，**起算点不定**——不知当日早/晚）。
   - 食堂（FOOD_NUMS）→ `上班`（只报打卡事实，不判到点/迟到）。
   - 四班次倒班 / 无菌倒班 / 通用倒班无排班 → `上班`（只给班次体系标签，起算点不定）。
4. **豁免** → `豁免`。
5. 以上都不命中 → `在册待确认`。

实现要求：以上解析做成**纯函数** `department_board.resolve_expected(profile, schedule)`，`profile` 由数据层从名单/绑定预计算（含豁免、admin、food、safety、绑定班次及其 start/late、班次体系标签），保证离线可测、名单口径单一（import 现有常量，不复制）。

## 5. 状态计算

### 5.1 实时模式（目标日期 = 今天，注入当前时刻 now）

仅对 `expected.kind == 上班` 且 **起算点确定** 的员工做到点判定：

- 已到岗：存在首张「入窗口」卡 → 状态 `已到岗 HH:MM`（绿）。入窗口起点 = `start_time - 4h`；若该起点跨到前一天零点之前则钳制为当天 00:00（`start_time` 为 00:00 的夜班不向前借卡，避免把前一天的卡当入窗卡）。若首卡晚于 `late_after` 且非跨天歧义 → 附 `迟到` 徽标。
- 未到班次点：now < start_time → `未开始 HH:MM 上班`（中性）。
- 未打卡(未到迟到点)：start_time ≤ now < late_after 且无入窗口卡 → 中性提示。
- 未打卡(已到班次点)：now ≥ late_after 且无入窗口卡 → `未打卡`（琥珀提示，**不写**缺勤/迟到定性）。
- 超过期望下班时刻仍无卡：仅追加备注「班次时段内无打卡，请以月度汇总为准」，不判缺勤。

起算点不定（安全/四班次/无菌/通用等无排班人员）与食堂：只报事实——`已打卡 HH:MM` / `未打卡`，不判到点迟到。

### 5.2 回顾模式（目标日期 < 今天）

- 优先用 `tabAttendance` 该日记录做权威状态：Present→`出勤`（附 late/early 徽标）、Absent→`缺勤`、On Leave→`请假`。
- 无考勤记录的员工：回落排班/请假/豁免/休息；期望上班但当日无任何卡 → 显示「当日无配对考勤记录」，**不判定缺勤**（尊重连续无卡 3 天起判等既有口径，不与其矛盾）。
- 展示当天首卡/末卡/卡数事实。

### 5.3 状态徽标集

`已到岗 / 迟到 / 未打卡 / 未开始 / 请假 / 休息 / 豁免 / 在册待确认 / 缺勤 / 当日无配对考勤记录`。

### 5.4 统计卡口径

- 在册 = 该部门 Active 员工数。
- 应出勤 = 期望为「上班」的人数（不含豁免/请假/休息/在册待确认）。
- 已到岗 = 应出勤中有入窗口卡人数（实时）或考勤出勤人数（回顾）。
- 出勤率 = 已到岗 ÷ 应出勤（应出勤为 0 时不显示）。

## 6. 后端模块与数据接口

- 纯函数模块：`hbos_attendance/department_board.py`（无 frappe 依赖，可离线测试）：
  - `resolve_expected(profile, schedule)` → expected 对象。
  - `live_state(expected, in_window_times, now)` → 实时状态（保守判定，时钟注入）。
  - `day_review(expected, attendance, card_times)` → 回顾状态。
- 数据层：`hbos_attendance/page/hbos_department_board/department_board_data.py`
  - `@frappe.whitelist() get_data(department=None, date_str=None, live=1)`：按 §3 取数、调用纯函数、聚合统计，返回：
    - `{departments:[], meta:{date, mode, now, scope}, stats:{...}, rows:[{dept, num, name, expected_label, state, state_kind, first_card, last_card, card_count, tags[], note}]}`
  - `@frappe.whitelist() live_sync()`：节流 ≥120s（frappe.cache 标记）后调用现有 `api.sync_delicloud_checkin`，失败仅记日志不阻断页面。
  - `date_str > 今天` 时 `frappe.throw`。
- 复用现有常量与函数：`rule_lists` / `roster_classify.classify` / `shift_rules.BUILTIN_SHIFTS` / `pairing` GPS 口径 / 现有同步端点。不复制名单。
- 权限：沿用工作台既有可见性（HR Manager / HR User / System Manager 通过 Workspace 进入）；与现有页一致不做额外 Page 角色门禁；数据接口只读 + 已节流同步。
