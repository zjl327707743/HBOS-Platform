## 一、目标

在「月度考勤汇总」报表中新增「AI复核」：把当月异常（迟到/早退/缺勤）逐条交给真实大模型复核，返回逐日「结论 + 理由」，作为替代人工逐条审的辅助列；结果随 CSV/Excel 导出；再次筛选 AI 结果消失，每次点击重新复核。

## 二、用户决策记录

| 决策点 | 结论 |
|---|---|
| AI 形态 | 真实大模型 API（OpenAI 兼容 + env：HBOS_AI_BASE_URL/KEY/MODEL/TIMEOUT） |
| 调用时机 | 点「AI复核」按钮按需调 |
| 复核目标 | 逐条判定（属实/存疑/非异常，可纠正系统误判）+ 理由 |
| 列形态 | 月度考勤汇总每行一个「AI复核」汇总列，格子内逐日多行：日期｜类型｜结论｜理由 |
| 复核范围 | 仅当前筛选结果中当月有异常的员工，每人一次调用 |
| 数据源 | 打卡流水 + 考勤结果 |
| 规则源 | 部门-班次-人员（绑定/名单）+ 系统规则（该员工相关子集） |
| 成本保护 | 点按钮先算本次人次 → 弹确认框 → 才跑；无异常员工不调用 |
| 生命周期 | 再次筛选 AI 列消失；每次点击重新复核；随导出 |
| 实现方案 | 方案 A：报表服务端 enable_ai 临时列 |

## 三、方案 A 架构

```
点「AI复核」
  → ai_review_preview() 服务端算本次异常员工数 N（剔豁免名单）
  → 前端确认框：「将调用 AI 复核 N 名异常员工（约 M 条异常），继续？」
  → 确认 → 设 enable_ai=1 → report.refresh()
       → execute() 对 N 人逐人调 LLM 生成 ai_review 逐日文本 → 动态加「AI复核」列
```

- `enable_ai`：隐藏 Check 过滤，默认 0。默认态无 AI 列、不调 LLM。
- 再筛选/换条件 → 报表重置 enable_ai=0 → AI 列消失；下次点=重新复核。
- AI 结果只存在于本次报表响应（临时），不写库、不落盘、不改考勤/打卡数据。
- enable_ai=1 时「导出 Excel」/ CSV 原生导出自动带 AI 列（列在服务端数据）。

## 四、AI 模块 `ai_review.py`

### 数据打包（纯函数，可离线测试）

`build_fact_pack(employee, month, year, attendance_rows, checkin_rows, rule_summary) -> dict`
- 每人一份「事实包」：该员工当月全部异常日期 + 这些日期对应的考勤结果、打卡流水、班次规则摘要（应到/迟到起算）、豁免状态。
- 只含该员工异常相关行，不把全公司数据喂给模型。

### LLM 调用（frappe 侧）

`call_llm(api_key, base_url, model, messages, timeout) -> str`
- OpenAI 兼容 `POST {base_url}/chat/completions`；`Authorization: Bearer {api_key}`。
- `temperature:0`、`max_tokens:~1200`；超时/网络/非 200 抛异常。
- env 缺省（未配 HBOS_AI_*）→ `frappe.throw("未配置 AI（HBOS_AI_BASE_URL/API_KEY/MODEL）")`。

### prompt 骨架

```
你是海滨考勤审核助手。对每条系统判异常的记录给复核结论。逐条输出：
日期|类型|结论|理由
结论限：属实 / 存疑 / 非异常（非异常=系统误判，须给出依据）

【员工】{姓名} 工号{工号} 部门{部门}
【班次规则】{班次体系 + 上下班 + 迟到起算；豁免：是/否}
【考勤结果】{异常日期的系统判定明细}
【打卡流水】{对应日期卡明细}
---
待复核：
{逐行异常列表}
```

### 返回解析（纯函数，可离线测试）

`parse_review_output(text, anomalies) -> {date_key: "结论：理由"}`
- 按行切，跳过无 `|` 行；结论映射（属实/存疑/非异常）；多余行截断；解析失败回落「AI 复核失败：原因」。

## 五、报表改造（月度考勤汇总）

- 隐藏过滤 `enable_ai`（Check，default 0）。
- `_columns()`：enable_ai 时追加 `{"label":"AI复核","fieldname":"ai_review","fieldtype":"Small Text","width":450}`。
- `execute()`：enable_ai 且该员工有异常 → 构造 fact pack → call_llm → parse → 写入 `ai_review`；逐人失败隔离（单人不影响其他）。
- JS：`onload` 加「AI复核」按钮 → 确认流（先调 preview 得人次）→ 设 enable_ai=1 并 refresh；「导出 Excel」「异常考勤导出」参数透传 enable_ai（export_xlsx 接收并传给 execute）。
- 新白名单 `ai_review_preview()`：按当前筛选返回 `{employee_count, anomaly_count}`。

## 六、容错与成本保护

- 逐人失败隔离：单次 LLM 失败 → 该人回落 `AI复核失败：{原因}`；全败提示检查配置/稍后重试。
- 超时 `HBOS_AI_TIMEOUT`（默认 60s）；返回超长按行截断。
- 确认框给 N 人次；N>50 提示分批（仍逐次开 enable_ai）。
- 本期同步逐人调用，不做后台队列（YAGNI；验证后如需批量/留存另开轮）。
