# 调休与换班记录界面 设计文档

- 日期：2026-09-11
- 项目：HBOS（新乡海滨智能运营管理平台）· `hb_attendance_app`
- 归属：M1-FIX-B5 后续追加
- 状态：DESIGNED（待 Owner 复核本 spec 后进入实施计划）

## 1. 目标与范围

新增两个**只读记录界面**，分别展示飞书「调休」与「换班」审批数据，供 HR 查看与筛选。

**本轮范围**

- 两个新 DocType + 两个飞书同步脚本 + 工作台/侧栏入口。
- 数据来源：飞书多维表格（只读取「已通过」的记录）。

**范围外（本轮不做，明确记录）**

- **不影响考勤判定**：调休/换班都不参与缺勤、迟到、早退的判定。
- **不重算任何历史**：不触发 `regenerate_attendance`。
- **不与请假表合并**：现有 `HBOS Leave Record` 的「请假类型=调休」记录与新「调休记录」**各记各的**（Owner 2026-09-11 确认），两边数据互不影响。
- **不写回飞书**（只读同步）。
- 不做"调休当天不算缺勤""换班按实际班次判迟到"的判定接入——留待下一轮。

## 2. 调休与换班的语义（Owner 2026-09-11 确认）

| | 调休 | 换班 |
| --- | --- | --- |
| 含义 | 加班换来的休息（影响考勤） | 两人互换班次（影响判定） |
| 形态 | 单人 + 一段日期区间 | 申请人 + 替班人 + 两个日期 |
| 时间关系 | 起止日期 | **甲先替乙、乙以后再还**（换班日期与还班日期错开） |
| 本轮效果 | 仅登记展示 | 仅登记展示 |

## 4. DocType 设计

### 4.1 `HBOS 调休记录`（`hbos_rest_leave_record`）

`autoname = field:feishu_approval_id`，`module = HBOS Attendance`，权限与加班记录一致
（System Manager / HR Manager / HR User 可读写）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `employee` | Link(Employee) | 调休人员 |
| `employee_name` / `employee_number` / `department` | Data/Link | fetch_from employee |
| `start_date` / `end_date` | Date | 起止日期 |
| `rest_days` | Float | 调休天数 |
| `approval_status` | Select(已通过/已驳回/已撤销/审批中) | 申请状态 |
| `feishu_approval_id` | Data | 唯一键 `feishu-bitable-restleave-<SourceID>` |
| `feishu_sync_time` | Datetime | 同步时间 |
| `remarks` | Small Text | 说明 |

### 4.2 `HBOS 换班记录`（`hbos_shift_swap_record`）

同样的约定，字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `applicant` | Link(Employee) | 申请人 |
| `applicant_name` / `applicant_number` / `applicant_department` | Data/Link | fetch_from applicant |
| `substitute` | Link(Employee) | 替班人 |
| `substitute_name` / `substitute_number` / `substitute_department` | Data/Link | fetch_from substitute |
| `swap_date` | Date | 换班日期（甲替乙之日） |
| `repay_date` | Date | 还班日期（乙还甲之日，可空） |
| `approval_status` | Select | 申请状态 |
| `feishu_approval_id` | Data | 唯一键 `feishu-bitable-swap-<SourceID>` |
| `feishu_sync_time` | Datetime | 同步时间 |
| `remarks` | Small Text | 说明 |

两份 DocType 均 `in_list_view` 展示：人员、日期、状态、说明（换班额外展示替班人与还班日期），
便于直接在 Desk 列表页筛选。

## 5. 同步脚本

新增两个模块，结构对齐现有 `api.sync_overtime_from_bitable`（复用 `_get_token` / `_fetch_all_records_custom`）：

- `hbos_attendance/sync_rest_leave.py` → `sync_rest_leave_from_bitable()`
- `hbos_attendance/sync_shift_swap.py` → `sync_shift_swap_from_bitable()`

共同逻辑：

1. 取 token → 分页拉全量记录；
2. 仅处理 `申请状态 == "已通过"`，其余跳过；
3. 工号优先匹配 Employee，匹配不到回退姓名；都匹配不到则跳过并计数；
4. 以 `feishu_approval_id` 存在则更新、不存在则新建；
5. 返回 `{created, updated, skipped}`，异常记 `frappe.log_error` 并 `frappe.throw`（与加班同步一致）。

## 6. 风险与处理

| 风险 | 处理 |
| --- | --- |
| **换班表是 wiki 链接** | 其 `app_token` 是 wiki 节点而非 bitable app_token。实现时先用飞书 `wiki/v2/spaces/get_node` 解析真实 `obj_token`；解析失败则记录明确错误，不静默跳过 |
| 列名日后被改名 | 同步时按列名取值，缺失记 `log_error`（不静默产生空记录） |
| 姓名重名 | 工号优先；仅当工号缺失才用姓名，且与现有请假同步同策略 |
| 时间戳时区 | 沿用项目既有做法（目前请假/加班同步用容器本地时区 `fromtimestamp`），本设计**不改动既有行为**；同步时间仅用于展示日期 |

## 8. 测试

离线（纳入 CI，frappe-free）：

- 换班 wiki 节点解析：给定 wiki 节点响应，正确取出 `obj_token`；异常响应报错不静默。
- 字段映射纯函数：飞书记录 dict → 待写入字段 dict（含毫秒时间戳→日期、工号优先匹配、缺失列跳过）。
- 契约：两个 DocType JSON 存在且字段齐备；`setup.py` 含两个新侧栏项。

运行态（需 Owner 授权）：

- `bench execute hbos_attendance.sync_rest_leave.sync_rest_leave_from_bitable`（只读飞书 → 写本地 DocType），
  核对记录条数与飞书中「已通过」条数一致。

## 9. 验收标准

1. 两个 DocType 可在 Desk 中打开、列表可见、可筛选。
2. 侧栏与工作台各出现「飞书调休记录」「飞书换班记录」两个入口。
3. 同步只取「已通过」，重复执行不产生重复记录（唯一键生效）。
4. **考勤判定与既有报表行为完全不变**（不重算、不改判定）。
5. 全量离线测试通过。
