## 一、目标

在「海滨考勤工作台」的**班次管理**页（`hbos-shift-management`）中新增一个**规则看板**，把每一条班次判定规则可视化展示到界面上，覆盖全部三类规则：

1. **规则表记录**：`HBOS Shift Rule` DocType 中的每一条记录（含绑定人数）。
2. **内置默认班次表**：`shift_rules.BUILTIN_SHIFTS` 中的 8 种班次。
3. **名单与配对参数**：代码常量中的名单（行政班/食堂/安全/豁免/无菌/四班次/打卡机 SN）与配对算法参数。

规则看板是**只读展示面**，所有修改仍走「班次设置」Tab 既有交互，不引入第二套编辑逻辑。

## 三、架构

```
班次管理页加载
  → renderShiftSetupTab()   现有功能原样（Tab 1）
  → renderRulesBoardTab()   规则看板（Tab 2）
      → frappe.call(get_rules_board)      @frappe.whitelist()
          → 读 tabHBOS Shift Rule + 绑定人数 count
          → 读 BUILTIN_SHIFTS / api 名单常量 / pairing 参数
          → 返回 5 块 JSON
      → 渲染 5 个分区（优先级链 / 规则表 / 内置班次 / 名单卡片 / 配对参数）
```

- 名单与配对参数**直接 import 现有常量**，不复制数据，杜绝漂移。
- `get_rules_board` 只读，不触发 `regenerate_attendance`，不动数据库，无副作用。

## 四、后端数据契约 `get_rules_board()`

文件：`apps/hb_attendance_app/hb_attendance_app/hbos_attendance/page/hbos_shift_management/shift_management_data.py`

`@frappe.whitelist() def get_rules_board()` 一次返回五块数据：

| 键 | 内容 | 来源 |
|---|---|---|
| `rules` | 全部规则记录（含实时计算的绑定人数 `assigned_count`） | `tabHBOS Shift Rule` + `tabHBOS Employee Shift` 计数 |
| `builtin_shifts` | 8 种内置默认班次（班次/上班/下班/迟到起算/最小工时） | `shift_rules.BUILTIN_SHIFTS` |
| `lists` | 名单组数组，每项 `{key, title, count, desc, nums[]}` | `api.py` 的 ADMIN/FOOD/SAFETY/EXEMPT、`pairing.py` 的 SPECIAL/FOUR、设备 SN 两组 |
| `pairing_params` | 配对算法参数（去重 10 分钟、最短 2h、最长 16h/18h、跨天夜班锁定、零点夜班、GPS 豁免、分机起始日等） | 常量 + 描述 |
| `priority_chain` | 判定优先级链（排班表 > 固定班次绑定 > 部门/全局规则 > 名单短路 > 硬编码兜底） | 静态描述数组 |

要点：

- **绑定人数实时算**：`assigned_count` 字段在 DocType 中已存在但从未被维护（grep 无引用），看板端实时 `count()` 计算，不依赖存量数据。
- **名单人数是工号集合大小**，同时返回完整工号数组供展开。
- 时间字段统一走现有 `_fmt_time()` 规范化为 HH:MM，与班次管理页口径一致。
- 异常兜底：任一来源读取失败不整体抛错，该分组返回空并带 `error` 提示。

## 五、前端 Tab 结构与规则看板渲染

文件：`apps/hb_attendance_app/hb_attendance_app/hbos_attendance/page/hbos_shift_management/hbos_shift_management.js`

### 5.1 Tab 结构

页面容器改为 Tab 栏：

```
+--------------------------------------------------+
|  班次管理    [班次设置] [规则看板]      ← Tab 栏 |
+--------------------------------------------------+
|  Tab「班次设置」= 现有全部功能（原样保留）       |
|  Tab「规则看板」= 规则看板分区                   |
+--------------------------------------------------+
```

- 进入页面默认落在「班次设置」，现有功能零改动（`renderPage` 拆出 `renderShiftSetupTab()` / `renderRulesBoardTab()`，原 `loadOverview` 链原样进前者）。
- Tab 用 Frappe 风格（类 `nav nav-pills`），切换时只重建对应容器。
- 页面标题不变，仍为「班次管理」。

### 5.2 规则看板渲染

`renderRulesBoardTab()` 调 `get_rules_board()` 后渲染 5 个分区：

1. **判定优先级链**：横向步骤条，展示「排班表 → 固定班次绑定 → 部门/全局规则 → 名单短路 → 硬编码兜底」，一眼看懂判定顺序。
2. **班次规则表**：全量规则记录表格（规则名称/部门/班次类型/上班/下班/迟到起算/最小工时/生效日期/状态/绑定人数）。可折叠展开「停用/草稿」历史规则，默认只显示生效 + 待生效。
3. **内置默认班次**：8 种班次的只读表（班次/上班/下班/迟到起算/最小工时），标注「未配置专属规则时按此判定」。
4. **名单规则**：卡片网格，每类一张卡（名称 + 人数 + 规则说明 + 生效范围徽章）；点击卡片展开内联工号清单（等宽字体小号显示）。
5. **配对算法参数**：参数名 → 值 → 说明的三列表格（如去重 10 分钟、最短 2h、最长 16h/环保质控 18h、跨天夜班锁定 22-24→次日 4-10、零点夜班、GPS 豁免、分机起始 2026-08-15）。

### 5.3 权限

列表靠 `@frappe.whitelist()`，无需额外权限配置；页面本身已有 System Manager / HR Manager / HR User 角色。

## 六、错误处理

- `get_rules_board()` 各数据源独立 try/except：任一失败只空该分组并返回 `error` 字段提示，不整体抛错。
- 前端空数据 → 分区显示「暂无数据」占位，不影响其他分区渲染。
- 名单工号集合正常规模（几十~两百），单次 JSON 返回无性能压力；未来某名单超千条再考虑分页（YAGNI，现在不做）。
