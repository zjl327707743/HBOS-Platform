## 3. 现有代码对象的精确字段

以下是源码已有的 Python 依赖对象，参见 [management_http.py](../../apps/hbos_portal/hbos_portal/organization/management_http.py)、[management_query_http.py](../../apps/hbos_portal/hbos_portal/organization/management_query_http.py)、[management_storage.py](../../apps/hbos_portal/hbos_portal/organization/management_storage.py)。它们目前不从生产私有配置自动装配。

### 3.1 `ManagedHTTPBinding`

| 字段 | 约束与审查内容 |
| --- | --- |
| `site_id` | 非空，必须等于本次原生请求的实际 Site；本机候选为已核对的 `frontend` |
| `database_sha256` | 小写 64 位 SHA256，必须对应实际数据库；由来源 / 政策仓储再次核验 |
| `origin` | 精确 scheme + host + port，无路径、用户名、密码、query 或 fragment；本机候选 `http://127.0.0.1:5178` |
| `approval_verifier` | 精确 `PinnedPolicyApprovalVerifier` 类型，由可信服务端装配；不能接收浏览器声明或自填批准字符串 |
| `clock` | 可信当前 UTC 时钟；默认 `_utc_now`。正式装配不得注入 Preview 合成时钟、客户端时间或可冻结时间 |
| `enabled` | 默认 `False`，只有明确 `True` 才可进入校验；这不是已经存在的全局 Site 开关 |

`ManagedQueryHTTPApplication(application, binding=...)` 仅安装四个 GET 的请求能力。`ManagedHTTPApplication(application, binding=...)` 是四个写 POST 的独立包装。共享绑定类不意味着一次启用读就应启用写：正式只读阶段仅装配查询包装，写包装保持未安装或使用独立的关闭绑定。原生 API 在没有对应请求私有能力时继续默认拒绝。

`ManagementPolicyStore` 的现有内部依赖还有 `operator_users`、`clock`、`approval_verifier`、`enabled` 以及已绑定的仓储。`operator_users` 是政策维护运维名单，区别于获准读取的 `subject_user` 和批准人；当前没有配置加载器或导入命令，Administrator 不自动成为运维人。政策运维写入须单独说明理由、expected_revision 和提交 / 回滚所有者，不能通过浏览器或普通 REST 修改。

## 5. 四个 GET 与浏览器安全请求

路径前缀固定为 `/api/method/hbos_portal.api.organization_relations.`：

| 方法 | 可接受参数 | UI 结果要求 |
| --- | --- | --- |
| `get_management_context` | 无 | 仅完整可用规则的操作 / 范围；不展示批准、政策内码或 User 身份 |
| `list_positions` | `page`、`page_size`、`company_id`、`department_id`、`q` | 仅获准岗位；授权过滤先于搜索、total 和分页 |
| `get_person_assignments` | 必填 `employee_id`；`page`、`page_size` | 仅获准任职；无权人员与不存在人员同答，禁止原生数据回填 |
| `lookup_people` | `page`、`page_size`、`company_id`、`department_id`、`q` | 最小 Employee ID / 姓名 / 组织 / 岗位类别等投影，不含电话、User ID、角色或批准 |

所有管理 GET 都必须使用真实登录 cookie SID 和服务端保存的 `X-Frappe-CSRF-Token`；Authorization 头不能替代 cookie。请求实际 `scheme://host` 必须等于绑定 origin；同源 GET 可能不带 Origin，存在时须精确匹配，`Sec-Fetch-Site=cross-site` 拒绝。不能为接入 UI 放宽后端 GET 的 CSRF 或来源校验。

现有 Portal 客户端此前对所有 GET 跳过 CSRF。本轮四条精确管理 GET 已复用同一个 token 缓存 / 单飞 / 会话 generation 机制；普通 GET 不增加 CSRF，bootstrap 不递归获取 token。受控 GET 成功返回后也重验代次；受控 GET 与共享 token bootstrap 的旧401 / CSRF错误先扣留，不清除新会话 token 或退出新会话。新登录显式提供的新 token 不被旧缓存覆盖，退出 / 换会话清理旧 token，旧会话尚未结束的 token 请求不能进入新会话。

GET 公开 `FORBIDDEN` 可能表示会话安全或政策拒绝，不能把所有 403 当作 CSRF 过期自动重试；不自动重放写请求。`NOT_SUPPORTED` 显示尚未启用，服务 / 冲突错误不改为“暂无记录”，读取失败不回退为原生目录结果，也不新增默认授权。

页码范围 1—10000，页大小 1—50、默认 10，`q` 最多 80 字符；不接受 phone、通用 fields / order / filters、重复 query key、客户端身份 / 批准、GET body 或 include_children。合法空结果只说明当前获准结果为空。

Vite 现有 `/api` 代理 `changeOrigin:false` 可保留 5178 Host，但还需在真实运行链核对原生选定 Site 与 scheme。端口 8080 的后端 URL、Preview origin、另一个 host 别名或 HTTPS 终止后的内部 scheme 不等于已经验收的 5178 origin；正式代理装配须提供明确证据，不能由客户端声明替代。

## 7. 回退与停止条件

发现目标绑定、schema、当前政策 / pins、真实来源、会话校验、数据释放、Hook 加载或容量门禁异常，先关闭 / 移除查询绑定并确认四个管理 GET 恢复默认拒绝。未完成核验不能以空结果、原生角色或跳过 CSRF 恢复可用性。

回退 UI / 新查询装配与私有配置时，保留原生存储保护 Hook / 模型、schema、根锁、政策修订和事实历史。不能删除表、重写历史、恢复旧 active 政策或把保护代码一并撤下作为常规功能回退；整库恢复会影响并行写入，必须使用另行批准且验证过的恢复方案。

回退后核对原生目录真实只读行为、管理 GET / POST 默认拒绝、Site / 数据库身份、原生计数 / 受保护指纹、没有业务 Grant 变更、运行代码 / 私有配置 / 缓存一致性。输出无人员明细结果和尚未执行事项，不把 Query wrapper 已移除解释为全站无所有原生写入。

## 8. 写入与业务授权的独立后续门禁

正式查询通过只表明管理只读边界在记录场景内成立。岗位 / 任职事实写入仍需单独放行四个 POST、独立 create / update 政策及期限、原生 POST cookie / CSRF / Origin、本人增权拒绝、旧 / 新完整范围、同键重放、提交前复核、提交未知与恢复、完整生命周期 / 审计以及 Owner 验收。

事实写入成功也不代表业务 Grant 已生效。固定角色版本 / 岗位关联、具名人员与组织来源、批准派生、兼任不串权、各 App 独立业务执行、调岗 / 停用 / 到期撤权、Q1 / Q2、Employee Date、固定 P1 来源与原库恢复门禁仍按原主文档保留。
