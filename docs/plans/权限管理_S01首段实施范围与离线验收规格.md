## 4. 首段协议的固定边界

### 4.1 定义注册

| 输入或输出 | 首段规则 |
| --- | --- |
| contract_version | 初版支持整数 1；未知版本拒绝相应 App。版本、revision、generation 等整数字段须拒绝布尔值冒充整数 |
| app_id / action_id | app_id 初版格式为 `[a-z][a-z0-9_]*`；action_id 为本 app_id 加一个或多个点分段，每段为 `[a-z][a-z0-9_]*`，全部完整匹配。不能通过显示名、菜单名或通配符推导动作 |
| definition_revision | 非空不透明修订标识，不靠字符串大小比较先后，不与 Portal 传输版本混用 |
| 资源、动作、范围及入口绑定 | 资源和范围均由该 App 声明，动作引用明确存在；入口绑定在首段使用不透明 binding_key，不保存可执行路径。遗漏、未知或互不兼容的引用拒绝相关定义；实际入口覆盖待 S01-C 核实 |
| 来源输入 | 调用方显式提供来源标识及预期 App ID，不能只信 payload 自称的 App；首段不发现真实来源、不 import 任意路径、不调用 resolver 或 Frappe Hook |
| 来源可信性 | 注入输入仅便于离线校验，不构成安装来源证明；真实可信来源由 S01-C 的加载器验证 |
| 冲突隔离 | 同 App ID 冲突时所有冲突候选隔离，不能先到先得；非法 App 不阻断其他无关 App。重复动作 ID 或越命名空间属于该定义错误 |
| 可用性 | 保存定义中的声明状态供校验；输出明确为 validation_only / runtime_verified=false，不提供生效授权结果，不能把声明 enabled 当成已实现、已验收 |
| 只读快照 | 返回不可变副本；修改原输入或后来注册新动作，不能改变已经得到的模板 / 关联快照 |

`build_definition_registry`、`validate_template_version`、`validate_role_bundle`、`validate_position_binding`、`validate_assignment_projection` 已按首段能力名实现，另提供岗位投影和显式任职集合校验。不得加入 `has_permission`、`approve`、`apply_grant`、真实目录端点或自动迁移功能，避免调用方误用离线校验结果放行业务。

### 4.2 角色、范围和任职

| 内容 | 校验范围与限制 |
| --- | --- |
| App 模板 | 明确 app_id、template_id、正整数 version 及 action_ids；拒绝通配符和未知动作。新草案不能引用不可用动作；历史版本可保留已退役动作的引用与不可用标记，但不能因此重新授予 |
| 固定版本 | 已知同键同版本而内容不同的模板 / 关联拒绝冲突；升级形成新版本，不能自动更新旧引用 |
| 页面角色组件 | component_id 唯一，逐项引用已知 App 模板的固定版本；不能只存一份跨 App permissionIds |
| 岗位关联 | 显式引用具体 position_id 和角色版本；component_scopes 覆盖应有组件，不能缺项、串 App 或使用共用 scopeLabel 作为授权结构 |
| 范围选择 | 首段支持已注册的对象引用集合结构：scope_type、schema_version、dimension、reference_type、reference_ids、include_descendants；对象类型与字段由注册定义限定 |
| 范围安全 | 空对象集合、未知结构 / 维度、错误字段类型和任意 SQL / 表达式拒绝；包含下级须由该范围类型允许，不默认启用 |
| 实际对象 | 只验证引用结构和已注入的关系一致性，不声称某个 ID 在真实 Site 存在，不按同名 Department 推导检验组 |
| 人员来源 | person_ref 区分来源类型和主键；subject_user 可空，unlinked / ambiguous / unknown 保留明确状态，不伪造可授权资格 |
| 任职结构 | 引用具体岗位，主岗 / 兼任分开；对显式给出的同一人员任职集合检查有效期间重叠主岗和重复任职，不能据局部集合声称全库无冲突 |
| 有效期 | 接受有时区时间，开始早于结束；拒绝无时区或空区间。valid_until=null 只表示请求未设截止，不代表长期授权已批准 |
| 来源修订 | 保留对象 revision、authorization_generation、固定版本及来源引用，不执行增代、撤权或事件同步 |

首段校验只接受协议定义的字段与结构；未来范围通过新注册结构和适配增加，不做通用表达式引擎。职责分离、本人负责过滤、目标人员资格、实际对象存在性、批准依据和管理边界，必须由后续可信来源与执行层验证。

以下合成关联说明结构边界，不是实际 API 或 Grant：

```json
{
  "binding_id": "BIND-DEMO-A",
  "version": 1,
  "position_id": "POS-DEMO-A-REVIEWER",
  "role_id": "ROLE-DEMO-REVIEWER",
  "role_version": 1,
  "component_scopes": [
    {
      "component_id": "demo-lab-review",
      "scope_type": "demo_lab.lab_group",
      "schema_version": 1,
      "dimension": "lab_group",
      "reference_type": "demo_lab.group",
      "reference_ids": ["GROUP-DEMO-A"],
      "include_descendants": false

```

`demo_lab` 是离线合成命名空间，不是已安装的业务 App。另一兼任使用独立 binding、position 和 GROUP-DEMO-B；A 的角色组件不能与 B 的范围串接。通过这种结构校验仍不代表 A 组复核或 B 组提交在运行态已经允许。
