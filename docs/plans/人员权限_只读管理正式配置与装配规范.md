## 3. JSON schema v1

最小关闭配置示例，仅说明格式，本轮未在原站创建此文件：

```json
{"schema_version":1,"enabled":false,"sites":[]}
```

| 层级 | 字段 | 约束 |
| --- | --- | --- |
| 根 | schema_version | 必填，真正int且等于1；bool不作整数 |
| 根 | enabled | 可省略默认false，真正bool |
| 根 | sites | 可省略默认空list，至多16个；根enabled=true必须至少一个启用目标 |
| 每Site | site_id | 必填，非空稳定文本、无首尾空白 / 控制字符 / 通配符，至多140字 |
| 每Site | database_sha256 | 必填，小写64位SHA256，由实际数据库名精确核实 |
| 每Site | origin | 必填，规范http / https + lowercase host，可选规范显式端口；无用户名、密码、路径、query、fragment，端口出现时1—65535；省略与显式默认端口按精确origin区别 |
| 每Site | enabled | 可省略默认false，真正bool；true必须有非空批准pins |
| 每Site | approval_pins | 可省略空list，至多128项；本Site的精确批准清单 |

所有层级拒绝未知字段；拒绝重复JSON键、NaN / Infinity、非法UTF8与超量 / 超深数据。Site键和origin在整个文件均不可重复；同一Site内政策ID不可重复。不要填写clock、callable、动态模块、write_enabled或权限操作列表，均不是此配置的合法键。新模块或语义不能通过向旧配置塞未知字段自动获得权限。

每个pin必须完整具有：`site_id`、`database_sha256`、`policy_id`、`revision`、`authority_generation`、`subject_user`、`content_digest`、`approval_json`、`source_ref`。Site / DB必须等于所属目标；政策ID规范UUID，两个版本为1—2147483647的真正int，摘要小写64hex，具名主体不能Guest，可信来源引用至多140字。

approval_json是规范canonical JSON字符串，完整六字段 `approval_ref`、`approved_by`、`approved_at_utc`、`approved_revision`、`approved_authority_generation`、`content_digest`。批准人非Guest或被授权主体本人；版本 / 代次 / 摘要与pin严格相等。时间必须等于解析后UTC datetime.isoformat()，对应已有policy_data实际导出（+00:00及规范微秒格式），不能使用其他offset / Z / 不规范微秒替换相同时间。完整当前内容、来源、批准时点与政策资格仍由原服务根锁读取 / PinnedPolicyApprovalVerifier重验；合法字符串不是批准已核实的证明。

不把真实subject、批准内容、私有配置或凭据提交Git / 公开文档。实际管理人 / 批准清单本轮未指定或创建；政策维护运维名单和导入工具也未实现。

## 4. 逐Site路由与返回前重验

只用实际 `wsgi.url_scheme` 和 `HTTP_HOST` 精确匹配一个启用的已批准origin。HTTP_HOST只选择候选绑定，不建立授权；原生实际Site / DB、cookie SID、CSRF、当前主体、政策及来源仍须核实。忽略客户端X-Frappe-Site / X-Forwarded-Host / X-Forwarded-Proto，不使用SERVER_NAME或第一个Site作回退。真实代理必须保留并验证准确外部Host / scheme；别名、内部8080或HTTPS终止不能被客户端声明“修好”。

新装配固定使用真实UTC默认clock，并强制查询包装的结构预检。内层仍缓冲至当前DB政策 / 来源、原生GET回滚、返回前复核和会话收尾；外层继续缓冲，关闭内层迭代器后重新读取完整私有配置。禁用 / 丢失 / 损坏返回NOT_SUPPORTED；有效字节摘要变化返回CONFLICT_RETRY_REQUIRED并扣留全部旧数据，即使只是空白或另一Site修改。没有自动重试 / 重放。返回前最后核对是一个时点，不是跨文件与DB的原子事务，也不承诺核对之后发生的配置变更可撤回已释放数据。

外层响应上限1MiB，错误、非bytes、缺失响应或迭代 / 关闭故障扣留数据，固定SOURCE_UNAVAILABLE；关闭不会失败后重复执行。内层已有缓冲和来源范围锁的总内存 / 延迟 / 容量仍须验证，外层上限不等于整个查询成本受限。
