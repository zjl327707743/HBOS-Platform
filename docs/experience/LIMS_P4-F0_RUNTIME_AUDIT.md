## 2. 真实页面与关键路径

### 2.1 Portal 入口路径

`/hbos/apps` → LIMS 卡片 → `/hbos/lims`。

观察到：Portal Shell 的 Header、左侧工作台导航、App Center 卡片和权限入口正常；LIMS 进入后停留在 Portal 同源过渡页。该过渡页清楚说明前台尚待设计，并提供返回应用中心动作，符合当前入口切换要求。

### 2.2 LIMS 业务主路径

`/hbos-lims/dashboard` → `/hbos-lims/tasks` → `/hbos-lims/results` → `/hbos-lims/results/:id`。

工作台显示待检、检验中、待复核、待发布 COA 四个 KPI，并提供检验组分布、任务状态分布和最近样品。任务板按待分配、已分配、检验中、已提交、已复核、已批准、OOS 候选分栏。结果清单提供搜索、状态/判定筛选、分页和「录入/查看」。结果详情提供冻结限度、结果输入、判定预览、操作签署链和修订记录。

### 2.3 样品登记路径

`/hbos-lims/samples` → 选择样品类型与优先级 → 填写成品检验表单 → 质量标准与检验项目快照。

表单把样品类型、质量标准、检验项目快照和登记后字段冻结规则放在同一页，业务规则可被用户直接看到。审计仅检查表单和按钮，不点击「保存草稿」或「登记样品」。

### 2.4 空状态与错误状态

- 结果清单使用搜索词 `P4-F0-NO-DATA` 得到 0 条记录，页面显示表头、`0 条记录`、`No data` 图标和「暂无检测记录」。
- 未登录打开当前 Native LIMS 时，页面仍渲染完整工作台，但顶部重复出现「您无权访问此资源」并暴露 `frappe.client.get_list`、`frappe.desk.query_report.run` 等实现细节。
- 加载过程未能在无网络延迟的本地运行态截取；源码确认结果表使用 Ant Design `loading`，任务板本身没有包住主内容的页面级 loading 容器。

## 4. 发现与优先级

### P1：进入和权限反馈

1. **Portal LIMS 入口与当前业务页面存在明显断层。** `/hbos/lims` 能正确保持在 5179，但真实模式只提供过渡页；用户从 Portal 进入后无法继续完成任务、结果或样品操作。P4-F2 需要以现有 Native 页面为流程基线，定义 Portal Shell 内的首个 LIMS Dashboard 和业务页落点。
2. **未登录状态泄露 Frappe 实现细节且重复弹出。** `frappe.client.get_list`、`frappe.desk.query_report.run` 和 `@frappe.whitelist()` 出现在用户提示中，且同一错误可重复堆叠。应统一为用户可理解的会话/权限提示，保留开发诊断信息在日志，不改变后端权限判断。

### P2：高频操作效率与可访问性

3. **结果清单操作按钮缺少行上下文。** AX 树中每一行都只读为「录入/查看」，屏幕阅读器无法仅凭按钮名称知道对应记录。建议将可访问名称绑定记录号、样品编号和项目。
4. **筛选控件的可访问名称不足。** 搜索框有 placeholder，两个选择框在 AX 中显示为 `rc_select_*`，没有稳定的可见标签或 aria-label。任务板的优先级和搜索也存在同类问题。
5. **任务板缺少页面级加载反馈。** 任务数据异步加载期间，主区域没有明确的 loading 容器；空态和加载态可能短暂混淆。统一组件时应保留上次数据、显示加载层并避免动作按钮误点。
6. **图表的屏幕阅读器语义不足。** Dashboard 的 ECharts 柱图和环图视觉可读，但 AX 树只暴露标题和总数，未暴露每个检验组/状态的数值。应提供可读的文本摘要或可展开数据表。
7. **密集表格和双栏台账尚未有移动证据。** 结果清单、结果台账和签署链在 1280 宽度可用；源码只在部分页面提供 1180/640 断点，TaskBoard/ResultList 没有针对移动的结构化降级。390 宽度需要改为卡片或行摘要，避免横向滚动承载核心动作。
8. **筛选空态需要区分「无数据」和「无匹配」。** 当前均显示 `No data` 与「暂无检测记录」，筛选后应明确显示条件和清除筛选动作。

### P3：统一语言与细节

9. Native LIMS 的深色侧栏、顶部用户区、按钮和状态色与 Portal Shell 视觉语言不同。两者都保留了业务导航，但缺少统一的 Header、侧栏折叠、状态 token、间距和焦点样式映射。
10. 样品登记页的决策条、质量标准卡和检验项目快照是当前最有价值的业务解释组件，应在 LIMS Native 组件库中保留语义，再映射到 HBOS token，而不是把规则藏到 Portal。
11. 结果详情页的冻结限度、自动判定和「检验人 → 复核人 → 批准人」签署链是审计和质量场景的核心优势。后续视觉优化必须保持这些证据的稳定位置和状态可读性。

## 5. 已验证的交互与状态

| 状态/动作 | 真实表现 | P4 设计约束 |
| --- | --- | --- |
| 结果草稿 | 可编辑原始值、结果值、仪器和结果描述；主动作是「提交结果」 | 结果输入保持 V1 效率和字段标签清晰 |

| 认证错误 | 页面保留完整壳体并堆叠原始异常 | 统一为单一错误提示与明确恢复动作 |

## 6. 下一步 P4-F2 输入

P4-F2 原型应先覆盖四个桌面/响应式核心面：

1. LIMS Dashboard：保留四个 KPI、任务分布、最近样品，并补充图表文本摘要和入口优先级。
2. Task Board：保留状态分栏和任务动作，补齐筛选标签、加载/错误/空态和移动卡片结构。
3. Result List / Result Entry：保留密集表格与冻结限度，优化行上下文、状态 token、签署链和移动表单。
4. Result Ledger：保留样品主列表与受控记录详情，定义 768/390 宽度下的单栏切换。

建议的 V-level：Dashboard 使用 V2（适度玻璃、KPI、图表），Task/Result/Sample/Ledger 使用 V1（效率优先、低装饰）。LIMS 域色继续使用 emerald/cyan，并统一到 EA-4/EA-5.4 的语义状态、4px 间距、焦点、键盘、减少动态和非颜色状态表达。
