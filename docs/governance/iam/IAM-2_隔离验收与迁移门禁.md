# IAM-2 隔离验收与迁移门禁

状态：测试规范，以下用例全部 NOT_RUN。本轮没有创建隔离 Site、测试账号或迁移数据。后续隔离环境的建立/资源操作应单独授权，不能把 Owner 固定 P1 当空白测试库。

## 合成测试主体

U-A/U-B 不同部门普通员工；M-A 部门主管；H-A 限定公司 HR；W-A/W-B 不同仓库操作员；Q-A 为 LAB-A Reviewer + LAB-B Analyst；S-A 仅技术运维；K-A/K-B 不同知识空间；X-A 未确认企业成员；D-A 停用用户。全部使用合成数据，不使用真实员工替身或复制原密码/MFA。

## 证据格式

每条用例记录源SHA/制品标识、测试类型、合成角色与配对Grant、资源范围、请求方法、预期/实际状态与业务错误码、数据库副作用断言、审计证据代号、测试输出摘要。除HTTP状态外要检查响应正文和实际数据变化，防止应用用200包装拒绝。读取场景同时验证允许与拒绝，不能通过“全拒绝”冒充隔离成功。

涉及失败写入的用例校验业务事务回滚；拒绝日志的保留不得提交半完成业务事务。针对并发撤权与关键提交做竞争测试，明确重验点、事务隔离/锁策略及已完成在途请求的边界，不承诺无法兑现的绝对即时撤回。

## 迁移原则

先只读映射既有 User/Role/Profile/User Permission/Custom DocPerm/Share 到候选 Grant，不直接替换。形成新增/保持/收窄/异常四类差异并由业务 Owner 确认；旧权限并非全部合法，也不能因无法映射就静默删除。无归属记录、多人共用账号、超宽System Manager、跨部门Share列入专项。

先在批准的隔离环境测试转换可重复、幂等、可回退；生产/固定P1启用另行批准。切换按应用和明确用户队列进行；已切换接口不能以 legacy OR new 方式放宽判定，也不能让未切换旧接口成为旁路。影子判定只比较，不改变现有决策；不得借 shadow 阶段提前开放新用户。

修改原环境前必须有经过验证的保护备份与具体回退步骤；不把全库覆盖还原当默认回退。回退授权规则时不能恢复已离职/撤销的权限；保留变更日志和已提交业务记录。

## 放行条件

IAM-0：真实Site盘点完整性、来源对应与私有数据边界明确。
IAM-1：业务矩阵、数据归属、现有权限映射、委派管理规则批准。
IAM-2：上述关键允许/拒绝用例在目标版本隔离环境通过，完成原生与自定义入口闭环。
IAM-3：管理中心先原型、Owner评审后实现；前端不能成为安全边界。
IAM-4：具名试点验收与启用批准；公司服务器发布另行记录。

任何 NOT_RUN、PARTIAL 或未解释的权限扩大都不得标为“全员可用/权限治理完成”。
