# HBOS 生产看板 AI 工艺分析服务

定时跑：读**工艺描述 + 生产台账**，AI 逐工序分析，结果写回飞书 `AI工艺分析结果` 表。
看板读那张表显示「工艺提升与改进方案」。

规格见 `docs/frontend/P4_生产看板_AI分析服务规格.md`。

## 与取数服务的区别

| | 取数服务 `hbos_production` | **本服务** |
|---|---|---|
| 形态 | 常驻 Web 服务（FastAPI） | **定时脚本**（跑完即退） |
| 触发 | 前端 HTTP 请求 | **每天 16:30**（launchd） |
| 飞书操作 | **只读** | 读（工艺描述+台账）+ **写**（结果表） |
| `.env` | 自己一份 | **自己一份**（Owner 2026-10-02 选 B，与根 `.env` 不共用） |

## 流程

```
① 检查配置 → ② 探活模型 → ③ 逐产品分析 → ④ 校验输出 → ⑤ 幂等写回
```

**② 探活必须在循环之前** —— 历史教训：模型名被上游下线后，跑了整批才失败
（`docs/milestones/M1_FIX_F_调休模块第一阶段落地记录.md:218`，`HTTP 503 model_not_found`）。
探活失败会直接退出，并尝试列出上游可用模型名。

**④ 校验不过就不写飞书** —— 模型可能给出枚举外的评级、编造工序名。
这些在写库前拦下。Owner 定了**不做人工确认**，写进去就直接进看板了。

## 幂等（最重要的设计）

```
一个产品 + 一道工序 = 一行。
写之前先查：指纹相同 → 跳过；不同 → 更新该行；没有 → 新增。
指纹 = hash(产品 + 工艺描述全文 + 台账批号清单)
```

**刻意不含运行时间** —— 否则每次跑指纹都不同，幂等就失效了。

为什么强调：既有 openclaw 项目在这一步出过缺陷 —— `B6生产台账_AI测试` 里
同一格被追加了 **64 次**同一句话（根因是写入前不清空、也不判重）。

## 运行

```bash
cp .env.example .env      # 填 HBOS_AI_API_KEY + HBOS_FEISHU_APP_ID/SECRET
uv venv --python 3.12
uv pip install -r requirements.txt

uv run --env-file .env python -m app.main
```

**先干跑验证**（不写飞书）：

```bash
HBOS_AI_DRY_RUN=1 uv run --env-file .env python -m app.main
```

## 定时（launchd）

```bash
cp launchd/com.haibin.hbos.production-ai.plist ~/Library/LaunchAgents/
# 改 plist 里两个占位路径：__UV_PATH__ / __SERVICE_DIR__
launchctl load ~/Library/LaunchAgents/com.haibin.hbos.production-ai.plist
```

日志在 `/tmp/hbos-production-ai.log`。

## 结构

```
app/config.py    环境变量（模型 + 飞书 + 分析范围）
app/feishu.py    飞书客户端（**既读又写**）
app/sources.py   工艺描述（从字段名动态取工序清单）+ 台账
app/prompt.py    提示词（**纯函数**）
app/llm.py       模型调用（含探活、列模型）
app/parse.py     输出解析与**校验**（**纯函数**）
app/writer.py    幂等写回
app/main.py      编排
tests/           解析校验 + 提示词的单测（不联网）
```

## 输出规格（照《4BMA降本增效实验方案分析报告》）

三条**硬约束**（写进了系统提示词，且有单测锁住）：

1. **没有依据的话不说** —— 台账没有的参数写「台账无相关数据」，**不推测、不用行业经验补全**
2. **每个判断能指到来源** —— 哪一批、哪个字段
3. **数据不足就标 `数据不足`** —— 这不是失败，是正确结论

评级四档：`已达标` / `部分达到` / `数据不足` / `未达标`（与结果表单选选项逐字一致）。

## 当前范围

`HBOS_AI_PRODUCTS=4BMA,F9,F12,F13,无菌美罗培南,无菌亚胺培南` —— **全部 6 个在产产品**（Owner 2026-10-10 放开，
此前只跑 4BMA 验证输出质量）。

**放开时踩到的坑（已修，别再踩）**：各产品的**工艺描述表结构并不一致** ——

| 产品 | 维度标记列 | 取值 |
|---|---|---|
| 4BMA | `项目` | 工艺 / 标准工艺参数 / 设备描述 |
| F9 | `序号` | **裸数字 `1`/`2`/`3`**（语义靠位置，不靠标签） |
| F12 / F13 | `序号` | 工艺描述 / 标准工艺参数 / 设备描述（**顺序与 4BMA 不同**） |
| 无菌美罗培南 / 无菌亚胺培南 | `项目` | 工艺描述 / 工艺参数 / 设备参数；且**一表多规格**（`规格/投料量` 分组） |

原来只认 4BMA 一种形态，其余产品要么读不到工序、要么把 `序号`/`基本信息` 当成工序喂给模型 ——
**不会报错，只是结论错**。解析逻辑收在 `app/sources.py::parse_craft_records()`（纯函数），
`tests/test_sources.py` 用 8 个用例把 5 种表形态各钉一个。

新增产品时：先 `DRY_RUN=1` 跑一遍，确认日志里「工序 N 道」与工艺描述表的实际列数吻合，再实跑。

## 部署到服务器

本机开发**不配开机自启**时的 plist 同上；服务器上换 systemd timer / cron，
并把 `.env` 换成服务器的密钥管理。同取数服务的部署注意事项。
